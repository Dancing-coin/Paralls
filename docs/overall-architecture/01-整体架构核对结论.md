# 整体架构核对结论（基于 deepseek v4 方案）

## 1. 适用范围

- 输入文档：[架构设计-来自deepseek-v4.md](/d:/Projects/Paralls/docs/overall-architecture/架构设计-来自deepseek-v4.md)
- 核对目标：用于指导 `Phase 1` 技术架构总纲（仅 Phase 1）
- 约束：`core = Phase 1 必做`，后期能力不得反压到 Phase 1 core

## 2. 总体判断

- 可采纳：六层总框架（L1/L2/L3/L4/L5/L6）作为“总体架构视图”。
- 必须收束：用于 Phase 1 时，优先级必须转为 `L1/L2/L3/L6 > L4/L5`。
- 结论：该方案可作为上游架构蓝图，但落地到 Phase 1 时必须经过阶段裁剪。

## 3. 关键冲突与处理

### 3.1 感知链路职责冲突(已解决)

- 输入稿写法：`L1 感知系统`将物理事件直接转结构化感知事件。
- 当前冻结口径：`原始世界事件 -> 可感知信息编译层(L2) -> Per-Character 感知过滤器 -> 角色感知事件`。
- 处理：Phase 1 保持当前冻结口径；L1 仅负责“世界事实上抛”。
- 层级补充：
  - `可感知信息编译层`是 `L2` 子系统。
  - `Per-Character 感知过滤器`是“角色智能体引擎”的孙系统（角色智能体 `L1` 感知层内部组件）。

### 3.2 深度沉浸机制落层冲突

- 输入稿写法：深度沉浸机制在 L1 视觉表现系统族。
- 当前冻结口径：深层沉浸主要由角色智能体 `L2/L4` 驱动，司命只做冲动催化。
- 处理：Phase 1 文档继续按 `L2/L4` 主导，不迁移到 L1。
t
### 3.3 Phase 边界冲突（L4/L5 过重）

- 输入稿包含大量完整商业/治理能力（市场、链上、完整运营体系）。
- 当前冻结口径：这些能力多数为 Phase 2/3。
- 处理：Phase 1 仅保留 L4/L5 最小可验证切片与接口预留。

## 4. Phase 1 采纳清单（可进入 core，按子系统族建模）

### 4.1 L1 运行时执行域

- 子系统族：交互执行系统族
  - 客户端交互系统
  - 空间音频系统
- 子系统族：环境执行系统族
  - `ESM` 环境状态管理器
  - 建造与蓝图执行（阶段化）

### 4.2 L2 智能决策域

- 子系统族：角色决策系统族
  - 角色智能体引擎
- 子系统族：叙事编排系统族
  - 司命
  - 模型路由调度器（基础版）
- 子系统族：感知与知识系统族
  - 可感知信息编译层
  - 信息共享执行系统

角色智能体孙系统展开：

- Per-Character 感知过滤器（角色智能体 `L1` 感知层内部组件）
- 输入：可感知信息编译层分发的候选感知事件
- 输出：角色专属感知事件

### 4.3 L3 表现增强域

- 子系统族：表现渲染系统族
  - 点云过渡系统（基础触发与降级）
  - 视觉障眼法系统（基础触发与降级）
  - 高光编排系统（Phase 1 必要触发链）

### 4.4 L6 跨层治理域（Phase 1 硬门槛）

- 子系统族：通信编排系统族
  - 事件总线
  - 房间与状态管理
- 子系统族：数据基础设施系统族
  - 持久化与存档（事实库/缓存/对象存储/快照恢复）
  - 证据链系统（Phase 1 闭环必需子集）

### 4.5 L4/L5 在 Phase 1 的限制性采纳

- 仅保留最小商业验证与平台安全/匹配基础能力
- 以接口预留和薄层实现为主，不进入完整生态交付

## 5. Phase 1 不采纳清单（后移）

- 完整创作者经济市场
- 链上确权与智能合约分账
- 完整大玩家经营体系
- 完整治理代币与生态议会
- 完整世界编辑器与持续世界全量运行

  - 视图A：Phase 1 运行时闭环（L1/L2/L3/L6）
