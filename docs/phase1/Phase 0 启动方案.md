# Phase 0 启动方案

## 状态

- 状态：第一版初稿
- 主来源轮次：`380`
- 补充来源轮次：`102`、`105`、`399`、`400`

## 当前冻结结论

- Phase 0 的目标是验证最小技术闭环，不是提前做完 MVP
- 里程碑 Demo 至少包含：单场景、2 个 AI 角色、基础对话、空间音频、1 个可交互物品、Godot ↔ Python 打通

## 1. 文档目标

本文档用于定义《开本》Phase 0 的启动边界、原型范围、任务拆解和验收标准。

Phase 0 不是产品文档，也不是完整路线图。它只回答一个问题：

“在最小投入下，我们能否证明智能体驱动的 3D 动态剧本杀核心链路可行？”

## 2. 时间线覆盖说明

与 Phase 0 相关的前后版本中，需按如下顺序理解：

- `102`：较早版本，强调把视频/图片工作流接入 L3，并给出分阶段建议
- `105`：较早版本，第一次把 Phase 0 单独抽出来，给出“单场景 + 2 AI + 空间音频 + 1 可交互物品”的里程碑
- `380`：后期版本，明确“先跑通最小闭环，再逐步扩展”，并把 Phase 0 验证目标收束为工程启动口径
- `399/400`：进一步把 Phase 0 定位为服务于 Phase 1 核心体验验证

当前采用规则：

- 以 `380` 为主口径
- `105` 作为 Phase 0 里程碑的前置来源
- `102` 只保留其 L3 作为辅助验证链路的部分，不直接继承其更宽泛的分阶段描述

## 3. 启动目标

Phase 0 目标不是做出“可玩剧本”，而是验证以下技术链路是否成立：

1. Godot 场景可稳定运行
2. Godot 与 Python 后端可实时互通
3. AI 角色可完成基础文本输入到语音输出的对话闭环
4. 玩家与 AI 的空间距离可影响声音体验
5. 物品交互可触发结构化事件并回显结果

如果以上链路无法稳定跑通，则不应进入 Phase 1 完整闭环开发。

## 4. 最小闭环定义

Phase 0 最小闭环应严格限制为以下内容：

### 4.1 场景

- 1 个单场景
- 可先用书房、客厅等低复杂度空间
- 只需要基础光照和可导航区域

### 4.2 角色

- 2 个 AI 角色
- 可先使用低保真角色占位体
- 角色至少具备：
  - 被触发后主动打招呼
  - 接收玩家文本输入
  - 语音回复

### 4.3 玩家交互

- 基础移动
- 面向角色发起对话
- 点击 1 个可交互物品

### 4.4 声音

- 玩家靠近 / 远离 AI 时，音量或清晰度变化可感知
- 不要求完整“清晰区 / 模糊区 / 静默区”玩法化，仅需原型证明空间音频方向可行

### 4.5 物品与 L3 验证

- 至少 1 个可点击物品
- 点击后返回一段文字说明或一张线索图
- 如果当期成本过高，可先用静态图代替实时图片生成

说明：

- `102` 中对 L3 的大段设想不作为 Phase 0 必做项
- `380` 的收敛口径优先：L3 在 Phase 0 只需证明“能接”或“能替代性模拟”

## 5. 不在 Phase 0 范围内

Phase 0 明确不做：

- 完整房间系统
- 多场景剧本流程
- 完整司命
- 完整角色智能体
- 投票结算
- 完整线索系统
- 小世界
- 证据链完整闭环
- 创作者工具
- 商业化系统

## 6. 技术验证优先级

按优先顺序执行：

1. Godot 场景与角色占位
2. WebSocket 连通
3. Python AI 回复链路
4. TTS 语音输出
5. 空间音频基础效果
6. 单个物品交互
7. 可选的 L3 演示接口

如果第 1-4 步不稳定，不进入后续扩展。

## 7. 任务拆解

### 7.1 客户端

- 搭 1 个单场景
- 放置玩家起点
- 放置 2 个 AI 占位角色
- 放置 1 个可交互物品
- 实现最小移动、视角和点击交互
- 实现接收 AI 文本 / 语音结果并回显

### 7.2 后端

- 建 1 个最小 WebSocket 服务
- 定义最小消息协议：
  - 玩家输入
  - AI 回复
  - 物品交互结果
- 接入 1 个 LLM 服务
- 接入 1 个 TTS 服务

### 7.3 AI

- 给 2 个角色各配置最小人格标签
- 约束 AI 不输出明显越界信息
- 实现最小上下文拼接

### 7.4 可选 L3

- 物品点击后返回线索图片
- 或先返回静态替代图，验证前端呈现链路

## 8. 验收标准

Phase 0 的验收产物应是一段可重复录制的视频或可现场演示的原型。

必须满足：

1. 玩家进入单场景
2. AI 角色主动打招呼
3. 玩家输入一句问题
4. AI 角色语音回复
5. 玩家移动导致音量或声音感知发生变化
6. 玩家点击物品后得到可见反馈

若上述 6 项有任一项不稳定，则 Phase 0 未通过。

## 9. 止损条件

出现以下任一情况，需要暂停扩展，先回到技术链路修复：

- Godot ↔ Python 通讯不稳定
- AI 回复延迟不可接受
- TTS 无法稳定接入
- 客户端回显与交互频繁断裂
- 每增加一个最小功能都导致整体链路显著不稳定

## 10. 下一阶段入口

只有在 Phase 0 通过后，才进入 Phase 1 的完整闭环开发。

Phase 1 的第一步不是继续加愿景，而是：

- 把单场景扩成双场景
- 把 2 个 AI 角色扩成首个剧本所需角色集
- 引入事实锁定、房间管理和完整玩法循环
