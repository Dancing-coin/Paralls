# 商业与生态设计

## 状态

- 当前状态：第一轮可执行整理稿
- 主要用途：统一平台、大玩家、创作者、玩家四方关系与三阶段项目边界
- 事实口径：以 `210-211` 为商业结构主依据，并受 `398-400` 的阶段收束约束

## 当前冻结结论

- 《开本》平台兼具“技术基建方”和“官方资产 / 云服务提供方”双重身份
- 平台不能只写成抽成市场，也不能只写成内容平台；它还是最大的官方资产供给者和算力、云服务提供者
- 大玩家是“剧院经营者 / 世界经营者”，创作者是“内容生产者”，玩家是“体验者与世界公民”
- 当前 Phase 1 只验证商业可行性接口和价值，不完整交付生态系统
- 商业与生态文档不得反向扩大 Phase 1 范围
- 常规云端经营成本按“谁经营谁承担”拆分；云游戏基础设施应由平台统一建设运营，不下放给大玩家独立承接

## 1. 文档目标

本文档回答四个问题：

1. 平台自身在生态中到底扮演什么角色。
2. 大玩家、创作者、玩家分别如何参与。
3. 收入和成本大致如何分布。
4. 这些商业想象与当前 Phase 1 的执行边界如何相处。

## 2. 时间线覆盖说明

- 主证据轮次：`210`、`211`
- 关键补证：`200`、`203`、`205`、`249-250`、`315`、`322`、`400`、`406-437`
- 明显过时口径：把平台仅理解为交易抽成方，忽略其官方资产供给和算力云服务属性

## 3. 核心修订点

### 3.1 从“平台撮合交易”改为“双重平台身份”

`211` 之后的稳定口径是：平台不是纯市场中介，而同时承担：

- 技术基建方
- 官方资产供给方
- 算力 / 云服务提供方

这决定了商业模式不能只写：

- 抽成
- 会员
- 门票

还必须写：

- 官方剧本和世界资产销售
- AI 算力套餐
- 云存储与云服务器
- 资产托管

### 3.2 从“角色单一”改为“四方生态结构”

后期比较稳定的参与结构是：

- 平台：提供底座、官方内容、算力和市场
- 大玩家：经营服务器、策展、服务社群
- 创作者：生产剧本、角色、场景、机制包
- 玩家：消费、社交裂变、二创、众筹支持

### 3.3 从“愿景全开”改为“分阶段验证”

商业生态的长期图景很大，但 `398-400` 之后必须承认：

- Phase 1 不做完整创作者生态
- Phase 1 不做完整大玩家体系
- Phase 1 不做完整资产市场和区块链确权

当前只能把这些写成后续生态方向，不是当前交付承诺。

### 3.4 建造商业线当前以“建筑蓝图资产”为主

当前商业落点不是完整体素沙盒经济，而是：

- 建筑蓝图设计与售卖
- 蓝图导入生成服务
- 蓝图授权与分成

这条线可与创作者生态和大玩家经营对齐，但不应在 `Phase 1` 承诺完整世界编辑与生态模拟商业闭环。

蓝图资产最小计费单元（V1）：

- 蓝图授权费：按授权模式（单次/周期/范围）计费
- 导入生成服务费：按实例化请求与资源消耗计费
- 运行回写审计费：按审计记录与留存周期计费（平台侧能力）

授权模式最小集合（V1）：

- 仅个人使用
- 可被大玩家世界导入（需署名）
- 商业世界可用（需分成）

### 3.5 云端成本归属与云游戏供给边界

当前收束口径：

- 常规服务器云成本：谁经营谁承担（官方承担官方世界，大玩家承担其经营世界）
- 云游戏基础设施成本（GPU 云渲染、流媒体、边缘节点）：由平台统一建设与运营
- 玩家端采用“主流硬件准入 + 云游戏兜底”，低配设备通过云游戏接入

这三条要并列写，避免把“经营算力”与“云游戏平台算力”混成一条账。

## 4. 平台的双重身份

### 4.1 技术基建方

平台提供：

- 司命叙事引擎
- 角色智能体引擎
- 创作工具链
- 事件总线、空间音频、匹配与跨服基础设施
- 资产市场与后续结算能力

这一层决定平台不是单纯内容公司，而是系统能力提供者。

### 4.2 官方资产供给方

平台还直接生产或控制：

- 官方平行世界
- 官方剧本
- 官方角色智能体模板
- 官方 3D 场景和外观资产
- 官方玩法机制包

这决定平台不是完全中立的空市场，而是生态中的最大“种子内容提供者”。

### 4.3 云服务方

平台还提供：

- AI 推理算力套餐
- 云存储
- 云服务器
- 资产托管
- 后续持续运行世界的托管能力

这使平台的商业模式天然包含 SaaS / 云服务属性。

## 5. 平台收入结构

当前稳定可写的收入类型：

- 官方资产销售与授权
- AI 算力套餐
- 云服务与扩容
- 市场交易抽成
- 官方服务器收入
- 玩家会员订阅

其中要注意：

- 官方资产销售和算力服务是被 `211` 强化后的关键项
- 不能再只把平台写成“从别人交易里抽成”的平台

## 6. 大玩家参与模式

### 6.1 当前定位

大玩家不是普通房主，而是：

- 社群经营者
- 内容策展者
- 世界 / 服务器运营者

### 6.2 当前两种典型模式

- 影院模式：灵活策展、多题材轮换、投入较轻
- 主题世界模式：强绑定单一世界观、投入更高、品牌沉淀更深

### 6.3 大玩家收入来源

可稳定保留的项目：

- 门票 / 入场券
- 会员订阅
- 服务器内虚拟道具 / 皮肤
- 直播互动玩法
- 众筹 / 活动冠名
- 私域裂变返利

### 6.4 大玩家成本结构

关键成本：

- AI 算力套餐
- 剧本授权
- 美术与场景资产采购 / 租赁
- 营销推广
- 服务器基础云费

### 6.5 云端成本拆账口径（新增）

大玩家承担：

- 其经营世界的常规算力与服务器成本
- 对应内容经营活动引发的可归属云端消耗

大玩家不承担：

- 平台级云游戏基础设施建设成本
- 全平台边缘节点与流媒体底座的统一运维成本

大玩家承担的建造链路成本（V1）：

- 其经营世界中的蓝图导入与实例化执行成本
- 对应审计记录留存的可归属成本

平台承担的建造链路底座成本（V1）：

- 蓝图资产索引、授权校验与跨世界映射基础设施
- 冲突审核队列与统一审计服务

## 7. 创作者参与模式

### 7.1 当前定位

创作者是内容生产者，不限于写剧本，也包括：

- 角色模板
- 场景资产
- 机制包
- 完整平行世界框架
- 外观与声线资产

### 7.2 当前收入来源

可稳定保留的项：

- 剧本销售 / 订阅
- 资产市场交易
- 众筹收入
- Fork 授权费
- 大玩家剧本使用分成
- 跨媒介授权

补充当前更明确的资产化入口：

- 建筑蓝图销售与授权分成
- 蓝图导入生成相关的服务型收费接口

### 7.3 当前成本结构

- 平台服务费
- AI 算力使用费
- 官方 / 社区资产采购费
- Fork 授权费
- 云存储费

### 7.4 创作者成长路径

当前草案可保留的路径：

- 新人：验证创意
- 成熟创作者：产出精品资产
- 工作室：系列化品牌生产
- 大师 / 世界主：构建原创平行世界

## 8. 玩家参与模式

### 8.1 当前定位

玩家不仅消费内容，也通过：

- 社交裂变
- 众筹支持
- 内容二创
- 评分与反馈

参与生态共建。

### 8.2 玩家消费结构

可稳定保留的消费项：

- 剧本买断 / 门票 / 订阅
- 皮肤、主题、声线、动作表现
- 智能体收编与个性化
- 社交增值
- 纪念内容与云存档扩容
- 算力与云服务

### 8.3 玩家权益保障

当前可写的保障包括：

- 买断资产永久权
- 跨服资产有效性
- 一定范围的退款保障
- P2P / 本地保存方向

这些条目仍偏远期体系，Phase 1 只适合作为方向，不应承诺全部完成。

## 9. 四方关系图

当前生态关系应理解为：

- 平台提供底座、官方资产和算力
- 创作者生产内容和资产
- 大玩家经营内容与社群
- 玩家消费、传播并反哺市场

平台不是旁观者，而是同时参与技术、内容和基础设施三层价值分配。

## 10. Phase 边界

### 10.1 Phase 1 当前可写

- 首个剧本付费意愿验证
- 玩家对 AI 带走与小世界的情感价值验证
- 未来剧本买断、门票和智能体相关付费接口的预留
- 官方主产品与官方首批内容的价值验证

### 10.2 Phase 1 当前不应写成已交付

- 完整创作者市场
- 完整大玩家服务器体系
- 完整链上确权与智能合约分账
- 完整世界经营商业闭环
- 成熟的多边市场飞轮

## 11. 当前采用规则

- 以 `211` 的修订版商业模型为平台主口径
- 平台必须同时写清“技术基建方 + 官方资产 / 云服务方”双重身份
- 商业文档只能描述后续生态方向，不能反向扩大当前 Phase 1 交付
- 与 Phase 1 直接相关的商业内容，只能写验证目标、接口预留与最小变现假设

## 12. 延后项

- 具体抽成和分账比例的正式冻结
- 区块链确权与合约分账单独设计稿
- 大玩家经营手册单独成文
- 创作者生态与 Fork 机制单独成文
