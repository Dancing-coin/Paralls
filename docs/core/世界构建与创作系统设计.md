## 3. 分层模型

### 3.1 场景级（Scene Layer）

- 面向创作者的局部空间建造与蓝图化
- 产出：场景资产、建筑蓝图、局部交互点配置
- 不负责：世界级全局规则与多场景编排

### 3.2 世界级（World Layer）

- 面向大玩家的世界编排与规则装配
- 负责：场景拼接、世界地图组织、全局参数约束
- 不负责：底层渲染 / 物理内核替代

### 3.3 运行级（Runtime Layer）

- `Godot` 承担渲染与物理运行时
- 规则封装层负责规则执行、状态回写、异常治理
- 通过事件总线与 `ESM`、司命、角色层协同

## 4. 权限矩阵（冻结版）

| 操作 | 创作者 | 大玩家 | 玩家 |
| :--- | :---: | :---: | :---: |
| 新建场景资产 | ✅ | ✅ | ⬜ |
| 编辑生物/物件底层模板 | ✅ | ✅（受授权） | ⬜ |
| 发布蓝图到市场 | ✅ | ✅ | ⬜ |
| 世界地图编排 | ⬜ | ✅ | ⬜ |
| 世界规则参数配置 | ⬜ | ✅ | ⬜ |
| 在世界内使用蓝图 | ✅ | ✅ | ✅（受世界规则约束） |
| 运行时组合/培育/组装 | ⬜ | ⬜ | ✅（受模板边界约束） |
| 回滚世界级改动 | ⬜ | ✅ | ⬜ |

说明：

- 玩家可“使用与组合”，不可“越权编辑底层模板”。
- 大玩家对创作者资产的编辑权必须依赖授权策略。

## 5. 蓝图与资产生命周期

```text
创作
  -> 本地校验
  -> 版本固化
  -> 发布授权
  -> 市场流通
  -> 世界导入
  -> 运行时实例化
  -> 状态回写与审计
```

阶段要点：

- `Phase 1`：建筑蓝图闭环（创建/发布/导入/实例化）
- `Phase 2`：创作者工具外放与更完整授权策略
- `Phase 3`：持续世界下的跨世界资产演化

### 5.3 校验错误码（V1）

| 错误码 | 含义 | 处理策略 |
| :--- | :--- | :--- |
| `E_AUTH_DENIED` | 权限不足或授权范围不匹配 | 直接拒绝，写审计 |
| `E_DEP_MISSING` | 依赖资产缺失 | 拒绝并返回缺失依赖列表 |

| `E_CONFLICT_REVIEW` | 自动合并失败需人工处理 | 进入审核队列 |
| `E_RUNTIME_FAILURE` | 实例化执行失败 | 回滚并写异常审计 |

## 6. 映射更新与冲突合并

### 6.1 映射对象

- 场景状态映射（局部状态）
- 世界地图映射（全局位置与可达性）
- 资产实例映射（模板与实例关系）

### 6.2 冲突优先级（冻结版）

1. 世界级规则约束
2. 授权约束
3. 场景级本地改动
4. 运行时临时状态

### 6.3 合并策略（冻结版）

- 同层冲突：按版本时间戳 + 操作人权限等级判定
- 跨层冲突：高层规则优先，低层改动降级为候选补丁
- 不可自动合并：进入人工审核队列（大玩家/官方）

## 7. 生物与物件创作链路

### 7.1 三层链路

- 形态层：外观、部件、骨架、点云过渡素材
- 参数层：属性模板、材料参数、可交互标签
- 行为层：生长/繁殖/组装/安装的可执行规则

### 7.2 与 ESM 边界

- `ESM` 负责行为层的物理与状态执行
- 本文档负责行为规则如何由创作产物映射到 `ESM` 可执行输入
- “生长/繁殖”完整版不前置到 `Phase 1`

## 8. 与其他 core 的接口

- 对 `技术架构总纲`：提供世界构建系统的统一边界与术语
- 对 `核心玩法机制设计`：提供创作权限与玩家玩法边界
- 对 `商业与生态设计`：提供蓝图授权与资产流通约束
- 对 `Phase 1 项目计划书`：提供“可交付闭环 vs 后移能力”切线

## 10. Phase 1 验收阈值（建造链路）

- 蓝图导入校验拦截率：`100%`（越权与非法依赖不得漏拦）
- 蓝图导入成功率：`>= 95%`（合法请求）
- 实例化回写成功率：`>= 99%`
- 自动合并成功率：`>= 90%`（同层且无权限冲突）
- 冲突工单 `P1/P2` 闭环时间：`P95 <= 30 分钟`
- 审计记录完整率：`100%`
