## 当前冻结结论

- `Phase 0` 的目标是验证最小技术闭环，不是提前做完 MVP。
- 里程碑 demo 至少包含：单场景、2 个智能体驱动角色、基础对话、空间音频、1 个可交互物品、Godot ↔ Python 打通。
- 当前用户补充的 `Phase 0` demo 目标是：在单个 3D 场景里跑通“两个角色 + 环境 / 物体 + 司命最小叙事引擎”的短剧情交互演示。

## 1. 文档目标

本文档用于定义《开本》`Phase 0` 的启动边界、原型范围、任务拆解和验收标准。

`Phase 0` 不是产品文档，也不是完整路线图。它只回答一个问题：

> 在最小投入下，我们能否证明智能体驱动的 3D 动态剧本杀核心链路可行？

## 2. 时间线覆盖说明

与 `Phase 0` 相关的前后版本中，当前采用以下顺序理解：

- `102`：较早版本，强调把视频/图片工作流接入 `L3`，并给出分阶段建议
- `105`：较早版本，第一次把 `Phase 0` 单独抽出来，给出“单场景 + 2 AI + 空间音频 + 1 可交互物品”的里程碑
- `380`：后期版本，明确“先跑通最小闭环，再逐步扩展”，并把 `Phase 0` 验证目标收束为工程启动口径
- `399/400`：进一步把 `Phase 0` 定位为服务于 `Phase 1` 核心体验验证

当前采用规则：

- 以 `380` 为主口径
- `105` 作为 `Phase 0` 里程碑的前置来源
- `102` 只保留其 `L3` 作为辅助验证链路的部分，不直接继承其更宽泛的分阶段描述

## 3. 启动目标

`Phase 0` 目标不是做出“可玩完整剧本”，而是验证以下技术链路是否成立：

1. Godot 场景可稳定运行
2. Godot 与 Python 后端可实时互通
3. 2 个智能体驱动角色可完成基础文本输入到语音输出的对话闭环
4. 玩家与 AI 的空间距离可影响声音体验
5. 环境 / 物体交互可触发结构化事件并回显结果
6. 司命可在单场景内对这 2 个角色和环境做最小叙事催化

如果以上链路无法稳定跑通，则不应进入 `Phase 1` 完整闭环开发。

## 4. 最小闭环定义

`Phase 0` 最小闭环应严格限制为以下内容：

### 4.1 场景

- 1 个单场景
- 可先用书房、客厅等低复杂度空间
- 只需要基础光照和可导航区域

### 4.2 角色

- 2 个智能体驱动角色
- 可先使用低保真角色占位体
- 角色至少具备：
  - 被触发后主动打招呼
  - 接收玩家文本输入
  - 语音回复
  - 在最小剧情片段中对环境 / 物体 / 司命催化做出反应

### 4.3 玩家交互

- 基础移动
- 面向角色发起对话
- 点击 1 个可交互物品

### 4.4 声音

- 玩家靠近 / 远离 AI 时，音量或清晰度变化可感知
- 不要求完整“清晰区 / 模糊区 / 静默区”玩法化，仅需原型证明空间音频方向可行

### 4.5 环境、物体与司命

- 至少 1 个可点击物品
- 至少 1 段最小环境 / 物体状态变化
- 至少 1 次司命最小催化，使两个角色和环境组成一段可演示短剧情

### 4.6 L3 验证

- 如果当期成本过高，可先用静态图或简化反馈替代实时生成
- `L3` 在 `Phase 0` 只需证明“能接”或“能替代性模拟”

## 5. 不在 Phase 0 范围内

`Phase 0` 明确不做：

- 完整房间系统
- 多场景剧本流程
- 完整司命
- 完整角色智能体
- 投票结算
- 完整线索系统
- 小世界
- 证据链完整闭环
- 创作者工具
- 商业化系统
