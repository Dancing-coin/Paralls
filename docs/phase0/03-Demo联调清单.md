## 联调链路

1. Godot 单场景加载
2. 玩家移动与基础交互
3. Godot ↔ Python 通讯
4. 2 个角色智能体接入
5. 文本输入 -> LLM -> TTS -> 语音回显
6. 空间音频基础效果
7. 单个物体交互 -> 结构化结果反馈
8. 最小环境 / 物体状态变化
9. 司命最小催化
10. 最小事件链 / debug 证据链可观察

## 每步联调模板

后续继续补充时，统一使用：

- 输入
- 观察点
- 成功条件

## 每步通过条件

### 1. 场景和通信

输入：

- 启动客户端
- 连接后端

观察点：

- 玩家进入场景
- 角色占位体加载
- 基础消息收发日志

成功条件：

- 玩家可进入场景
- 角色可加载
- 客户端和后端之间稳定收发消息

### 2. 两角色对话闭环

输入：

- 玩家面向角色发起一句输入

观察点：

- 至少一个角色主动说话
- 另一角色或同一角色完成回话
- TTS 成功播放

成功条件：

- 至少一个角色主动说话
- 玩家输入能得到语音回复
- 两个角色都能被触发

### 3. 空间音频

输入：

- 玩家靠近 / 远离角色

观察点：

- 音量或清晰度变化
- 旁观者能从 demo 中听出差异

成功条件：

- 靠近 / 远离时感知差异明确
- 演示时能被旁观者听出来，不只是日志里有值

### 4. 单物体交互

输入：

- 玩家点击关键物体

观察点：

- 客户端出现可见反馈
- 后端返回结构化结果

成功条件：

- 点击物体得到结构化反馈
- 该反馈可被角色或司命承接

### 5. 最小 `ESM` 结构化结果

输入：

- 触发一次成功交互
- 再触发一次失败交互或约束失败

观察点：

- 成功交互有 `object_interaction_result` / `environment_state_result`
- 失败交互有 `constraint_state_result`

成功条件：

- `ESM` 至少回写 1 次成功结果
- `ESM` 至少回写 1 次结构化约束结果

### 6. 环境状态变化

输入：

- 触发一次最小环境或物体状态变化

观察点：

- 场景表现变化
- 角色可观察或司命可承接

成功条件：

- 至少一段环境 / 物体状态变化可被表现
- 变化前后可被观察与复述

### 7. 司命最小催化

输入：

- 给司命一个最小局部情境

观察点：

- 司命输出一次高层催化
- 角色或环境对它做出承接

成功条件：

- 司命至少成功触发 1 次高层催化
- 催化结果能引发角色或环境的可见变化

## 观测面

联调时至少同时保留三种观测面：

- 关键日志
