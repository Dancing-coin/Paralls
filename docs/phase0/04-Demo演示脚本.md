# Demo 演示脚本

## 状态

- 状态：第一轮草案
- 作用：冻结 `Phase 0` demo 的演示顺序与验证点
- 上游约束：[02-Demo范围与验收标准.md](/d:/Projects/Paralls/docs/phase0/02-Demo范围与验收标准.md)

## 演示顺序

1. 进入场景，展示玩家可移动
2. 展示 2 个角色加载完成
3. 角色 A 主动发起一句对话
4. 玩家回复一句，角色 A 语音回应
5. 玩家靠近 / 远离角色，展示声音感知变化
6. 玩家点击物体，展示可见反馈
7. 触发一次最小环境或物体状态变化
8. 展示司命对这段局部情境进行 1 次最小催化
9. 展示两个角色对催化和环境变化做出反应

## 演示前准备

演示开始前应确认：

- 场景启动稳定
- 两个角色均在线
- TTS 正常
- 关键物体可交互
- 司命最小催化入口已可触发

## 每一步在证明什么

### 1. 进入场景

证明：

- Godot 场景本体可运行
- 玩家可控输入链成立

### 2. 角色加载完成

证明：

- 角色副本正常存在
- 两个角色都可被后端驱动

### 3. 角色 A 主动发起对话

证明：

- 至少一个角色具备最小主动性
- 不是纯被动问答机

### 4. 玩家回复，角色语音回应

证明：

- 文本输入 -> LLM -> TTS -> 回显链成立

### 5. 声音感知变化

证明：

- 空间音频方向成立
- 距离变化会影响感知结果

### 6. 点击物体

证明：

- 物体交互链成立
- 交互结果可被场景表现

### 7. 环境 / 物体状态变化

证明：

- 不只是静态问答
- 世界内至少有一个“状态会变化”的对象

### 8. 司命最小催化

证明：

- 司命能作为最小叙事引擎介入
- 不是只有角色和玩家自说自话

### 9. 两角色承接变化

证明：

- 角色、环境、司命三者能形成一段最小剧情交互
- demo 已不是孤立功能拼装，而是最小戏剧闭环

## 本次演示在证明什么

- Godot 场景与角色副本可稳定运行
- 智能体驱动角色可完成最小对话闭环
- 空间音频方向可行
- 物体 / 环境 / 角色 / 司命能形成一段最小剧情交互

## 通过口径

如果这 9 步能稳定、重复地演示，并且旁观者能看懂“角色、环境、司命共同构成了一段短剧情”，则 `Phase 0` demo 通过。

## 失败回退脚本

如果演示时某一步失败，建议按以下优先级回退，保证 demo 仍能说明最小闭环：

1. 若空间音频波动不稳定：
   - 退回为“日志 + 近远距离可见数值变化”辅助说明
2. 若司命最小催化未能自动触发：
   - 切换为手动触发一次预设催化，证明链路可走通
3. 若环境变化表现不稳定：
   - 回退到物体变化反馈，先证明“世界结果可被角色和场景承接”
4. 若第二角色承接不稳定：
   - 保底保证第一角色完整承接，避免整个 demo 断掉

原则：

- 优先保住“最小戏剧闭环”讲述
- 不硬撑展示还没稳定的复杂段落
