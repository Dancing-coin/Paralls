## 3. 盒子解释（最短版）

### 3.1 Godot 单场景客户端

当前只负责：

- 玩家移动
- 角色副本承载
- 物体点击交互回显
- 空间音频回显
- 环境变化的可见表现

当前不负责：

- 角色认知真值
- 司命叙事判断
- 完整证据链推理

上位约束：

- [Godot源码底层基础设施与运行时约束.md](/d:/Projects/Paralls/docs/phase1/core/00-总纲/Godot源码底层基础设施与运行时约束.md)

### 3.2 后端协调层

当前只负责把最小输入输出链串起来：

- 接收 `Player Input`
- 分发给角色智能体
- 分发给司命最小叙事引擎
- 回收 `AI Output`
- 回收物体 / 环境结果
- 回写给 Godot

### 3.3 两个角色智能体

当前只要求证明：

- 能被驱动
- 能最小主动说话
- 能响应玩家输入
- 能承接环境 / 物体 / 司命催化

不要求完整人格、长期记忆、多轮复杂博弈。

### 3.4 司命最小叙事引擎

当前只要求证明：

- 能识别局部情境
- 能触发一次高层催化
- 能让角色、环境、物体形成一段可观察短剧情

不要求完整单局导演能力。

### 3.5 物体 / 环境结果层

当前只要求：

- 至少 1 个物体交互结果
- 至少 1 段环境或物体状态变化
- 这些变化能被角色和司命承接

### 3.6 最小 `ESM` 内核

当前只要求：

- 对单个关键物体做最小状态结算
- 对单段环境变化做最小状态结算
- 对失败交互返回结构化约束结果

当前不要求：

- 完整物理世界模拟
- 连续天气与复杂传播

## 4. 最小必须成立的输入输出链

### 4.1 玩家输入链

`Player Input -> 后端协调层`

至少成立：

- `move_intent`
- `dialogue_submit`
- `interact_intent`

### 4.2 角色输出链

`后端协调层 -> 角色智能体 -> AI Output -> Godot`

至少成立：

- `dialogue_response`
- `interaction_reaction`

### 4.3 物体 / 环境结果链

`interact_intent -> Object / Environment Result -> Godot / 角色 / 司命`

至少成立：

- `object_interaction_result`
- `environment_state_result`
- `constraint_state_result`

### 4.4 司命最小催化链

`局部情境成立 -> 司命最小输出 -> 角色或环境变化`

至少成立：

- `narrative_nudge`
或
- `attention_prompt`
或
- `situation_shift`

## 5. 当前明确不在范围内

这次 demo 当前不负责：

- 完整房间系统
- 多场景流程
- 完整司命
- 完整角色智能体
- 完整证据链
- 投票结算
- 小世界
- 创作者工具
- 商业化系统

## 7. 一句话收束

`Phase 0` 的技术构成不是“把所有最终系统先做薄一层”，而是：

> 在一个单场景里，用玩家输入、两个角色、一个物体 / 环境变化点和一次司命最小催化，证明《开本》的最小戏剧闭环在技术上能跑通。
