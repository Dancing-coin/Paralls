# 会话成员资格、隐私与偷听机制设计稿

## 1. 文档定位

- 状态：设计稿
- 主题：多场景多人会话中的成员资格、隐私保护、偷听、加入与排斥机制
- 适用范围：`Phase 1` 单房间单实例优先，同时要求接口与语义不锁死未来多房间/云地混合
- 作用：作为事件总线、`L1` 事实上抛器、司命高阶知识图谱、角色智能体之间的配套约束文档

本设计稿不替代以下正式文档：

- `docs/phase1/core/00-总纲/L1层架构初稿.md`
- `docs/phase1/core/01-运行时核心/事件总线与感知链路设计.md`
- `docs/phase1/core/01-运行时核心/司命设计文档.md`
- `docs/phase1/core/01-运行时核心/角色智能体设计文档.md`

本设计稿只回答一件事：在司命与角色智能体内部细节尚未完全冻结时，如何先收敛“会话成员资格、隐私边界、偷听与加入机制”的跨模块运行时契约。

## 2. 当前判断前提

### 2.1 顶层前提

- `Phase 1` 先按单房间单实例优先
- 语义与接口不能锁死未来多房间、多场景并行与云地混合
- 事件总线先冻结跨模块运行时契约，不冻结司命和角色智能体内部推理细节

### 2.2 关键边界

- `L1` 负责上抛空间接入、声学传播、遮挡与社交行为事实
- 事件总线负责传输事实，不负责知识推理
- 司命的高阶知识图谱子系统负责确认“互相知晓”与成员资格变化
- 角色智能体负责接收自身可知结果，并将其转化为理解、记忆、规划与具身表现

### 2.3 核心原则

- 听见不等于加入
- 加入不等于自动补全更早历史
- 沉默者可以是成员
- 偷听成功不自动授予成员资格
- 私密对话的隐私必须可经营，而不是纯随机

## 3. 基础定义

### 3.1 作用域层级

- `room`：单局运行时会话容器
- `scene`：房间内承载交互与空间状态的地图单元
- `zone`：场景内用于感知裁剪和路由的局部范围
- `dialog_group`：运行时临时会话组，用于耳语、密谈、阵营共享或限定对象沟通

### 3.2 会话开放度

- `open`：公开对话，允许自然接近和加入
- `local`：局部对话，允许接近、旁听与有限自然加入
- `private`：私密对话，默认不自动接纳，隐私保护优先

### 3.3 会话参与状态

- `overhearer`：听到内容，但未形成成员资格
- `candidate_member`：进入接入条件，可能被纳入
- `passive_member`：已被纳入但尚未主动发声
- `active_member`：已主动发声参与
- `excluded`：被明确或隐式排斥出当前会话
- `rejoin`：曾离开或被中断后重新接回会话

### 3.4 成员资格规则

成员资格不由单一空间条件决定，而由三件事共同决定：

- 可感知接入事实已成立
- 司命高阶知识图谱确认互相知晓已成立
- 当前未被排斥

正式规则：

`成员资格 = 可感知接入 + 司命高阶知识图谱确认互相知晓 + 未被排斥`

## 4. 对话路由规则

### 4.1 作用域职责

- `room` 负责会话隔离，不作为普通对话默认传播面
- `scene` 负责同一场景内的公开传播
- `zone` 负责局部空间内的传播
- `dialog_group` 负责临时私有或半私有传播
- `direct` 负责单一目标的直接结果消息

### 4.2 默认映射

- 公开发言：默认 `scene`
- 普通近距聊天：默认 `zone`
- 耳语：默认 `dialog_group`
- 指定对象低声提醒：`direct` 或 `dialog_group`
- 阵营私下同步：`dialog_group`
- 大声呼救或争吵：`scene`
- 阶段切换与系统广播：`room`

### 4.3 加入规则

- 公开与局部会话：满足接入条件后，发声即可自动升格为 `active_member`
- 私密会话：进入范围后先为 `candidate_member`，默认不自动升级为成员
- 若已形成互相知晓且未被排斥，则即使未发声，也可成为 `passive_member`
- 新成员的有效上下文只从其 `heard_from_ts` 开始，不因成员资格变化而补发更早历史

### 4.4 沉默成员规则

如果角色：

- 在当前参与者的可感知范围内
- 当前参与者知道其在场
- 其本人知道参与者知道自己在场
- 当前会话没有发生排斥动作

则其即使不发声，也应被视为 `passive_member`，而不是偷听者。

## 5. 偷听与隐私保护

### 5.1 偷听不是布尔判定

偷听结果建议至少分五级：

- `0`：完全听不到
- `1`：知道有人在说话
- `2`：听到情绪、语气或关键词
- `3`：听到大意
- `4`：听清全文

### 5.2 偷听成功率输入

偷听判定必须是条件驱动，而不是纯随机。输入至少包括：

- 说话模式：正常 / 压低 / 耳语 / 喊叫
- 距离
- 朝向
- 遮挡与门窗状态
- 环境噪音
- 偷听者的听觉或偷听能力
- 说话者的隐私敏感度与反偷听行为
- 会话开放度
- 偷听者当前注意力与状态

### 5.3 私密性推断

系统默认根据以下事实自动推断会话是否趋于私密：

- 音量降低
- 站位收紧
- 角色围拢
- 关门、关窗、拉帘
- 远离旁人或退入角落
- 避开公共动线

角色不需要显式切换“私密模式”。

### 5.4 隐私保障原则

私密对话的隐私应通过以下行为被系统显著保护：

- 关门、关窗、调整遮挡
- 压低音量
- 选择更私密位置
- 减少围观者接入角度
- 说话者对靠近者做出回避或排斥反应

## 6. L1 事实上抛器与会话状态机输入映射

### 6.1 基本边界

所有空间接入相关底层事实，必须来自 `L1` 执行侧事实上抛器或 `ESM` 状态回写；司命只基于这些事实，通过高阶知识图谱判定成员资格、互相知晓、排斥与加入状态，不得反向虚构空间接入事实。

### 6.2 八类上抛器中与会话最相关的硬依赖

#### 视觉事实上抛器

至少负责：

- 角色在场可见性
- 朝向可见性
- 会话圈内外的可见纳入迹象
- 门口、入口、拐角等关键位置上的出现事实

#### 听觉事实上抛器

至少负责：

- 发声开始 / 结束
- 音量档位
- 声源位置
- 环境噪音基础事实
- 耳语、正常、喊叫等声学模式

#### 社交距离与空间行为上抛器

至少负责：

- 靠近、停留、退开、围拢
- 插入对话圈、转移站位、回避
- 进入 / 离开 `scene`
- 进入 / 离开 `zone`
- 与关键对象的距离变化

#### 交互边界回写

由交互系统或 `ESM` 回写：

- 开门、关门
- 开窗、关窗
- 拉帘、移物形成遮挡
- 制造背景噪音或掩护音源

### 6.3 原始事实与派生事实的边界

`L1` 只上抛：

- 谁走近了
- 谁进入了哪个 `scene/zone`
- 门关没关
- 音量压低没压低
- 谁停留了多久

`L2` 才能派生：

- 是否构成 `approach_detected`
- 是否形成互相知晓
- 是否从 `candidate_member` 升为 `passive_member`
- 是否被排斥
- 是否完成 `join_transition`

## 7. 司命的职责落位

### 7.1 高阶知识图谱的会话职责

司命的高阶知识图谱子系统负责：

- 确认“谁知道谁在场”
- 确认“谁知道别人知道自己在场”
- 判断角色是否只是偷听者，还是已被社会性纳入会话
- 结合排斥信号确认成员资格变化

### 7.2 排斥判定

未被排斥应采用：

- 隐式行为判定为主
- 少量明确动作作为强覆盖信号

隐式排斥信号包括：

- 集体降声
- 转身背离
- 收紧站位
- 集体转移位置
- 关门后继续交谈
- 停止当前话题

明确排斥信号包括：

- 要求对方离开
- 明确说明“这不是你该听的”
- 主动切断对话面

### 7.3 会话状态转换输出

司命对角色侧输出的会话关系结果至少应支持：

- `overhearer`
- `candidate_member`
- `passive_member`
- `active_member`
- `excluded`
- `rejoin`

## 8. 角色智能体的接口要求

### 8.1 会话参与状态子模块

归属：`角色智能体 -> 动态状态系统 -> 会话参与状态子模块`

建议字段骨架：

- `active_conversation_refs`
- `primary_conversation_id`
- `conversation_role_state`
- `heard_from_ts`
- `member_from_ts`
- `knowledge_confirm_level`
- `privacy_pressure`
- `exposure_risk`
- `exclusion_signal_state`
- `join_path`
- `speech_entitlement`
- `attention_focus_in_conversation`

### 8.2 与人格档案的关系

人格档案只提供长期倾向与能力参数，例如：

- 听觉与偷听能力
- 社交开放度
- 隐私敏感度
- 回避 / 迎战倾向
- 健谈度
- 礼仪 / 边界感
- 伪装与控场能力
- 压力响应风格
- 信任门槛

人格档案不保存当前会话态。

### 8.3 与记忆系统的关系

一场会话结束后，角色不应把“整场对话”混成一条记忆，而应拆入：

- 事件记忆：这场会话发生了什么
- 观察记忆：我听到或看到什么
- 知识记忆：我因此知道了什么
- 社交记忆：我对谁的判断发生了变化
- 高阶记忆：我认为别人知道什么

### 8.4 与 L2/L3/L4 的关系

#### L2 理解层

负责把会话参与状态解释成：

- 我被纳入了吗
- 我是不是暴露了
- 我现在该警惕谁
- 我听到的内容可信度如何

#### L3 规划层

负责基于会话状态生成候选行为：

- 插话加入
- 维持沉默
- 邀请加入
- 排斥或回避
- 压低音量
- 转移位置
- 中止话题
- 试探沉默成员

#### L4 执行层

负责将这些结果映射成：

- 语音与音量
- 站位和朝向
- 社交距离变化
- 微表情与小动作
- 明示或暗示的接纳 / 排斥行为

- `L1` 事实上抛器与司命高阶知识图谱的职责边界

- 各类对话的完整优先级和调度细则

## 10. 当前结论

当前最合理的机制不是“只有邀请才能加入”，也不是“进入范围自动加入”，而是：

`成员资格由空间接入事实、司命高阶知识图谱确认的互相知晓，以及未被排斥三者共同决定。`

同时：

- 听见与加入分离
- 沉默在场者可以成为成员
- 偷听者不因获取内容自动变成员
- 新加入者的上下文按个人实际听到的时间线切片
- 私密对话由空间条件、音量控制、遮挡、回避行为与偷听条件共同塑形
