# docs 文档总纲（总体架构 + 分阶段结构）

## 1. 目标

本文件是 `docs` 目录的上游治理文档，作用是：

- 给出《开本》总体架构（跨阶段的稳定边界）
- 规定 `phase1/phase2/phase3` 的并列目录结构
- 约束各阶段 `core/expansion` 的落文规则
- 确保“总体设计”和“分阶段设计”可同时维护

## 2. 目录总览（并列）

- `phase1/`：首个可玩闭环阶段
- `phase2/`：跨局叙事与创作者生态阶段
- `phase3/`：持续世界与完整生态阶段
- `consolidation/`：来源追踪、冲突覆盖、Phase 映射

## 3. 总体架构（跨阶段稳定骨架）

### 3.1 架构层

- `L1` 确定性空间执行层：交互、物理、空间音频、事件上抛
- `L2` 智能决策层：角色智能体、司命、知识与信息博弈
- `L3` 表现增强层：点云过渡、视觉障眼法、高光编排
- `L6` 跨层基础设施层：事件总线、房间状态、持久化、存档
- `L4/L5` 生态运营层：商业运营与平台治理（按阶段渐进开放）

### 3.2 当前优先级原则

- `Phase 1` 以 `L1/L2/L3/L6` 闭环为硬优先级
- `L4/L5` 在 `Phase 1` 只保留最小可验证切片与接口预留
- `L4/L5` 完整体系主要在 `Phase 2/3` 成熟

## 4. 分阶段文档结构规范

每个阶段统一采用以下结构：

- `core/`：该阶段验收必做（硬门槛）
- `expansion/`：该阶段可选扩展或下一阶段预留

### 4.1 Phase 1 规则

- 以 `docs/phase1/README.md` 为准
- `core = Phase 1 必做`

### 4.2 Phase 2 规则

- 以 `docs/phase2/README.md` 为准
- `core = Phase 2 必做`

### 4.3 Phase 3 规则

- 以 `docs/phase3/README.md` 为准
- `core = Phase 3 必做`

## 5. 写作与迁移规则

- 新文档先判定阶段，再判定 `core/expansion`
- 不允许把后期终局能力直接压入早期 `core`
- 目录迁移后必须同步：
  - `docs/consolidation/04-Phase映射表.md`
  - 对应阶段 `README.md`
  - 相关索引文件（`INDEX.md`）

## 6. 真源与冲突覆盖

- 主真源：`filtered_conversation_split/`
- 处理目标轮次时必须核对相邻序号文档
- 同议题以后轮覆盖前轮
- 冲突与覆盖结论必须回填 consolidation

## 7. 最小闭环检查清单

每次结构或大文档更新后至少检查：

- 总体架构边界是否被破坏（尤其 L1/L2/L3/L6 职责）
- 阶段边界是否被破坏（是否把后期能力误写进早期 core）
- 链接路径是否有效（phase/core/expansion）
- consolidation 是否同步
