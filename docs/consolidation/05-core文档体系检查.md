1. 当前 `docs/core` 是否还缺少必须新增的核心文档。
2. 哪些议题虽然重要，但目前更适合继续作为现有核心文档的章节，而不是新开一个 `core` 文档。

## 3. 检查结论

### 3.1 当前不建议新增新的 core 文档

结论：当前阶段不建议再新增新的 `core` 文档。

原因：

- 运行时主骨架已经被 `技术架构总纲 + 司命 + 角色智能体 + 事件总线与感知链路 + 信息共享 + ESM` 覆盖。
- 玩法底座已经被 `核心玩法机制设计 + 目标与任务系统设计` 覆盖。
- 情感闭环已经被 `AI陪伴与小世界设计` 覆盖。
- 项目级平台与远期价值已经被 `产品白皮书 + 商业与生态设计` 覆盖。
- 执行层边界已经被 `Phase 0 启动方案 + Phase 1 项目计划书` 覆盖。

当前缺的不是“再多一个 core 标题”，而是继续把现有核心文档做深、做一致、补足时间线覆盖说明。

### 3.2 `信息共享执行系统` 已经完成 core 升格，不必重复新增

`02-模块来源索引.md` 已明确：`信息共享执行系统` 具备独立核心文档条件。

当前仓库中已经有：

- `信息共享与知识状态设计.md`

因此，这一升格动作已经完成，不需要再单独新增一份平行 `core` 文档。

### 3.3 `商业与生态` 已完成 core 升格

用户已明确同意把 `商业与生态` 升为 `core`。

当前仓库中已经有：

- `商业与生态设计.md`

因此，这一方向也不是待新增项，而是待继续深化项。

## 4. 不新增的重点议题

### 4.1 玩家投影 / 旅人模型

当前判断：重要，但暂不单独拆成新的 `core` 文档。

原因：

- 其系统边界主要落在 `角色智能体设计文档` 内部。
- 它和玩家接管点、自动补全层、挂机模式、内心独白 / 冲动 / 决策建议等是同一簇问题。
- 目前单独拆出，容易与角色智能体文档形成重复边界。

当前更合理的做法：

- 继续作为 `角色智能体设计文档` 的重点章节深挖。

### 4.2 证据与痕迹专题

当前判断：不升回 `core`。

原因：

- 用户已明确要求将 `证据与痕迹系统设计.md` 降级。
- 当前运行时主骨架仍以 `司命 / 角色 / 事件总线 / ESM / 信息共享` 为中心。
- 证据链虽然重要，但更适合作为专题扩展或玩法绑定文档，而不是重新与运行时骨架并列。

当前更合理的做法：

- 保持降级状态
- 等后续用户要求再讨论 `世界状态与证据链设计` 的处理

### 4.3 特殊人群分类体系

当前判断：不单独新增 `core`。

原因：

- 它是 `目标 / 任务系统` 与角色语法的附属支撑。
- 目前尚不足以与 `司命 / 角色 / 事件总线` 同级。
- 单独升格会造成文档体系失衡。

### 4.4 阵营设计

当前判断：不升格为单独 `core`。

原因：

- 用户已明确指出阵营设计与 `司命 / 角色智能体 / 事件总线` 的核心程度不可比。
- 当前更准确的工程口径是“目标 / 任务系统”，阵营是共享目标与博弈结构的派生结果。

## 5. 后续工作重点

比起新增文档，当前更应该做的是：

1. 继续扩充现有 `core` 文档的时间线覆盖说明。
2. 继续核对 `filtered_conversation_split`，补足后期覆盖关系。
3. 让 `01-决策总表.md` 与各 `core` 文档保持一致。
4. 在需要时补充整理层文档，而不是盲目新增 `core` 文档。

## 6. 当前冻结判断

当前核心文档体系已经够用。

接下来的主要任务是：

- 做深现有 core
- 修正时间线覆盖不全
- 维持模块边界一致

而不是继续扩充 `core` 标题数量。
