# 09-V1实现任务清单-世界构建与创作

## 状态

- 状态：可执行清单（基于 `08` 冻结映射）
- 目标：把 V1 映射转成可排期、可联调、可验收的开发任务
- 范围：仅覆盖 `D104-D108` 的 Phase 1 最小闭环

## 1. 任务分层

| 任务层 | 说明 | 责任面 |
| :--- | :--- | :--- |
| Runtime 层 | 导入校验、实例化、映射同步、冲突检测 | 游戏运行时 / 规则封装 |
| Service 层 | 工单服务、审计服务、指标聚合 | 后端服务 |
| Data 层 | V1 最小表与查询接口 | 数据层 |
| QA/验证层 | 联调脚本、阈值统计、回归门禁 | 测试与运维 |

## 2. 任务清单（V1）

### 2.1 Runtime 层

| ID | 任务 | 输入/输出 | 依赖 | 完成定义 |
| :--- | :--- | :--- | :--- | :--- |
| `WB-RUN-001` | 实现 `wb.import.requested.v1` 消费器 | 入：导入请求；出：校验结果 | 无 | 能接收并落 `request_id` |
| `WB-RUN-002` | 实现导入四段校验（权限/依赖/世界约束/资源） | 入：请求；出：`validated` | `WB-RUN-001` | 能返回 `accepted/rejected/needs_review` |
| `WB-RUN-003` | 实现实例化与回滚执行器 | 入：accepted 请求；出：`instantiated/failed` | `WB-RUN-002` | 失败必回滚并带 `error_code` |
| `WB-RUN-004` | 实现映射同步与冲突检测 | 入：实例或状态变更；出：`mapping.synced/conflict_detected` | `WB-RUN-003` | 冲突必触发工单事件 |

### 2.2 Service 层

| ID | 任务 | 输入/输出 | 依赖 | 完成定义 |
| :--- | :--- | :--- | :--- | :--- |
| `WB-SVC-001` | 工单创建服务 `wb.review.open_ticket` | 入：冲突事件；出：`ticket_id` | `WB-RUN-004` | 所有冲突均有工单 |
| `WB-SVC-002` | 工单闭环服务 `wb.review.close_ticket` | 入：决策；出：闭环事件 | `WB-SVC-001` | `P1/P2` 时长可统计 |
| `WB-SVC-003` | 审计写入服务 `wb.audit.logged.v1` | 入：任一关键动作；出：`audit_id` | `WB-RUN-002/WB-RUN-003/WB-RUN-004` | 拒绝/失败路径 100% 写审计 |
| `WB-SVC-004` | 指标聚合服务（6项 V1 指标） | 入：审计+工单+事件 | `WB-SVC-003` | 可按口径产出日报 |

## 3. 推荐执行顺序

1. `DATA-001~005`（先建最小数据抓手）
2. `RUN-001~004`（先打通运行时主链）
3. `SVC-001~003`（补工单与审计闭环）
4. `QA-001~003`（三条联调脚本）
5. `SVC-004` + `QA-004`（指标聚合与门禁）

## 4. 联调里程碑（V1）

| 里程碑 | 条件 |
| :--- | :--- |
| `M1` 事件可跑通 | `requested -> validated -> instantiated/failed` 全链路通 |
| `M2` 冲突可闭环 | `conflict_detected -> ticket_opened -> ticket_closed` 通 |
| `M3` 指标可观测 | 6 项指标可自动产出 |
| `M4` 可发布 | 达到 `08` 中 Phase 1 阈值 |

## 5. 风险与回退

- 风险：事件字段漂移导致统计失真  
  回退：以 `08` 字段定义为单一口径，新增字段只增不改。
- 风险：冲突路径被绕开  
  回退：发布门禁要求“冲突事件必须有工单”。
- 风险：审计缺失  
  回退：在 `RUN/SVC` 出口统一强制 `wb.audit.logged.v1`。
