# 01-决策总表

## 说明

本表记录《开本》项目当前可采用的核心结论。

判定规则：

- 以 `filtered_conversation_split` 为唯一主源
- 同一议题以后期明确修正后的说法为准
- `规则-参与者分类与死亡规则.md`、`Paralls.md`、`Phase 1.md` 仅作旧稿参考，不作为事实源

字段说明：

- `当前结论`：目前应在新文档中采用的版本
- `主要来源轮次`：最关键的依据
- `次要来源轮次`：补充和细化来源
- `覆盖历史`：说明是否存在旧版本被推翻或修正

## 决策条目

### D001 产品定义

- 议题：产品是什么
- 当前结论：《开本》不是单一剧本杀产品，而是“智能体驱动的3D沉浸式动态叙事平台”；动态剧本杀是 Phase 1 的首个产品形态，不是全部边界。
- 主要来源轮次：`024`、`203`、`379`、`400`
- 次要来源轮次：`018`、`029`、`196-200`
- 覆盖历史：前期讨论常把它表述为“剧本杀世界”或“多人即兴叙事新物种”；后期明确提升为平台级定义。
- 备注：所有总纲文档都应先按“平台”写，再落到 Phase 1 的“动态剧本杀”。

### D002 Phase 1 核心承诺

- 议题：Phase 1 要验证什么
- 当前结论：Phase 1 的核心承诺是“同一个剧本，每一次游戏都不同”，验证“智能体驱动的3D动态剧本杀”是否成立。
- 主要来源轮次：`398`、`400`
- 次要来源轮次：`029`、`203`、`380`
- 覆盖历史：无实质推翻，后期是对前期 MVP 提法的正式收束。
- 备注：后续任何 Phase 1 计划都应围绕“核心体验验证”，而不是提前承接完整生态。

### D003 三阶段路线

- 议题：项目演进路径
- 当前结论：三阶段路线冻结为：
  - Phase 1：静态世界内单局剧本
  - Phase 2：静态世界内连续单局剧本
  - Phase 3：持续运行世界
- 主要来源轮次：`203`、`400`
- 次要来源轮次：`191-195`、`207-209`、`235`、`264`
- 覆盖历史：早期存在“只看完整规划”“先单局再连续再永续”的多种表述，后期在 `203` 和 `400` 形成稳定版本。
- 备注：整理文档时必须把“跨局记忆”和“持续运行世界”分别归到 Phase 2/3，不得混入 Phase 1。

### D004 三层技术架构

- 议题：系统分层
- 当前结论：架构冻结为三层：
  - L1 确定性空间层：3D渲染、物理碰撞、玩家交互、空间音频、事件埋点
  - L2 智能体交互层：角色智能体、司命、对话生成、模型路由
  - L3 视觉增强层：线索特写、记忆闪回、结局CG、WOW时刻
- 主要来源轮次：`203`、`214`、`379`
- 次要来源轮次：`103`、`118`、`130`、`398`
- 覆盖历史：无根本推翻，后期只是不断补充 L3 的职责边界。
- 备注：任何模块说明都应先标明所属层级。

### D005 事实锁定时间线

- 议题：案件事实何时锁定
- 当前结论：采用 T0-T3 锁定机制：
  - T0：锁世界观、角色设定、场景、基础规则
  - T1：锁案件框架
  - T2：锁本局完整事实
  - T3：事实不再改，但叙事路径、冲突和结局可继续涌现
- 主要来源轮次：`031`、`398`
- 次要来源轮次：`030`、`032`、`310`
- 覆盖历史：该结论直接修正了“剧本写完即锁定全部真相”的早期不稳定说法。
- 备注：这是剧本模板、规则引擎、司命事实核心的共同前提。

### D006 动态叙事的边界

- 议题：什么是“无限体验”
- 当前结论：无限的是体验路径、发现顺序、角色反应、次生事件和结局演绎；不是“案件事实随时可改写”。
- 主要来源轮次：`031`、`272-274`、`398`
- 次要来源轮次：`107-110`
- 覆盖历史：早期有“剧情根据言行变化”的宽泛提法，后期被事实锁定机制收紧。
- 备注：写文档时必须区分“事实不可变”和“叙事可涌现”。

### D007 司命的系统身份

- 议题：司命是什么
- 当前结论：司命是运行时核心智能体，拥有全局视野和更高权限，但不是上帝脚本，不直接控制玩家。
- 主要来源轮次：`040`、`212`
- 次要来源轮次：`082`、`089-093`、`266`、`400`
- 覆盖历史：早期的“AI叙事导演”提法在 `040` 被重构为“独立智能体”。
- 备注：所有司命文档都要强调“催化、修剪、守护”而不是“操控”。

### D008 司命的干预原则

- 议题：司命如何干预
- 当前结论：四原则冻结为：
  - 间接性
  - 不可见性
  - 逻辑自洽性
  - 公平性
- 主要来源轮次：`040`、`212`、`400`
- 次要来源轮次：`174`
- 覆盖历史：后期无推翻，仅补充更明确的执行规则。
- 备注：这是所有司命干预和审查逻辑的上位约束。

### D009 司命与角色智能体的协作关系

- 议题：司命是否控制角色
- 当前结论：司命只发送 `impulse`、`fact_reveal`、`opportunity` 等高层信息，角色是否执行由角色自身心智模型决定。
- 主要来源轮次：`040`、`212`、`213`
- 次要来源轮次：`221`、`266`
- 覆盖历史：修正了可能把司命写成中央控制器的倾向。
- 备注：写角色智能体文档时要重复这一点，避免职责打架。

### D010 角色智能体的核心定义

- 议题：角色智能体是什么
- 当前结论：角色智能体不是对话树，也不是传统行为树 NPC，而是拥有完整心智模型、独立人格、自主决策能力的虚拟角色驱动核心。
- 主要来源轮次：`024-026`、`046-050`、`213`
- 次要来源轮次：`216-229`、`261-263`
- 覆盖历史：早期是“NPC 也要活起来”，后期在 `213` 收敛为完整系统描述。
- 备注：Phase 1 就按完整单局版角色智能体写，不要退回“纯 prompt NPC”。

### D011 角色智能体的心智模型

- 议题：角色如何决策
- 当前结论：采用四层心智模型：
  - L1 感知
  - L2 理解
  - L3 规划
  - L4 执行
- 主要来源轮次：`046`、`213`
- 次要来源轮次：`215`、`227`
- 覆盖历史：无根本推翻，后期主要补完各层职责和触发频率。
- 备注：后续设计和实现应避免绕开 L2/L3 直接把 LLM 当黑盒回复器。

### D012 人格档案的生成逻辑

- 议题：人格参数如何来
- 当前结论：采用“基因种子 → 人生记忆 → 品格层 → 五维人格 → 决策系统”的单向推导，不直接手填扁平人格值作为起点。
- 主要来源轮次：`047-049`、`213`
- 次要来源轮次：`042`、`048`
- 覆盖历史：修正了“先给角色打五维分数”的简化倾向。
- 备注：角色模板和剧本模板都要支持这一生成顺序。

### D013 三重过滤器

- 议题：角色行为如何约束
- 当前结论：所有行为必须通过：
  - 人设过滤器
  - 逻辑过滤器
  - 得失过滤器
- 主要来源轮次：`213`
- 次要来源轮次：`026`、`049-050`
- 覆盖历史：前期分散讨论“符合人设”“符合逻辑”“符合利益”，后期在 `213` 合并成明确机制。
- 备注：这是防 OOC 的核心结构。

### D014 可感知信息编译层的技术路线

- 议题：AI 如何感知 3D 世界
- 当前结论：不走截图/多模态视觉主路，采用与人类同源计算的结构化语义事件流，由每角色独立感知过滤器按感官档案过滤。
- 主要来源轮次：`135-136`、`214-215`、`400`
- 次要来源轮次：`076`、`226`
- 覆盖历史：修正了“是否依赖视觉模型”的不稳定讨论，后期结论明显偏向结构化语义感知。
- 备注：这是成本、延迟、公平性的关键决策。

### D015 事件总线的职责

- 议题：事件总线做什么
- 当前结论：事件总线是 L1-L2-L3 的通信中枢，负责消息路由、优先级调度、广播/单播/组播、实时与可靠通道分流；它承载的是原始/结构化世界事件和高层系统消息，不直接承担业务状态判断，也不负责把同一语义结果等量下发给所有角色。
- 主要来源轮次：`214`、`260`
- 次要来源轮次：`215`、`287`、`302-304`、`352-353`
- 覆盖历史：无根本推翻，但后期对消息结构和优先级更明确。
- 备注：后续文档不要把“证据判定”“接触痕迹持久化”或“角色感知解释”写进事件总线职责。

### D016 知识模型

- 议题：公共知识、共有知识、高阶知识如何处理
- 当前结论：系统必须显式支持公共知识、共有知识和高阶知识，并把它们作为信息博弈底层模型，而不是仅作为叙述概念。
- 主要来源轮次：`038`、`212`
- 次要来源轮次：`233`
- 覆盖历史：无明显推翻，后期只是把它并入司命知识图谱与角色记忆。
- 备注：这决定了信息共享、偷听、伪装与知情人网络的统一表示。

### D017 ESM 的系统身份

- 议题：ESM 是什么
- 当前结论：ESM 是 L1 的独立环境状态管理器，负责毫秒级确定性物理计算和物体/环境状态机，不属于司命，也不依赖 LLM。
- 主要来源轮次：`302`、`303`
- 次要来源轮次：`286-291`、`308`
- 覆盖历史：修正了“环境交互大脑是否属于司命下属程序”的模糊说法。
- 备注：后续架构文档应明确“司命秒级叙事决策，ESM 毫秒级物理执行”。

### D018 ESM 与司命的边界

- 议题：司命和 ESM 谁负责什么
- 当前结论：司命负责高层催化和叙事判断，ESM 负责在物理规则允许范围内执行并回报状态变化；司命不能替代 ESM 做底层物理模拟。
- 主要来源轮次：`302-303`
- 次要来源轮次：`287`、`350`
- 覆盖历史：修正了“司命直接生成环境结果”的表述。
- 备注：这条边界必须进入[技术架构总纲](/d:/Projects/Paralls/docs/phase1/core/00-总纲/技术架构总纲.md)和世界状态文档。

### D019 证据链的职责拆分

- 议题：证据系统如何落位
- 当前结论：证据链不能全部压给事件总线或司命，应拆分为：
  - ESM：物体物理状态变化
  - 物品流转追踪器：物品归属与位置流转
  - 接触痕迹管理器：指纹/纤维/唾液等接触痕迹
  - 生物痕迹管理器：血迹/毛发/皮屑等生物痕迹
  - 司命事实核心：时间线矛盾与说法比对
- 主要来源轮次：`304-307`、`310`、`400`
- 次要来源轮次：`351-357`
- 覆盖历史：修正了前面“ESM 生成物证”或“事件总线负责痕迹”的混杂表达。
- 备注：第一轮整理建议把它们先合并写成“世界状态与证据链设计”。

### D020 玩法系统的分层

- 议题：哪些机制绑定侦探玩法，哪些是通用底座
- 当前结论：案件生成、线索、伪装、知情人网络、证据链、投票与结局等偏侦探绑定；智能体、司命、ESM、天气、空间音频、对话、事件总线等是全玩法通用底座。
- 主要来源轮次：`310`、`379`
- 次要来源轮次：`232-248`
- 覆盖历史：修正了前期容易把所有系统都默认服务于“追凶”的倾向。
- 备注：这是后续做目标中立系统设计的依据。

### D021 目标系统设计原则

- 议题：是否给所有角色公共目标
- 当前结论：不给所有人强制分配统一公共目标。允许“共同目标 + 个人目标”并存，且共同目标只对部分角色成立。
- 主要来源轮次：`372-379`
- 次要来源轮次：`363-371`
- 覆盖历史：这是对“追凶应作为所有人第一目标”的明确修正。
- 备注：玩法机制、角色分配和剧本模板都要按此写。

### D022 特殊人群分类的地位

- 议题：特殊人群体系如何落文档
- 当前结论：特殊人群与职业维度是目标/阵营设计的附属支撑，不应先独立升格为高优先级主文档。
- 主要来源轮次：`388-396`
- 次要来源轮次：`400`
- 覆盖历史：后期对“侦探/罪犯/特工”命名与分类方式进行了修正和收敛。
- 备注：第一轮作为[目标与任务系统设计](/d:/Projects/Paralls/docs/phase1/core/03-玩法与内容/目标与任务系统设计.md)的附录处理。

### D023 小世界是否进入 Phase 1

- 议题：Phase 1 要不要小世界
- 当前结论：要，但只做轻量版：基础场景、有限容量、基础对话、结局后带走与快照存储，不做完整持续运行和跨世界能力。
- 主要来源轮次：`208`、`398`、`400`
- 次要来源轮次：`311-341`
- 覆盖历史：这条结论直接覆盖了“三阶段原始分工里小世界偏后期”的倾向。
- 备注：Phase 1 文档中必须明确“小世界基础版”和“完整版小世界”边界。

### D024 带走机制的最小闭环

- 议题：AI陪伴如何在 Phase 1 验证
- 当前结论：Phase 1 只验证最小闭环：
  - 结局时邀请同行
  - 基于信任/好感阈值判断
  - 角色快照存储
  - 小世界中基础互动
- 主要来源轮次：`208`、`400`
- 次要来源轮次：`166-175`、`197-198`
- 覆盖历史：后期将完整版“坦白与契约”“跨剧本带入”后移到 Phase 2+。
- 备注：这是商业验证和情感验证的重要指标。

### D025 Phase 1 基础设施优先级

- 议题：先搭什么
- 当前结论：基础设施优先级冻结为：
  - 事件总线原型
  - Godot 场景原型
  - LLM 对话原型
  - WebSocket 打通
  - 再扩房间管理、规则引擎、完整玩法闭环
- 主要来源轮次：`380`
- 次要来源轮次：`398`
- 覆盖历史：后期明确反对“一开始先做未来大而全设施”。
- 备注：[Phase 0 启动方案](/d:/Projects/Paralls/docs/phase1/core/04-商业与阶段/Phase 0 启动方案.md) 必须据此拆任务。

### D026 技术栈方向

- 议题：当前主技术路线
- 当前结论：当前规划方向稳定为：
  - Godot 4.x
  - Python / FastAPI
  - WebSocket + NATS
  - PostgreSQL + Redis + MinIO
  - 本地小模型 + 云端大模型混合
- 主要来源轮次：`380`、`400`
- 次要来源轮次：`214`、`215`
- 覆盖历史：目前无后续修正迹象，但属于“技术方向已锁、具体产品版本可调整”类型。
- 备注：这是执行层结论，不应写成绝对不可变教条。

### D027 Phase 1 的非目标

- 议题：哪些内容不应进入 Phase 1
- 当前结论：Phase 1 不承担：
  - 完整跨局叙事
  - 完整资产化
  - 持续运行世界
  - 对外创作者工具
  - 大玩家完整经营
  - 完整区块链与商业系统
- 主要来源轮次：`398`、`400`
- 次要来源轮次：`203`
- 覆盖历史：主要是把先前愿景层讨论从 Phase 1 中剥离出去。
- 备注：所有项目计划文档都应单列“不在范围内”。

### D028 玩法中立化

- 议题：系统是否只服务追凶
- 当前结论：Phase 1 虽以侦探推理为首个闭环，但核心系统必须目标中立，为追凶、逃脱、生存、复仇等多目标提供支撑。
- 主要来源轮次：`310`、`379`、`400`
- 次要来源轮次：`363-387`
- 覆盖历史：这条结论修正了“当前设计只能支撑追凶”的局限。
- 备注：后续玩法文档不要把“搜证”只写成“找真凶服务”。

### D029 角色选择机制

- 议题：玩家如何选角色
- 当前结论：角色分配应兼顾选择权与知情权保护，倾向采用“意向志愿系统”，只暴露公开人格侧写，不暴露真实身份、秘密和完整目标。
- 主要来源轮次：`224-225`、`400`
- 次要来源轮次：`216-217`
- 覆盖历史：后期作为新增议题正式进入更新版计划。
- 备注：这条会影响大厅、匹配、剧本模板和 UI 设计。

### D030 整理工作的方法论

- 议题：怎么整理这些对话
- 当前结论：整理时必须先建“决策索引层”，再写核心文档，不能直接把 405 组对话平铺改写成 20 份长文。
- 主要来源轮次：`201-202`
- 次要来源轮次：当前整理方案与本目录文件
- 覆盖历史：无

### D031 事件总线的消息分层

### D053 挂机自主模式

- 议题：玩家短暂挂机时角色该如何表现
- 当前结论：挂机不是故障，而是角色短暂切换到保守自主模式；当玩家长时间未操作时，系统接管 L3 规划层，让角色继续以人设驱动的方式存在，但禁止执行暗杀、主动推进关键对话、展示关键证据和其他不可逆高风险动作；玩家回归后会收到挂机简报并无缝接回控制。
- 主要来源轮次：`222`、`223`
- 次要来源轮次：`227`
- 覆盖历史：修正了传统在线游戏里“挂机=角色僵住或退场”的旧理解。
- 备注：这一能力是《开本》连续叙事和陪伴体验成立的基础，必须作为 Phase 1 默认能力之一。

### D054 玩家角色的混合驱动边界

- 议题：玩家角色到底是“完整智能体”还是“玩家大脑 + 系统补全”的混合体
- 当前结论：玩家角色不是纯系统智能体；玩家自己的大脑在真实世界里完成感知、理解、推理、决策与主动操作，系统只负责补全角色无法直接控制的生理、本能和潜意识层面。更准确的说法是：剧中角色 = 玩家大脑驱动的意志投射 + 系统自动补全层。
- 主要来源轮次：`216`、`226`、`227`
- 次要来源轮次：`218`、`219`、`220`、`222`、`223`
- 覆盖历史：修正了把玩家角色与 AI 角色完全对称化的中间表述。

### D055 核心目标的八目标收束

### D056 共同目标的适用范围

### D057 衍生复合目标的归并规则

- 当前结论：“偷盗并全身而退”不是新的核心目标，而是既有目标的组合型用法：偷盗阶段更接近独吞/资源获取，全身而退则落到嫁祸或逃脱（空间）；现有系统已经能支撑其主要博弈链条，但若要更完整地表达，需要补充物品价值、盗窃技能、赃物藏匿等细项。

- 次要来源轮次：`381`、`385`、`386`

### D058 平台的双重商业身份

### D059 Phase 1 的商业验证边界

### D060 玩家档案的公开 / 真实双层结构

- 议题：玩家在单局中的身份档案应如何组织
- 当前结论：玩家角色采用至少双层档案结构：公开档案用于对外展示姓名、身份、背景、与死者关系、案发时行踪等可暴露信息；真实档案仅自己可见，包含完整身份、核心秘密、真实不在场证明、伪装相关信息与关键能力。必要时可由系统再生成建议伪装档案作为扮演辅助。

### D061 玩家信息面板的当前稳定口径

### D062 信息减速带的系统定位

- 议题：面对高密度信息博弈，系统是否需要主动为玩家减压
- 当前结论：需要。信息减速带是稳定玩法支撑的一部分，而不是可有可无的提示层。当前稳定机制至少包括动态线索摘要、冲突高亮、基于已知信息的嫌疑度可视化、叙事化提示与可选推理快照，用于降低认知负荷并维持人类玩家参与度。
- 主要来源轮次：`233`
- 次要来源轮次：`220`、`398`
- 覆盖历史：修正了“信息过载就让玩家自己适应”的隐含前提。

### D063 凝神能力的 Phase 1 定位

- 议题：凝神能力是否属于当前 Phase 1 的正式能力
- 当前结论：属于，但有严格边界。凝神是单人 / AI 模式专属的高维观察能力，允许暂停时间、360 度环顾、凝视获取线索、拍照和翻阅笔记，但不能移动、不能交互、不能推进逻辑判定，因此它是辅助观察和整理工具，不是破坏博弈公平的超能力。

- 次要来源轮次：`398`
- 覆盖历史：修正了把凝神写成通用模式超能力或纯概念性体验点的摇摆表述。
- 备注：后续文档提及凝神时，必须一起写明“只限单人 / AI 模式”和“不能推进关键逻辑”。

### D064 匹配模式的当前冻结范围

- 议题：Phase 1 客户端应支持哪些匹配模式
- 当前结论：多种匹配模式已经进入当前稳定范围。至少包括纯真人、纯 AI、AI 优先、真人优先、混合、携友、携 AI、混合带 AI 等模式；其本质不是运营花样，而是保证不同玩家偏好和 AI 兜底能力在同一产品中共存。

- 次要来源轮次：`204`、`206`、`209`

### D065 强制变声器与可选文字润色

- 议题：沉浸式设置里哪些是强制、哪些是可选
- 当前结论：当前稳定口径是“强制变声器 + 可选文字润色”。变声器不可关闭，按角色档案自动配置，用于保护角色身份与沉浸感；文字润色可关闭，只是把玩家输入润色为更符合角色语言风格的表达。
- 主要来源轮次：`200`、`217`、`398`
- 次要来源轮次：`218-220`

### D066 信息默认私有与主动共享原则

- 议题：角色获得信息后，系统是否应默认自动广播
- 当前结论：不应。当前稳定规则是“信息默认私有，共享必须是主动行为”。玩家和智能体发现的线索、秘密和判断默认只归自己掌握；只有通过游戏内可验证的共享动作才会扩散。共享本身带有暴露身份、意图和位置的风险；智能体可基于人设拒绝分享，玩家也可选择隐瞒。
- 主要来源轮次：`037`
- 次要来源轮次：`204`、`207`、`217`、`398`
- 覆盖历史：修正了前期把“发现线索后系统自然扩散给相关方”的隐含简化理解，后期稳定为更严格的信息主权规则。
- 备注：`D046` 负责冻结“怎么共享”，本条负责冻结“为什么不自动共享”，两者必须一起使用。

### D067 带走机制的完整口径与 Phase 1 收缩版

- 议题：智能体带走机制最终应该按怎样的流程与阶段边界来写
- 当前结论：完整口径已经冻结为“双向叙事仪式”，流程为：玩家 / 旅人主动邀请 → 司命判断关系状态 → 人格过滤器决策 → 角色自然表达 → 坦白与契约。与此同时，Phase 1 只交付轻量版闭环：结局阶段触发“邀请同行”、信任值 / 好感度阈值判定、角色快照存储和简短告别叙事；完整“坦白与契约”仪式与更强跨世界语义后移。
- 主要来源轮次：`172-175`、`202`、`398`、`400`
- 次要来源轮次：`208-209`、`217`、`224`、`231`、`403`
- 覆盖历史：先修正了“点击按钮购买智能体”的商品化旧方案，再在后期进一步收束出“完整仪式保留、Phase 1 先交轻量版”的阶段化口径。
- 备注：后续文档既不能把带走重新写回成购买按钮，也不能误把完整版仪式提前塞进 Phase 1。

### D068 Phase 1 小世界的基础能力包

- 议题：Phase 1 的小世界到底最少要包含什么
- 当前结论：Phase 1 小世界只冻结为情感闭环所需的基础能力包：一个基础 3D 场景模板、带回智能体的基础对话互动、角色快照承载，以及作为“带回去之后还能见面”的容器身份。它不是完整生活模拟器，也不在当前阶段冻结多同伴共存、小镇生态、节日系统和场景化商店。
- 主要来源轮次：`208`、`398`、`400`
- 次要来源轮次：`311-341`、`403`
- 覆盖历史：前中期大量关于“小世界像家一样长期活着”的丰满设想，在后期被明确收束为支撑情感价值验证的基础容器。
- 备注：后续文档写 Phase 1 小世界时，应优先强调“情感承接容器”，而不是“第二人生空间”。

### D069 离线时间线补全的当前输出形式

- 议题：玩家下线后，小世界和同伴状态在 Phase 1 中应如何被补全
- 当前结论：Phase 1 采用“登录时关键事件补全 + 简报输出”的轻量方案。司命在玩家回到小世界时瞬间补全离线期间的关键变化，并以简报方式向玩家交代发生了什么，以制造“世界仍在继续”的感受；但它不等同于持续运行的离线模拟，不执行完整世界快进、完整居民生活推演或复杂多线程关系演化。
- 主要来源轮次：`398`、`400`
- 次要来源轮次：`340`、`403`
- 覆盖历史：修正了从“离线时完整持续运行小世界”到“低算力补全式活感”的后期范围收缩。
- 备注：这条与 `D045`、`D068` 共同限定了 Phase 1 小世界的真实规模。

### D070 三种知识形态的判定边界

- 议题：公共知识、共有知识和高阶知识到底如何区分
- 当前结论：三种知识形态必须严格区分。公共知识指某信息已在公开场景被展示或宣告，在场相关角色不仅都知道该信息，也知道彼此都知道；共有知识指某个局部群体通过私下共享完成同步，但外部角色并不知道这次同步已经发生；高阶知识则是“关于别人知道什么”的知识结构，包括确认、怀疑、以及“我知道你知道 / 我知道你不知道 / 我不确定你知道多少”这类层级关系。
- 主要来源轮次：`038`
- 次要来源轮次：`212`、`217`、`309`、`398`
- 覆盖历史：修正了把三者混写成“信息共享后大家都知道了”的平面化表达，后期明确需要把知识层级本身当成博弈对象。
- 备注：后续提到知识图谱时，不能只写“谁知道线索”，还要写“谁知道别人知道多少”。

### D071 证据可视化的触发与传播边界

- 议题：证据图片 / 特写是否对所有证据自动生成，以及生成结果如何传播
- 当前结论：证据可视化只服务“视觉可见的证据”，且必须由玩家主动触发。适合生成图片的是物体状态变化、物品外观细节、宏观生物痕迹和满足条件的微观接触痕迹；不适合直接图像化的是时间线矛盾、人证陈述和动机判断等逻辑结果。触发方式应限定为观察、凝神深度观察、拍摄、公开展示和私下分享；生成结果应绑定到笔记面板的对应证据条目，且传播范围严格遵守信息共享规则。
- 主要来源轮次：`309`
- 次要来源轮次：`310`、`398`
- 覆盖历史：修正了“所有重要信息都自动生成图片”或“证据图像只是纯表现层装饰”的两种失真理解。
- 备注：后续视觉增强文档应把证据可视化写成“玩家主动保全和传播视觉证据的链路”，而不是单独的炫技渲染功能。

### D072 首个剧本的结构化交付骨架

- 主要来源轮次：`271`、`275`
- 次要来源轮次：`268`、`270`、`398`、`400`
- 覆盖历史：修正了把首个剧本仅理解为“剧情文本 + 角色设定稿”的早期整理方式，转而收束为面向系统落地的结构化包。
- 备注：后续案例文档可以展开内容，但真正进入开发链路时仍应回到结构化包字段。

### D073 带回角色快照的存档边界

- 议题：Phase 1 带走后到底保存角色的哪些数据
- 当前结论：Phase 1 只保存“轻量快照”，用于支撑小世界中的基础对话和情感延续。当前冻结的快照边界至少包括：人格参数摘要、本局关键记忆摘要、与玩家的最终关系数据，以及必要的结局 / 存活状态标记；不保存完整长期记忆、跨剧本可执行能力、私房钱系统、独立经济行为或完整自主生活模拟。
- 主要来源轮次：`208`、`398`
- 次要来源轮次：`224`、`400`
- 覆盖历史：修正了从“带回后几乎完整继承全部智能体能力”到“先只保留情感连续性所需快照”的阶段收缩。
- 备注：这条与 `D067`、`D068` 一起构成 Phase 1 AI 陪伴闭环的数据边界。

### D074 四层心智模型的职责边界

- 议题：L1-L4 四层心智模型各层到底负责什么
- 当前结论：四层边界必须清晰冻结。`L1` 只负责接收并过滤结构化感知输入，不做推理；`L2` 负责解释感知、更新信念、生成推论与不确定态、更新情绪/压力/信任/怀疑等状态；`L3` 负责根据恐惧、目标、社交、好奇四类动机生成候选行动并经三重过滤器排序；`L4` 负责把选中的方案变成具体对话、动作和表现层输出。后续实现不能跳过 `L2/L3` 把大模型当“直接说一句话”的黑盒。
- 主要来源轮次：`046`、`213`
- 次要来源轮次：`039`、`048`、`069`、`105`、`204`、`221`、`227`、`263`、`276`、`304`、`310`、`353`、`403`
- 覆盖历史：前期更多是概念骨架；到 `105/204` 开始以工程模块方式落入开发清单，`276/304/353` 又把运行时循环、L2 解释职责和精确事件链补实。当前结论修正了“只是概念分层、实现仍可塌缩成感知后直接回复”的倾向。
- 备注：这是角色智能体工程实现、调试和测试拆分的基础边界。

### D075 玩家接管点与系统自动补全边界

- 议题：当角色由玩家扮演时，到底接管哪些层，哪些仍由系统运行
- 当前结论：玩家不接管整套智能体，只接管高层主动决策与主动执行。当前稳定口径是：`L1` 底层感知仍自动运行，但玩家同时通过 3D 画面与空间音频进行真实感知；`L2` 底层理解仍自动运行，用于生成内心独白、推论提示和状态更新，但玩家大脑独立完成自己的推理；`L3` 的方向盘主要交给玩家；`L4` 中主动行为由玩家操作，而微表情、小动作、社交距离、语音微表现等自动行为继续由系统补全。
- 主要来源轮次：`221`、`224-227`
- 次要来源轮次：`068-069`、`101`、`217`、`263`、`269`、`320`、`403`
- 覆盖历史：`068` 曾短暂走向“人类玩家和智能体分开配置”，`069` 先行修正为同权角色档案，`224-227` 再把旅人 / 玩家 / 剧中角色 / 自动补全层拆清，`320` 在后期陪伴场景里进一步强调“替身层必须对玩家透明”。当前结论同时修正了“玩家角色就是纯手动壳子”和“玩家角色是纯系统智能体”两端误差。
- 备注：这条是玩家角色、UI、输入系统与角色层 API 对接的根规则。

### D076 深层沉浸机制的角色层驱动源

- 议题：微表情、小动作、社交距离、内心独白这些深层沉浸机制究竟由谁驱动
- 当前结论：这些机制主要由角色智能体自身驱动，而不是由司命直接驱动。更准确地说：`L2` 负责产出推论、情绪、压力、信任/怀疑等内部状态；`L4` 负责把这些内部状态映射成微表情、小动作、站位、语音微表现等可观察输出；司命只在“冲动”注入这一类叙事催化中直接参与。
- 主要来源轮次：`219`、`221`、`227`
- 次要来源轮次：`223`、`226`、`258`、`314`、`320`、`346`
- 覆盖历史：中前期只是把这些能力当作“沉浸效果”描述；`221/227` 才把它们收回到角色层的 `L2→L4` 链路，`314/346` 又在第一视角和环境变化示例中反复说明它们由心智状态驱动，而非司命直接导演或纯前端特效。
- 备注：后续客户端、动画、语音和角色系统文档都应以“角色层状态驱动表现层”来组织。

### D077 Phase 1 角色层已前置的深层能力

- 议题：哪些原本看起来偏高级的角色层能力，其实已经进入 Phase 1
- 当前结论：Phase 1 角色层不仅有完整单局心智模型，还已前置多项深层能力：微表情、小动作、社交距离自动调节、内心独白提示、决策建议、挂机自主模式，以及玩家角色统一底层下的自动补全层。它们不是未来版装饰，而是当前核心体验的一部分；真正后移的是跨剧本长期记忆、完整资产化、跨世界压制和群体模拟。
- 主要来源轮次：`217`、`221-223`、`227`、`398`
- 次要来源轮次：`204`、`235`、`258`、`263`、`310`、`314`、`400`
- 覆盖历史：`204` 的应用清单和 `217/221-223/227` 的玩家侧讨论已经把这些能力提前写入当前产品结构；`263` 曾回压出偏窄的第一阶段切分，但后期 `398/400` 又明确恢复为 Phase 1 当前体验承诺。
- 备注：Phase 1 计划文档和角色实现边界都应继续保持这一口径，不要再把这些能力降成“可选增强”。

### D078 单局记忆五分类与用途边界

- 议题：角色记忆在当前版本里是否需要明确分池
- 当前结论：需要。当前稳定口径是单局内至少维护五类记忆：事件记忆记录亲历事件；观察记忆记录看到/听到的他人言行；知识记忆记录线索、证据和情报及其知识状态；社交记忆记录对每个对象的信任、怀疑和好感变化；高阶记忆记录“谁知道什么”的层级关系。它们不是一个混合文本池，因为检索、推理、共享和结局快照抽取依赖不同用途。
- 主要来源轮次：`045`、`228`
- 次要来源轮次：`046`、`076`、`213`、`263`、`304`、`307`、`398`、`403`
- 覆盖历史：五分类并不是后期才新增的复杂化设计，`045` 已给出直接前身，后续在 `228` 才被重新系统化命名；当前结论修正了把角色记忆简化成统一对话历史、统一向量池或仅服务对话的扁平化理解。
- 备注：Phase 1 结局后只从这些单局记忆中抽取轻量快照，不保留完整长期记忆。

### D079 感知链路的阶段化与本能反应边界

- 议题：角色到底在什么时机感知事件，是否只能在动作完成后反应
- 当前结论：不能只在完成后反应。当前稳定链路是“结构化语义事件 → 感知过滤器 → 阶段化感知 → 心智更新 / 本能反应”。阶段化感知至少区分意图阶段、执行阶段、完成阶段；角色在意图阶段即可收到威胁信号并触发反应。对致命级威胁，当前采用规则引擎直通的本能反应路径，目标延迟应保持在 `300ms` 量级内。
- 主要来源轮次：`202`、`352-353`
- 次要来源轮次：`076-077`、`101-106`、`214-215`、`263`、`276`、`302`、`346`、`350`、`398`、`403`
- 覆盖历史：`202` 首次明确淘汰截图与全知推送，`352-353` 则把意图 / 执行 / 完成的精确事件链和 Per-Character 感知分发补到工程级。当前结论修正了把感知主路写成“截图后识别”或“动作完成后再统一结算”的旧式理解。
- 备注：这条直接影响感知服务、威胁判定和暗杀 / 反应手感。

### D080 三重过滤器的执行顺序与否决链

- 议题：三重过滤器只是概念说明，还是有明确执行顺序与否决权
- 当前结论：有明确顺序与否决链。当前采用“人设过滤器 → 逻辑过滤器 → 得失过滤器”的顺序；任一层否决，当前候选行动即被丢弃。它不仅约束 AI 角色自主行为，也约束司命冲动被角色吸收后的响应、挂机接管期间系统生成的行为，以及系统提供给玩家的候选建议排序。玩家的直接主动操作不被它硬拦截，但系统代打与系统建议必须服从它。
- 主要来源轮次：`026`、`221`、`228`
- 次要来源轮次：`050`、`076`、`173`、`175`、`202`、`222`
- 覆盖历史：前期过滤器更像人格约束原则，后续在 `076/221/228` 逐步扩展到实时行为、挂机代打和叙事催化响应。当前结论修正了把过滤器仅写成“人格 prompt 前置语”或只作用于对话文本的过窄实现。
- 备注：后续若出现“司命发了冲动所以角色必须执行”的写法，应视为与本条冲突。

### D081 内心独白、冲动与决策建议的来源拆分

- 议题：玩家看到的内心层提示是否都属于同一种系统输出
- 当前结论：不是。当前应严格拆成三类：内心独白来自 `L2` 的推论、情绪与信念更新；冲动来自司命注入后经角色层承接的模糊倾向；决策建议来自 `L3` 对候选行动的排序结果。这三类输出都默认仅玩家自己可见，且都不是强制指令，玩家可以关注、忽略或反向操作。
- 主要来源轮次：`220`、`221`、`226`、`227`
- 次要来源轮次：`217`、`219`、`223`、`320`
- 覆盖历史：中前期只是在玩家侧堆叠“提示”“内心戏”“沉浸辅助”，`221/226/227` 才把来源拆回 `L2`、司命注入和 `L3` 三类；`320` 又从体验侧强调这些补全层必须对玩家透明，而不是让玩家感觉在操作另一个人。
- 备注：后续客户端和角色层接口应分别暴露三类来源，而不是只做一个“提示流”。

### D082 挂机自主模式的保守行为边界

- 议题：玩家挂机后，角色智能体接管到什么程度
- 当前结论：挂机不是停机，而是保守接管。当前稳定口径是：当玩家持续未操作达到阈值后，`L1/L2/L4` 持续运行，`L3` 的方向盘临时交还系统。允许的行为包括基础移动、观察环境、简短被动回应和保守自保；不允许的行为包括主动推进关键对话、主动展示或使用关键物品、暗杀及其他不可逆高风险行为。玩家回归后，应立即交还控制权，并生成挂机期间简报，同时把这段经历同步写入记忆系统。
- 主要来源轮次：`222`、`223`
- 次要来源轮次：`227`、`258`、`398`
- 覆盖历史：修正了“挂机等于角色木住”以及“挂机也能自动替玩家通关”这两种极端理解；后期回顾型轮次也持续把“挂机不掉线但不代替玩家做重大决定”作为玩家体验的一部分复述。
- 备注：这是角色自主性与玩家主权之间的保守保险丝。

### D083 角色智能体与事件总线的消息边界

- 议题：角色智能体到底从事件总线接收什么
- 当前结论：角色智能体默认不直接消费“全局原始世界事件流”。当前稳定链路是：L1/ESM/交互系统先上抛精确世界事件，可感知信息编译层先生成候选感知事件，再由 Per-Character 感知过滤器按视觉、听觉、嗅觉、热感、遮挡、距离、状态等条件做角色私有裁剪，最后送入角色智能体的 `L1` 感知层。
- 主要来源轮次：`214-215`、`353`
- 次要来源轮次：`202`、`260`、`287`、`302-304`、`352`
- 覆盖历史：修正了早中期容易把“广播”理解成“所有角色收到同一份事件内容”的粗粒度理解。
- 备注：写实现与文档时，必须区分“世界事件总线”与“角色感知入口”；后者不是可选优化件，而是角色消息边界的一部分。

### D084 司命接收原始事件与角色接收过滤后感知事件的分层

- 议题：司命和角色智能体是否接收同一种消息
- 当前结论：不是。司命拥有更广的全局事实视角，接收原始/结构化世界事件、环境状态变化和跨系统通知，用于事实核心、知识传播评估与叙事催化；角色智能体只接收经过感知过滤后的“我此刻看到/听到/闻到/感觉到什么”。两者不能混为同一订阅面。
- 主要来源轮次：`287`、`302-304`、`353`
- 次要来源轮次：`213-215`、`260`、`352`
- 覆盖历史：后期明确压实了“司命知道一切”与“角色只知道自己可感知部分”的差异，覆盖了较早期对广播范围的含混表达。
- 备注：这条分层是信息不对称、公平性和知识博弈成立的基础。

### D085 司命回写角色的消息边界

- 议题：司命可通过事件总线向角色下发什么
- 当前结论：司命回写给角色的只能是高层消息，如 `impulse`、`fact_reveal`、`opportunity` 一类模糊催化与事实揭示；司命不能借总线直接下发“去做动作 X”这种低层控制指令，更不能绕过三重过滤器或 `L2/L3` 直接改写角色行为。
- 主要来源轮次：`213`、`287`、`303`、`353`
- 次要来源轮次：`040`、`212`、`221`、`227`
- 覆盖历史：覆盖了中期版本中把司命写得过强、近似中央控制器的表达倾向。
- 备注：这是“司命只催化不控制”在消息接口层的具体落点。

### D086 司命的“实时编剧”是产品隐喻，不是无限改写权

- 议题：司命被称为“活着的实时编剧 / 导演”时，是否意味着它可以无限制改写世界
- 当前结论：不是。当前应保留“活着的实时编剧 / 导演”作为产品隐喻与愿景表达，但在系统实现上必须明确收束为：司命实时编排的是揭示顺序、冲突机会、节奏控制与次生事件，不是 `T2` 后对既定真相、底层物理结果或角色自主性的无限改写权。
- 主要来源轮次：`107-109`、`130`
- 次要来源轮次：`213`、`287`、`302-304`、`353`、`398-400`
- 覆盖历史：`107-109/130` 阶段曾出现“世界主宰”“实时写控制脚本”等过强措辞；后续边界轮次把这些愿景语言收束回“催化而非控制、编排而非重写真相”的可执行口径。
- 备注：后续文档若引用“实时编剧”表述，必须同时补上事实锁定、角色自主和 `ESM` 边界。

### D087 司命与 ESM 的职责边界

- 议题：司命是否负责环境物理模拟与状态执行
- 当前结论：不负责。`ESM` 是独立的 `L1` 环境状态管理器，负责毫秒级确定性物理规则、环境状态机与执行结果；司命负责解释这些结果的叙事意义、评估其是否构成冲突机会，并决定是否做进一步催化。司命不能跳过 `ESM` 直接写出违反物理规则的环境结果。
- 主要来源轮次：`302-303`
- 次要来源轮次：`287`、`304`、`353`、`400`
- 覆盖历史：覆盖了“环境交互大脑是否属于司命下属程序”以及“司命直接生成环境结果”的中期含混表述。
- 备注：后续凡写到火势、门锁、痕迹、尸体状态、物体破坏等结果，必须先落回 `ESM` 或相关确定性子系统。

### D088 司命的离线补全边界

- 议题：玩家离线后，司命是否需要持续后台运行以维持小世界“活着”
- 当前结论：Phase 1 不采用司命持续后台常驻运行。当前稳定口径是：玩家离线时司命也下线；玩家重新进入小世界时，由司命快速补齐离线期间的关键事件并生成简报，以制造“世界仍在继续”的感受，但不进行完整持续推演。
- 主要来源轮次：`341`、`398`、`400`
- 次要来源轮次：`340`、`403`
- 覆盖历史：`340` 曾提出“司命持续运行以维持活感”的倾向，`341` 随即修正为“离线期也下线，登录时补全关键事件”；后期 Phase 1 计划继续沿用这一收缩版。
- 备注：这条必须与小世界、AI陪伴和 Phase 1 范围文档保持一致，不得再把完整后台永续推演写回当前阶段。

### D089 ESM 管理的是“所有可交互实体的物理状态”

- 议题：ESM 只管环境，还是也管物体
- 当前结论：`ESM` 管的是“所有可交互实体的物理状态”，环境和物体只是尺度不同的实体类型。它既管理独立物体的燃烧 / 潮湿 / 破碎 / 开关 / 锁定等状态，也管理区域环境参数、天气状态和结构边界；但它不管理物品归属、接触痕迹、生物痕迹和推理意义。
- 主要来源轮次：`302`、`308`
- 次要来源轮次：`286-291`、`303-304`
- 覆盖历史：修正了“ESM 只管环境、不管物体”或反过来“ESM 包掉所有证据与归属逻辑”的两端误解。
- 备注：后续文档写 ESM 时，必须使用“可交互实体的物理状态”这一口径，而不是只写成“环境系统”。

### D090 ESM 的系统蓝图与 Phase 1 实现范围要分开写

- 议题：`302` 中完整 ESM 蓝图是否等于 Phase 1 全量交付
- 当前结论：不是。`302-308` 冻结的是 ESM 的系统最终职责版图，包括材质规则、状态机、天气、全局参数和更完整的环境联动；但阶段范围以后期计划为准。当前稳定口径是：Phase 1 只做“基础交互”级 ESM，用于支撑关键物体状态变化、基础燃烧 / 潮湿 / 破坏、基础环境参数和叙事所需的最小物理闭环；完整物理规则、天气完整版、生物成长等后移。

### D130 司命高阶知识图谱先冻结“会话与知识可见性”最小模型

- 议题：司命高阶知识图谱是否现在就需要设计成完整世界级知识图
- 当前结论：不需要。当前应先冻结 `v0.1` 最小模型，只覆盖“会话与知识可见性”闭环：谁进入了会话面、谁知道谁在场、谁知道别人知道自己在场、谁是偷听者/候选成员/沉默成员/主动成员/被排斥者、某角色从何时开始真正接入这场会话、某条信息是通过公开对话/局部对话/私密对话/偷听/显式分享/推断获得。完整世界级知识图谱、跨局继承、持续世界长期关系图和完整图数据库结构后置。
- 主要来源轮次：当前线程 `2026-05-28`
- 次要来源轮次：`212-213`、`217`、`233`、`235`、`352-353`、`398-400`
- 覆盖历史：补足了既有“司命有高阶知识图谱子系统”的稳定口径，把其当前冻结范围从抽象能力收紧为可执行最小模型，避免在会话语义尚未稳定前直接膨胀为完整世界图。
- 备注：后续任何高阶知识图谱扩展，都应先证明不破坏 `L1` 事实来源边界、事件总线传输边界和角色本地状态边界。

### D131 司命高阶知识图谱 v0.1 必须按固定顺序输出接入、知晓、成员资格与知识状态

- 议题：会话相关高阶知识判断的最小运行顺序是什么
- 当前结论：当前应采用固定判断顺序：先做接入判定，再做互相知晓判定，再做成员资格判定，最后做知识状态判定。高阶知识图谱至少应对外产出 `MembershipResolution`、`AccessResolution`、`KnowledgeResolution` 三类最小结果，并可逐步扩展到 `AwarenessResolution`、`PrivacyRiskResolution` 与 `ConversationBoundaryChange`。不得颠倒成“先判成员资格，再判是否接入”或“先给知识状态，再判是否真正听到”。
- 主要来源轮次：当前线程 `2026-05-28`
- 次要来源轮次：`214-215`、`233`、`302-304`、`352-353`、`398-400`
- 覆盖历史：补足了会话机制与高阶知识图谱之间此前只有边界、没有执行顺序的空白。
- 备注：后续若要写数据结构、API 或图数据库 schema，必须先保持这条判断顺序，再讨论具体存储与计算优化。

### D132 人格档案需先冻结会话相关长期参数的最小集

- 议题：人格档案中哪些长期参数必须先为会话、偷听、隐私和加入机制预留
- 当前结论：当前应先冻结一组 `Phase 1` 最小会话相关人格参数，用于支撑会话感知、加入与隐私机制的个体差异：`base_hearing_sensitivity`、`speech_discrimination_under_noise`、`whisper_capture_ability`、`social_openness`、`privacy_sensitivity`、`stranger_join_tolerance`、`talk_initiative`、`public_speaking_comfort`、`deception_control`、`anti_eavesdrop_habit`、`pressure_escape_bias`、`trust_threshold_for_private_talk`。这些参数只提供长期倾向和能力差异，不记录任何当前会话运行态。
- 主要来源轮次：当前线程 `2026-05-29`
- 次要来源轮次：`046-050`、`213`、`221`、`224-227`、`352-353`、`398-400`
- 覆盖历史：补足了既有人格形成链已冻结、但尚未显式抽出“会话相关长期参数”的空白。
- 备注：后续人格档案设计必须持续区分“长期人格参数”和“当前会话运行态”，不得把 `heard_from_ts`、当前成员态、当前隐私压力等短时状态写回档案；字段级解释见[角色智能体设计文档](/d:/Projects/Paralls/docs/phase1/core/01-运行时核心/角色智能体设计文档.md)中 `3.6.1`。

### D133 角色会话运行态字段需单独字段化并保持本地持有

- 议题：会话参与状态子模块是否只需概念描述，还是要先冻结最小字段表
- 当前结论：需要先冻结最小字段表。当前建议至少包括：`primary_conversation_id`、`conversation_role_state`、`heard_from_ts`、`member_from_ts`、`knowledge_confirm_level`、`privacy_pressure`、`exposure_risk`、`exclusion_signal_state`、`join_path`、`speech_entitlement`、`attention_focus_in_conversation`、`active_conversation_refs`。这些字段属于角色本地运行态，由角色本地状态或司命确认结果写入，不属于事件总线公共信封，也不应直接下放为全局知识真值。
- 主要来源轮次：当前线程 `2026-05-29`
- 次要来源轮次：`213`、`221`、`224-227`、`352-353`、`398-400`

- 备注：字段级解释见[角色智能体设计文档](/d:/Projects/Paralls/docs/phase1/core/01-运行时核心/角色智能体设计文档.md)中 `7.2.1`；后续 schema 设计必须保持“本地运行态持有”和“司命确认结果驱动”的双层边界。

### D134 会话确认事件至少拆成 MembershipResolution / AccessResolution / KnowledgeResolution 三类

- 议题：会话相关确认结果是否可以折叠成一个统一事件
- 当前结论：不建议折叠。当前应至少拆成三类确认事件：`MembershipResolution` 负责回答“角色在这场会话里的社会身份是什么”，`AccessResolution` 负责回答“角色从何时开始真正接入、接入了多少”，`KnowledgeResolution` 负责回答“角色现在到底知道了什么”。三者都继承事件总线公共信封，但只冻结 `payload` 语义，不冻结最终编码格式。
- 主要来源轮次：当前线程 `2026-05-29`
- 次要来源轮次：`214-215`、`233`、`260`、`302-304`、`352-353`、`398-400`
- 覆盖历史：补足了 `D128` 只有字段分层、`D131` 只有判断顺序，但尚未把确认结果正式拆成事件家族的空白。
- 备注：后续协议设计必须保持“接入 -> 成员资格 -> 知识状态”的依赖关系，不得以传输合包为理由把语义边界压平。

### D135 会话确认事件完整集为六件套，但当前 core 先冻结前三类

- 议题：会话确认事件是否应一次性全部进入 core 主文档
- 当前结论：完整语义集已经扩展为六件套：`MembershipResolution`、`AccessResolution`、`KnowledgeResolution`、`AwarenessResolution`、`PrivacyRiskResolution`、`ConversationBoundaryChange`。其中前三类构成最小闭环，后三类构成支撑与修正上下文。当前 core 主文档先冻结前三类，后三类保留在独立 schema 草案中，待整体审视稳定后再决定是否整体回填。
- 主要来源轮次：当前线程 `2026-05-29`
- 次要来源轮次：`212-213`、`214-215`、`233`、`260`、`302-304`、`352-353`、`398-400`
- 覆盖历史：补足了 `D134` 只处理三件套、尚未显式说明完整六件套边界和当前回填策略的空白。
- 备注：后三类进入 core 之前，必须保持两条 refinement：`AwarenessResolution` 能表达二阶知晓目标，`PrivacyRiskResolution` 只表示图谱侧风险判断而不等于角色本地主观压力。
