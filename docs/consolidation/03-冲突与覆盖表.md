# 03-冲突与覆盖表

## 说明

本表记录前后版本存在冲突、被覆盖或需特别注意的议题。

字段说明：

- `旧说法轮次`
- `新说法轮次`
- `当前采用`
- `采用原因`

---

## 冲突条目

### C001 产品边界

- 冲突议题：开本是“剧本杀项目”还是“平台”
- 旧说法轮次：`018-029`
- 新说法轮次：`203`、`379`、`400`
- 当前采用：平台级定义，动态剧本杀是 Phase 1 首个产品形态
- 采用原因：后期多次稳定复述，且与三阶段路线一致

### C002 案件事实何时锁定

- 冲突议题：案件真相在创作阶段是否已完全固定
- 旧说法轮次：`030` 之前的含混表述
- 新说法轮次：`031`
- 当前采用：T0-T3 分阶段锁定，T2 锁本局完整事实
- 采用原因：用户在 `031` 中明确修正，后续多次沿用

### C003 司命的本体

- 冲突议题：司命是中央控制系统还是独立智能体
- 旧说法轮次：`024` 等早期“导演系统”泛称
- 新说法轮次：`040`、`212`
- 当前采用：独立核心智能体
- 采用原因：与“智能体自主决策”理念一致，后期未被推翻

### C004 司命是否直接控制角色

- 冲突议题：司命是否可直接让角色执行动作
- 旧说法轮次：早期导演描述中的潜在控制倾向
- 新说法轮次：`040`、`212`、`213`
- 当前采用：只催化，不控制；角色自行决策
- 采用原因：这是后续角色智能体设计、干预原则和公平性的共同前提

### C005 感知路线

- 冲突议题：AI 是否依赖截图/多模态视觉
- 旧说法轮次：`135-136` 前后的探索性疑问
- 新说法轮次：`214-215`、`400`
- 当前采用：结构化语义事件流 + 可感知信息编译层 + Per-Character 感知过滤器
- 采用原因：成本、延迟、公平性三方面都更稳定
- 覆盖标注：`077`、`214`、`215` 中“感知过滤器直接承担主转换”的旧表述，统一以后期链路覆盖：`原始世界事件 -> 可感知信息编译层 -> Per-Character 感知过滤器 -> 角色感知事件`

### C006 ESM 与司命边界

- 冲突议题：环境交互大脑是否隶属于司命
- 旧说法轮次：`287` 的疑问态
- 新说法轮次：`302-303`
- 当前采用：ESM 独立于司命，司命只发高层催化指令
- 采用原因：物理规则必须毫秒级、确定性、可复现

### C007 证据系统归属

- 冲突议题：物证、痕迹是否由 ESM 或事件总线统一负责
- 旧说法轮次：`304-306`
- 新说法轮次：`307`
- 当前采用：拆为 ESM + 物品流转追踪器 + 接触痕迹管理器 + 生物痕迹管理器 + 司命事实核心
- 采用原因：后期职责划分最清晰，可直接指导系统设计

### C008 玩法是否只支撑追凶

- 冲突议题：核心系统是否默认只服务侦探推理
- 旧说法轮次：`370-372` 暴露出的偏追凶倾向
- 新说法轮次：`379`、`400`
- 当前采用：核心系统目标中立，追凶只是 Phase 1 首个完整闭环
- 采用原因：后续要扩展生存、复仇、逃脱、经营等玩法

### C009 是否给所有角色公共目标

- 冲突议题：是否所有玩家都必须共享同一个第一目标
- 旧说法轮次：`371-372`
- 新说法轮次：`373-379`
- 当前采用：只允许部分角色共享共同目标，所有角色都保留个人目标
- 采用原因：更符合角色扮演本质，也能容纳更复杂的剧本结构

### C010 “侦探/罪犯/特工”命名是否保留

- 冲突议题：特殊人群是否使用这组命名
- 旧说法轮次：`388-390`
- 新说法轮次：`391-396`
- 当前采用：不直接冻结这组三个命名，需重新纳入更统一的人群分类体系
- 采用原因：用户明确指出命名风格不一致

### C011 小世界是否属于 Phase 1

- 冲突议题：个人空间/小世界应在 Phase 2 还是提前到 Phase 1
- 旧说法轮次：三阶段原始分工中的后置倾向
- 新说法轮次：`208`、`398`、`400`
- 当前采用：Phase 1 实现轻量版
- 采用原因：用户明确前置需求，且后续计划多次接受

### C012 Phase 1 是否承担完整生态

- 冲突议题：Phase 1 是否同时做完整创作者生态、区块链、持续世界
- 旧说法轮次：早期愿景堆叠型讨论
- 新说法轮次：`380`、`398`、`400`
- 当前采用：Phase 1 只做核心体验验证，生态能力大多后移
- 采用原因：后期计划已经明确收缩范围

### C013 开发规划的组织方式

- 冲突议题：按完整大而全规划写，还是按阶段逐步落地
- 旧说法轮次：`106`
- 新说法轮次：`203`、`207`、`209`、`380`、`398`、`400`
- 当前采用：总体愿景可保留完整规划，但执行文档必须按阶段落地，尤其以 Phase 0/1 最小闭环为先
- 采用原因：后期反复收束为“先验证核心体验，再扩展”

### C014 Phase 1 是否包含个人空间/小世界

- 冲突议题：个人空间是否留到后续阶段
- 旧说法轮次：`207`
- 新说法轮次：`208`、`209`、`398`、`400`
- 当前采用：Phase 1 包含轻量版个人空间 / 小世界和带走机制
- 采用原因：`208` 是明确追加需求，之后多次进入修订版计划

### C015 技术栈与基础设施表达方式

- 冲突议题：是否用“七层大架构”作为当前执行依据
- 旧说法轮次：`106`
- 新说法轮次：`203`、`214`、`260`、`380`
- 当前采用：当前执行口径以三层架构 + 关键运行时子系统为准，不采用 `106` 的七层大架构作为当前主口径
- 采用原因：后期三层架构反复稳定，且更适合当前实现阶段

### C016 Phase 0 的目标边界

- 冲突议题：Phase 0 是否应同时验证大范围玩法和视觉增强系统
- 旧说法轮次：`102`、`105`
- 新说法轮次：`380`
- 当前采用：Phase 0 只验证最小原型链路，不提前承担完整玩法闭环
- 采用原因：`380` 对启动步骤和验收标准给出了更收敛的版本

### C017 Phase 1 中司命的能力定位

- 冲突议题：Phase 1 的司命是否只做被动逻辑守护
- 旧说法轮次：`266`
- 新说法轮次：`267`、`398`、`400`
- 当前采用：Phase 1 采用“完整单局导演”口径，司命要参与单局内的事实守护、知识管理、节奏评估、暗杀机会催化与有限主动干预
- 采用原因：`267` 已直接指出 `266` 的分拆过于保守；后期 Phase 1 规划再把“司命实时导演”纳入核心差异化体验。若仍沿用 `266` 的旧分拆，会与当前项目边界和体验目标冲突

### C018 玩家、旅人与剧中角色是否是同一对象

- 冲突议题：玩家本人、旅人身份和剧中角色是否可在设计上混写
- 旧说法轮次：`217` 及更早阶段里混合使用这些称呼的表述
- 新说法轮次：`224-225`
- 当前采用：旅人是 Meta 身份，剧中角色是单局内智能体实例，玩家是在驾驶剧中角色
- 采用原因：后期明确区分后，才能正确组织玩家投影角色、小世界、跨剧本与资产关系

### C019 玩家角色与 AI 角色是否走两套底层

- 冲突议题：玩家扮演角色是否需要完全独立于 AI 角色的另一套系统
- 旧说法轮次：`216-221` 中仍可能导向“双轨实现”的中间态表述
- 新说法轮次：`224-225`、`227`
- 当前采用：统一角色智能体底层，区别只在于玩家是否接管主动规划与部分执行
- 采用原因：后期统一底层口径更利于系统复用、一致性和后续挂机接管/回切

### C020 事件总线是否要先冻结具体线协议

- 冲突议题：做总线设计时，是否必须先锁 JSON、FlatBuffers 或某个唯一编码方案
- 旧说法轮次：`214-215` 附近容易衍生出的实现先行理解
- 新说法轮次：`260`、`352-353`、`400`
- 当前采用：先冻结语义层、优先级、链路分层和 Per-Character 感知路由，不冻结最终编码格式
- 采用原因：当前阶段真正稳定的是消息语义和职责边界，不是最终序列化协议

### C021 Phase 1 小世界是否包含完整持续运行感

- 冲突议题：Phase 1 的小世界是否应包含小镇生态、多同伴共存、节日和完整离线生活模拟
- 旧说法轮次：`311-341` 中大量前瞻性完整版设想
- 新说法轮次：`398`、`400`
- 当前采用：Phase 1 仅保留基础场景、基础对话、快照存储与基础离线补全
- 采用原因：后期更新版计划已把完整版小世界后移到 Phase 2/3；若不显式收束，文档极易范围膨胀

### C022 特殊人群是否已成为独立最高优先级主线

- 冲突议题：11 种特殊人群是否应独立凌驾于[目标与任务系统设计](/d:/Projects/Paralls/docs/phase1/core/03-玩法与内容/目标与任务系统设计.md)之上
- 旧说法轮次：`388-396` 讨论期间可能产生的“单独拔高”倾向
- 新说法轮次：`396`、`400`
- 当前采用：特殊人群是角色设计语法，服务于[目标与任务系统设计](/d:/Projects/Paralls/docs/phase1/core/03-玩法与内容/目标与任务系统设计.md)，不反客为主替代产品主线
- 采用原因：后期明确要求保持其从属地位，避免整理工程被局部议题带偏

### C023 深度沉浸是系统自动补全还是玩家手动表演

- 冲突议题：深度沉浸机制到底要靠玩家自己演，还是系统自动补全
- 旧说法轮次：`218` 之前的宽泛“沉浸设置”说法
- 新说法轮次：`218`、`219`、`220`
- 当前采用：系统自动补全微表情、小动作、社交距离、语音微表现和内心戏，玩家只需做决策
- 采用原因：后期把沉浸感从“手动表演门槛”转成“系统补齐人设表现”

### C024 玩家挂机时角色是否停滞

- 冲突议题：玩家短暂离开时角色是否应该原地发呆
- 旧说法轮次：传统在线游戏的故障式处理
- 新说法轮次：`222`、`223`
- 当前采用：切入保守自主模式，角色继续活着
- 采用原因：可维持叙事连续性，也不打断其他玩家体验

### C025 玩家角色是否是纯系统智能体

- 冲突议题：玩家角色是否与 AI 角色完全同构、都由系统自主运行
- 旧说法轮次：`216`、`217`
- 新说法轮次：`226`、`227`
- 当前采用：玩家角色是玩家大脑意志投射 + 系统补全层的混合体，不是纯系统智能体
- 采用原因：后期明确了玩家的真实感知、理解和决策不应被系统替代

### C026 目标体系是 30 种还是 8 种

- 冲突议题：游戏目标是否维持 30 种独立目标
- 旧说法轮次：`381` 之前的全量扩展态
- 新说法轮次：`385`
- 当前采用：8 种核心目标，其余作为衍生或组合
- 采用原因：更适合产品落地，也更利于围绕核心博弈做系统复用

### C027 共同目标是否可全员共享

- 冲突议题：是否所有角色都应共享同一个第一目标
- 旧说法轮次：`381` 附近的全员追凶倾向
- 新说法轮次：`386`、`400`
- 当前采用：共同目标只对部分角色成立，局部阵营可共享
- 采用原因：更符合角色扮演与复杂博弈结构

### C028 复合目标是否需要独立升格

- 冲突议题：像“偷盗并全身而退”这种复合玩法，是否需要单独升格为新核心目标
- 旧说法轮次：`387` 之前的模糊组合写法
- 新说法轮次：`387`
- 当前采用：不升格，拆回核心目标组合描述
- 采用原因：避免目标体系无限膨胀，同时保留玩法表达能力

### C029 平台是否只是交易平台

- 冲突议题：平台是否只扮演交易撮合与抽成角色
- 旧说法轮次：`210` 前的简化商业理解
- 新说法轮次：`211`
- 当前采用：平台是技术基建方 + 官方资产 / 云服务提供方的双重体
- 采用原因：`211` 明确补上了官方资产供给和算力云服务身份，后续商业结构必须据此重写

### C030 Phase 1 是否要交付完整商业生态

- 冲突议题：Phase 1 是否同时承担完整创作者市场、大玩家体系和链上分账
- 旧说法轮次：早期愿景堆叠式商业设想
- 新说法轮次：`398`、`400`
- 当前采用：Phase 1 只做商业验证最小闭环与接口预留
- 采用原因：后期收束已明确商业体系不能反压当前核心体验交付

### C031 玩家档案是否只有单层展示

- 冲突议题：角色档案是否只需要一个统一面板
- 旧说法轮次：早期粗略的角色信息展示思路
- 新说法轮次：`217`、`398`
- 当前采用：至少区分公开档案和真实档案，并允许建议伪装档案辅助扮演
- 采用原因：伪装、博弈和知情权保护都依赖这种分层

### C032 信息过载是否完全由玩家自行承担

- 冲突议题：高密度信息博弈是否不需要系统辅助
- 旧说法轮次：信息系统尚未细化前的隐含前提
- 新说法轮次：`233`
- 当前采用：引入信息减速带，包括摘要、高亮、嫌疑可视化和推理快照
- 采用原因：后期明确这不是软提示，而是保持参与度的结构性机制

### C033 凝神是否是通用模式超能力

- 冲突议题：凝神是否所有模式都可无条件使用
- 旧说法轮次：较早的高维观察想象
- 新说法轮次：`200`、`217`、`218`
- 当前采用：只限单人 / AI 模式，且不能移动、交互或推进关键逻辑
- 采用原因：否则会破坏多人博弈公平性

### C034 剧本大厅是否只需基础创建 / 加入

- 冲突议题：Phase 1 的大厅是否只要最小房间入口即可
- 旧说法轮次：`204/206` 前的简化理解
- 新说法轮次：`217`、`398`
- 当前采用：大厅至少要承载多种匹配模式和角色偏好入口
- 采用原因：AI 兜底和不同体验偏好是当前产品结构的一部分，不是后期装饰

### C035 变声器与文字润色是否同级可选

- 冲突议题：沉浸设置中，变声器和文字润色是否都只是普通开关
- 旧说法轮次：沉浸设置尚未分级时的轻量表达
- 新说法轮次：`200`、`217`、`398`
- 当前采用：变声器强制，文字润色可选
- 采用原因：后期口径已明确二者承担的沉浸职责不同

### C036 信息是否默认自动广播

- 冲突议题：角色发现线索后，系统是否会默认把信息自动扩散出去
- 旧说法轮次：信息系统尚未明确前的隐含简化理解
- 新说法轮次：`037`、`217`
- 当前采用：信息默认私有，必须通过公开对话、耳语、展示、带人查看、拍摄等可验证动作主动共享
- 采用原因：信息不对称本身就是玩法资源，若自动广播会直接削弱博弈层

### C037 带走机制是否是“点击购买”

- 冲突议题：带走智能体究竟是商品化按钮购买，还是人格驱动的叙事事件
- 旧说法轮次：`202` 中被明确点名的早期“点击按钮购买”旧版本
- 新说法轮次：`172-175`、`202`、`403`
- 当前采用：完整口径是玩家主动邀请、司命判断关系、人格过滤器决策、自然表达、坦白与契约的双向叙事仪式
- 采用原因：只有叙事仪式才能保证羁绊成立、角色不 OOC，且不把智能体降格成纯商品

### C038 Phase 1 是否要交付完整“坦白与契约”

- 冲突议题：带走机制的完整版叙事仪式是否应在 Phase 1 全量交付
- 旧说法轮次：`172-175` 的完整版设想及相关延展
- 新说法轮次：`208-209`、`398`、`400`
- 当前采用：Phase 1 只交付“邀请同行 + 阈值判定 + 角色快照 + 简短告别叙事”的轻量版，完整版坦白与契约后移
- 采用原因：后期已明确 Phase 1 只验证情感价值最小闭环，不承担完整跨世界叙事负担

### C039 离线时间线是否需要 Phase 1 全量持续推演

- 冲突议题：玩家下线后，Phase 1 是否要让小世界完整持续运行并推演全部生活细节
- 旧说法轮次：`311-341` 中大量完整小世界活态设想
- 新说法轮次：`398`、`400`
- 当前采用：只做登录时关键事件补全和简报，不做完整离线世界快进

### C040 三种知识形态是否可以混写

### C041 所有重要证据是否都应自动生成图片

### C042 首个剧本是否只需线性文案即可开发

### C045 玩家角色是否接管整套智能体

### C046 深层沉浸机制是否由司命直接驱动

### C047 Phase 1 是否只保留角色层基础功能

### C048 角色记忆是否只是单一记忆池

### C049 感知是否只能在动作完成后发生

- 新说法轮次：`202`、`263`、`352-353`

- 采用原因：只有这样，暗杀、躲避、惊吓、火灾回避等高张力行为才有实时性；`352-353` 之后这条已经从理念变成接口级要求

### C050 三重过滤器是否只约束对话文本

- 新说法轮次：`026`、`076`、`173`、`175`、`221`、`228`
- 当前采用：过滤器约束的是行动候选本身，覆盖 AI 自主行为、挂机代打行为和系统建议排序
- 采用原因：后续它被用于实时对话、带走决策、挂机代打和系统建议排序；如果只约束文本而不约束动作，角色会在行为层 OOC

### C051 内心独白、冲动与决策建议是否属于同一种提示

- 新说法轮次：`220`、`221`、`226`、`227`、`320`
- 当前采用：内心独白来自 `L2`，冲动来自司命注入，决策建议来自 `L3`
- 采用原因：只有拆清来源，才能保证玩家体验、调试和权限边界都可解释；`320` 还要求这些补全层对玩家应是透明的，而不是像在操控另一个替身

### C052 挂机模式是否允许自动推进关键剧情

- 旧说法轮次：把“角色继续活着”误解成“系统替玩家继续玩”的延伸理解
- 新说法轮次：`222`、`223`、`227`
- 当前采用：挂机模式只允许保守自保、基础移动、观察和简短被动回应，不推进关键剧情
- 采用原因：这样既不断叙事，又不剥夺玩家对重大选择的主权

### C053 事件总线是否把同一事件原样广播给所有角色

- 冲突议题：广播是否意味着所有角色收到同一份事件内容
- 旧说法轮次：`214-260` 阶段中容易产生的粗粒度理解，以及 `352` 之前对广播结果未彻底拆收件人的表述

- 当前采用：事件总线承载的是原始/结构化世界事件；角色侧默认接收的是经过 Per-Character 感知过滤后的角色专属事件，而不是同一份原始内容
- 采用原因：只有这样，视觉/听觉/嗅觉/热感差异、遮挡、距离与知识不对称才能成立；`353` 已把“司命收原始事件、角色收感知结果”压实为接口级边界

### C054 司命是否可借消息总线直接控制角色动作

- 旧说法轮次：`108` 中司命过强“指挥权”的表达，以及早期“导演系统”容易导向的中央控制器理解
- 新说法轮次：`213`、`287`、`303`、`353`
- 当前采用：司命只能发送 `impulse`、`fact_reveal`、`opportunity` 等高层消息，不能直接下发低层动作控制，更不能绕过角色的 `L2/L3` 和三重过滤器
- 采用原因：这是角色自主性、公平性和“司命只催化不控制”原则在消息接口层的具体实现

### C055 “实时编剧 / 世界主宰”是否等于无限系统权力

- 冲突议题：司命被描述为“活着的实时编剧”“世界主宰”时，是否意味着它可以无限制改写世界

- 新说法轮次：`213`、`287`、`302-304`、`353`、`398-400`
- 当前采用：保留“实时编剧 / 导演”作为产品隐喻，但系统实现上必须受事实锁定、角色自主、消息边界和 `ESM` 物理边界约束；司命编排的是叙事路径，不是无限重写真相或直接指挥世界
- 采用原因：中期强表述有产品想象价值，但若不被后续边界收束，会直接破坏角色自主性、可推理性和系统职责清晰度

### C056 司命是否需要在离线期持续常驻运行

- 新说法轮次：`341`、`398`、`400`

- 采用原因：`341` 已明确修正 `340` 的常驻运行倾向；后期 Phase 1 计划继续采用“登录补全式活感”，避免算力和系统复杂度失控

### C057 司命是否承担底层环境物理模拟

- 冲突议题：环境交互结果、物体状态变化和物理执行是否归司命直接负责
- 旧说法轮次：`287` 之前与周边轮次中“环境交互大脑属于司命”或“司命直接生成环境结果”的含混倾向
- 新说法轮次：`302-304`
- 当前采用：不归司命直接负责。`ESM` 负责毫秒级确定性物理规则与状态执行，司命只负责解释叙事意义、评估机会并发出高层催化请求
- 采用原因：只有把物理执行与叙事催化拆开，才能同时保证可复现性、性能、证据链一致性与职责清晰

### C058 ESM 是否直接生成物证与线索解释

- 冲突议题：`ESM` 是否负责生成物证、线索描述和矛盾判断
- 旧说法轮次：`302` 前后及其延伸表述中的混杂理解
- 新说法轮次：`304-305`
- 当前采用：`ESM` 只忠实记录和上报物理状态变化，不负责把状态变化解释为“证据”“矛盾”或“线索描述”；这些解释分别属于司命事实核心和角色 `L2`
- 采用原因：若不拆开，物理执行层与推理层会混在一起，导致职责不清、证据链不可解释

### C059 接触痕迹是否只需靠事件总线保留

- 冲突议题：接触痕迹是否只要作为事件总线里的消息存在即可
- 旧说法轮次：`305` 中“交互行为自动生成即可”的轻量延伸理解
- 新说法轮次：`306-307`
- 当前采用：不可以。事件总线只负责实时通知，接触痕迹必须有独立的接触痕迹管理器负责持久化存储、结构化查询、可见性判定和生命周期管理
- 采用原因：接触痕迹是推理闭环的长期业务数据，不是一次性消息；若只靠事件流，会丢失查询能力与证据稳定性

### C060 证据是否可以全部并入单一系统

- 冲突议题：物理状态、流转、指纹、血迹、矛盾是否可以由一个系统统一负责
- 旧说法轮次：`304-306` 期间仍有“事件总线负责痕迹”或“ESM 包掉全部证据”的混合表达
- 新说法轮次：`307`、`310`
- 当前采用：必须拆为五层：`ESM`、物品流转追踪器、接触痕迹管理器、生物痕迹管理器、司命事实核心
- 采用原因：不同证据类型的产生机制、持久化方式、查询方式和解释逻辑完全不同，强行并到单一系统会造成职责塌缩

### C061 销毁证据是否意味着信息彻底消失

- 冲突议题：证据被烧毁、砸碎或清洗后，是否等于线索链彻底断掉
- 旧说法轮次：传统线性剧本杀式的隐含理解，以及若干前期“销毁后不可恢复”直觉
- 新说法轮次：`351`、`354-357`、`400`
- 当前采用：销毁证据本身必须生成新的可推理后果，例如残骸、氧化、灰烬、目击、气味、时间线矛盾、归属历史和行为痕迹；销毁行为不能成为信息黑洞
- 采用原因：这是《开本》证据博弈闭环成立的关键原则，也是“销毁证据”从写死剧情转成实时物理博弈的核心

### C062 证据可视化是否对所有证据自动触发

- 冲突议题：所有重要证据是否都应该自动生成图片并发给玩家
- 旧说法轮次：证据图像化尚未细分时的泛化想象
- 新说法轮次：`309-310`
- 当前采用：只有视觉可见证据适合图片化，而且必须由玩家主动通过观察、凝神、拍摄、展示或分享触发；逻辑结论、人证和动机判断不属于自动图片生成对象
- 采用原因：若自动对所有证据图片化，会破坏信息主权、稀释观察行为价值，也会把逻辑推理错误地扁平成视觉素材

### C063 ESM 完整蓝图是否等于 Phase 1 交付范围

- 旧说法轮次：`302-308`
- 新说法轮次：`400`
- 当前采用：不是。Phase 1 只做基础交互版 `ESM`；完整物理规则后移到 Phase 2，天气 / 生物成长等进一步后移到 Phase 3
- 采用原因：`302-308` 冻结的是系统职责蓝图，不是阶段性交付边界；若不收束，会导致当前范围严重膨胀

### C064 角色身体状态是否完全归角色智能体维护

- 冲突议题：受伤、失温、中毒、醉酒、行动受限等状态，是否都应作为角色层内部变量直接维护
- 旧说法轮次：`297` 中把角色状态网络高度集中写在角色系统里的展开式表述
- 新说法轮次：`302-304`、`350`、`400`
- 当前采用：不完全归角色层。身体状态先由 `ESM` 作为具身物理结果结算，角色 `L2` 再解释这些结果并更新主观心智状态
- 采用原因：后续边界已经明确“物理事实”和“角色理解”不能混写；否则 `ESM`、角色层和证据链会发生职责塌缩

### C065 濒死与死亡是否由司命或叙事直接判定

- 采用原因：只有这样，角色死亡才既可推理、可复现，又不会变成叙事层随意越权的黑箱结果

### C066 `297-298` 的完整生理状态网络是否都属于 Phase 1 当前范围

- 冲突议题：饥饿、口渴、代谢、复杂康复等完整生理网络，是否都应随着角色状态设计一并进入 Phase 1
- 旧说法轮次：`297-298`
- 新说法轮次：`398-400`

- 采用原因：后期阶段边界已经收束到“支撑当前核心体验”的范围，不能再把早期扩展态全量回灌进 Phase 1

### C067 世界引擎是否等于“内置并重写一套游戏引擎”

- 冲突议题：项目是否需要把底层游戏引擎完整打包重写到开本内部
