## 三、消息协议

所有事件采用统一的结构化JSON格式：

```json
{
  "event_id": "evt_20260527_001",
  "timestamp": "2026-05-27T19:05:23.456Z",
  "priority": "P2",
  "ttl_ms": 5000,
  "source": {
    "layer": "L1",
    "system_family": "交互系统族",
    "component": "感知事实上抛器.视觉",
    "character_id": null
  },
  "type": "object_entered_vision",
  "routing": {
    "pattern": "broadcast",
    "scope": "room_12345",
    "targets": null,
    "space_filter": {
      "center": {"x": 14.5, "y": 1.65, "z": 10.5},
      "radius": 20.0,
      "channel": "vision"
    }
  },
  "payload": {
    "object_id": "char_B",
    "object_name": "华生医生",
    "position": {"x": 14.5, "y": 1.65, "z": 10.5},
    "notable_features": "面色苍白，右手有血迹",
    "lighting": "煤油灯，暖色调",
    "occlusion": "none"
  }
}
```

**关键字段说明**：

| 字段 | 说明 |
| :--- | :--- |
| `priority` | P0（致命威胁，<50ms）/ P1（紧急，<200ms）/ P2（重要，<3000ms）/ P3（普通，<5000ms） |
| `ttl_ms` | 消息生存时间。超时后优先级调度器自动丢弃，不再投递 |
| `routing.pattern` | `broadcast`（广播给scope内所有订阅者）/ `unicast`（指定targets）/ `multicast`（按标签/阵营筛选）/ `pubsub`（发布订阅） |
| `routing.space_filter` | 可选。当事件与空间位置相关时，携带空间信息。路由器可据此优化投递范围 |


## 四、优先级调度策略

| 优先级 | 事件类型 | 延迟上限 | 处理方式 | 超时处理 |
| :--- | :--- | :--- | :--- | :--- |
| **P0 致命** | 暗杀意图感知、本能反应指令、致命威胁事件 | <50ms | P0直连通道（内存队列），跳过所有排队，直接抢占 | 不可超时——P0消息不设TTL |
| **P1 紧急** | 玩家对话、状态同步、知识图谱更新、ESM状态变化上报 | <200ms | 实时通道（WebSocket），优先级队列头部 | 超时丢弃，等下一次心跳全量同步 |
| **P2 重要** | 司命干预决策结果、L3生成触发、角色心智模型输出 | <3000ms | 实时通道或可靠通道（按需），正常排队 | 超时降级为规则程序兜底 |
| **P3 普通** | 环境氛围事件、非关键状态更新、批量感知事件 | <5000ms | 可靠通道（NATS），可合并批处理 | 超时丢弃，下次心跳补全 |


## 五、通道分流策略

| 通道类型 | 技术实现 | 延迟 | 可靠性 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **P0直连通道** | 内存队列（同进程）/ Unix Domain Socket（跨进程） | <1ms | 不持久化 | P0致命威胁事件 |
| **实时通道** | WebSocket（客户端↔服务端） + 内存队列（服务端内部） | <50ms | 尽力交付 | P0/P1实时交互事件、状态同步、感知事件流 |
| **可靠通道** | NATS JetStream | <500ms | 持久化+至少一次交付 | P2/P3异步推理、持久化事件、跨服务解耦通信 |

### 6.1 订阅表管理器

| 维度 | 说明 |
| :--- | :--- |
| **核心职责** | 维护所有消费者的事件订阅关系 |

### 6.2 路由模式

| 路由模式 | 触发条件 | 投递范围 |
| :--- | :--- | :--- |
| **广播 (Broadcast)** | 公共事件（对话、环境变化、尸体发现） | 房间内所有订阅者 |
| **单播 (Unicast)** | 私密对话、司命→特定角色指令 | 指定角色或服务 |
| **组播 (Multicast)** | 阵营事件、空间范围事件 | 满足条件的角色集合 |
| **发布/订阅 (Pub/Sub)** | 服务间解耦通信 | 订阅该事件类型的所有服务 |

## 八、一句话总结

事件总线是《开本》六层架构的神经中枢，由消息路由器（广播/单播/组播/发布订阅）、优先级调度器（P0-P3四级调度）、通道分流器（P0直连/WebSocket实时/NATS可靠）三个孙系统构成。P0致命威胁走内存直连（<1ms），P1实时交互走WebSocket（<50ms），P2/P3异步事件走NATS（持久化+至少一次交付）。所有事件采用统一的结构化JSON格式，携带优先级、TTL、路由模式和空间过滤信息。L1作为事件生产者，L2/L3/L4/L5作为事件消费者，通过事件总线完全解耦。
