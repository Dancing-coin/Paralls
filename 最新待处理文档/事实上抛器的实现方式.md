在《开本》最终定稿的六层架构下，L1的**感知事实上抛器**是整个感知链路的起点。它们不是独立的脚本，而是深度集成在Godot引擎各子系统中的**事件生成器**。下面逐一说明八类上抛器的具体实现方式。

---

## 一、视觉事实上抛器

**集成位置**：Godot渲染管线的可见性计算阶段之后。

**实现原理**：利用Godot的`VisibilityNotifier3D`和自定义的可见性检测射线，在每帧（或按角色分频）检测每个角色视野范围内的所有`VisualInstance3D`对象。

```
[每帧/每3帧] → [遍历角色列表] → [获取角色位置+朝向+视野参数]
    → [空间哈希快速筛选候选对象] → [对候选对象做锥形视野检测]
    → [对通过视野检测的对象做遮挡检测(单次射线)]
    → [对比上一帧的可见对象集合]
        → 新进入的对象：生成 object_entered_vision 事件
        → 离开的对象：生成 object_exited_vision 事件
        → 状态变化的对象(受伤/倒地/持有物品变更)：生成 object_state_changed_vision 事件
```

**关键优化**：
- 空间哈希将场景划分为网格，只检测角色所在网格及相邻网格的对象
- 锥形视野检测用点积快速判断，120度锥形视野对应`dot > 0.5`
- 遮挡检测仅对视野边缘的对象做单次射线，视野中心对象默认可见
- 远处的角色每5帧检测一次，近处的每帧检测

**上报数据结构**：
```json
{
  "observer_id": "char_A",
  "object_id": "char_B",
  "object_name": "华生医生",
  "position": {"x": 3.5, "y": 0, "z": 2.1},
  "distance": 3.5,
  "notable_features": "面色苍白，右手有血迹",
  "lighting": "煤油灯，暖色调",
  "occlusion": "none"
}
```


## 二、听觉事实上抛器

**集成位置**：Steam Audio适配器处理完声音传播计算之后。

**实现原理**：L1的空间音频系统（Steam Audio适配器）已经完成了HRTF渲染、距离衰减、物理遮挡计算。听觉事实上抛器直接读取这些计算结果，将其转化为结构化事件，无需重复计算。

```
[声音事件发生(对话/脚步声/门响/物品掉落)]
    → [Steam Audio计算声波传播路径]
    → [获取每个听者位置的声压级、清晰度、混响参数]
    → [根据清晰度分级(清晰区/模糊区/静默区)]
    → [生成听觉事实事件]
```

**关键设计**：`clarity`字段直接复用Steam Audio的声学计算结果。物理阻挡（门/墙）的衰减值由Steam Audio自动计算，上抛器只需读取`occlusion_level`参数（0.0-1.0）映射为清晰度分级。

**清晰度判定规则**：
| 清晰度 | 条件 | 可感知内容 |
| :--- | :--- | :--- |
| `clear` | 声压级>阈值 + 遮挡<0.3 | 完整对话文本 + 说话者身份 + 情绪 |
| `muffled` | 声压级中等 + 遮挡0.3-0.7 | 关键词片段 + 模糊情绪 + 说话者身份"疑似" |
| `distant` | 声压级低 + 遮挡>0.7 | 仅知"有人在说话"或"有脚步声" |
| `barely_audible` | 声压级极低 | 仅知"有动静" |

**上报数据结构**：
```json
{
  "observer_id": "char_A",
  "source_id": "char_B",
  "source_name": "福尔摩斯",
  "sound_type": "speech",
  "content": "华生，你昨晚在书房看到了什么？",
  "clarity": "clear",
  "distance": 2.0,
  "direction": "front",
  "emotion": "calm_inquisitive",
  "occlusion_level": 0.1,
  "ambient_noise_level": 0.3
}
```


## 三、触觉事实上抛器

**集成位置**：Godot物理引擎的碰撞检测回调之后。

**实现原理**：监听`Area3D`或`CharacterBody3D`的`body_entered`/`body_contact`信号，以及射线检测触摸交互。

```
[物理碰撞事件] → [判定碰撞类型(接触/推搡/打击)]
    → [提取碰撞力度、接触点、接触材质]
    → [生成触觉事实事件]
```

**关键设计**：触觉范围通常极近（1-2米内），不需要复杂的空间筛选。材质触感通过读取被触摸物体的ESM材质属性（如`mat_wood`、`mat_stone`）来生成对应的触感描述（粗糙/光滑/冰冷/温热）。

**上报数据结构**：
```json
{
  "observer_id": "char_A",
  "source_id": "char_B",
  "contact_type": "tap_shoulder",
  "contact_point": "left_shoulder",
  "force": 0.3,
  "surface_texture": null
}
```


## 四、热感事实上抛器

**集成位置**：独立的热源管理系统，在ESM的温度计算之后。

**实现原理**：在场景中维护一个热源列表（壁炉、火焰、人体、热饮、冷源），每个热源有温度强度、辐射半径、遮挡状态。

```
[每0.5秒] → [遍历角色列表]
    → [对每个角色，检测热源列表中在其热感范围内的热源]
    → [对每个热源做遮挡检测(单次射线)]
    → [对比上一帧的热源感知状态]
        → 新出现/消失/强度变化的热源：生成热感事件
```

**关键设计**：热感范围较小（通常3-5米），检测频率可以降低（每0.5秒）。人体热源特殊处理——活人>死人>无生命的物体，盲人角色的热感范围和灵敏度翻倍。

**上报数据结构**：
```json
{
  "observer_id": "char_blind_monk",
  "source_id": "fireplace_01",
  "source_type": "fire",
  "temperature": 0.8,
  "distance": 2.5,
  "direction": "front-right",
  "occlusion": false
}
```


## 五、嗅觉事实上抛器

**集成位置**：独立的气味扩散模拟系统。

**实现原理**：在场景中维护一个气味源列表（血腥味、香水、烟雾、药物、腐败、食物），每个气味源有扩散半径、强度、衰减曲线。

气味扩散不是每帧计算，而是由气味扩散模拟器持续更新——考虑气流方向（ESM天气系统的风力参数）、温度（热空气上升携带气味）、空间障碍（门/墙阻挡气味扩散）。

**上报数据结构**：
```json
{
  "observer_id": "char_A",
  "smell_type": "burning_cotton",
  "intensity": 0.6,
  "direction": "kitchen_area",
  "decay": "increasing"
}
```


## 六、生理状态事实上抛器

**集成位置**：角色状态管理器的参数变化回调。

**实现原理**：监听每个角色的生理状态参数（体温、压力值、伤势、醉酒等），当参数超过阈值时生成事件。

```
[角色状态参数变化] → [检查是否超过触发阈值]
    → [生成生理状态事实事件]
    → [事件包含可被观察到的部位和表现类型]
```

**关键设计**：根据表现类型分流——视觉型表现（发抖、出汗、脸色苍白）标记为视觉可观察，听觉型表现（呼吸急促、牙齿打颤）标记为听觉可观察。分流信息供L2可感知信息编译层的通道编译器使用。

**上报数据结构**：
```json
{
  "observer_id": "char_A",
  "subject_id": "char_B",
  "state_type": "shivering",
  "intensity": 0.7,
  "observable_on": ["whole_body"],
  "observable_via": ["vision"],
  "cause": "cold_exposure"
}
```


## 七、社交距离与空间行为上抛器

**集成位置**：角色智能体L4执行层的社交距离通道指令输出之后。

**实现原理**：监听角色之间的空间关系变化。角色智能体的L4执行层社交距离通道下发指令后，L1深度沉浸机制的社交空间行为执行器执行位置调整，上抛器捕获这个变化并生成事件。

**触发条件**：两个角色之间的距离变化超过阈值（如从3米缩短到1米），角色身体朝向发生显著变化（从面对变为背对），角色之间出现特殊空间行为（挡在中间、眼神回避、长时间注视）。

**上报数据结构**：
```json
{
  "observer_id": "char_A",
  "subject_id": "char_B",
  "behavior_type": "distance_shrink",
  "previous_distance": 3.0,
  "current_distance": 1.0,
  "body_orientation": "face_to_face",
  "eye_contact": "mutual"
}
```


## 八、角色状态事实上抛器

**集成位置**：角色智能体L4执行层的动作通道指令输出之后。

**实现原理**：监听角色自身的状态变化动作。角色智能体的L4执行层动作通道下发指令后，L1骨骼动画驱动器执行，上抛器捕获并生成事件。

**触发条件**：角色执行任何改变自身状态的动作——坐下/起身、奔跑/停下、晕倒/苏醒、拔出武器/收起武器、躲藏/现身、死亡。

**上报数据结构**：
```json
{
  "observer_id": "char_A",
  "subject_id": "char_B",
  "state_change": "draw_weapon",
  "weapon_type": "dagger",
  "location": "dining_car_table_03",
  "previous_state": "idle",
  "new_state": "armed"
}
```


## 九、统一的上报接口

所有八类上抛器通过统一的接口向事件总线提交事件：

```
EventBus.submit({
    event_type: "perception_fact",      // 所有感知事实的统一类型
    perception_channel: "vision",       // 具体的感官通道
    observer_id: "char_A",             // 感知者
    target_id: "char_B",               // 被感知的对象
    fact_data: { ... },                // 具体的事实数据
    priority: "P1",                    // P0-P3
    ttl_ms: 5000,                      // 消息生存时间
    space_filter: {                    // 空间信息，供路由器优化
        center: {x, y, z},
        radius: 20.0
    }
})
```

**一句话总结**：八类感知事实上抛器深度集成在Godot引擎的各个子系统中——视觉上抛器在渲染管线的可见性计算之后，听觉上抛器复用Steam Audio的声学计算结果，触觉上抛器在物理碰撞回调中，热感上抛器在独立的热源管理系统中，嗅觉上抛器在气味扩散模拟中，生理状态上抛器在角色状态参数变化回调中，社交距离上抛器在L4执行层指令输出之后，角色状态上抛器在L4动作通道指令输出之后。它们生成统一格式的结构化事件，通过事件总线提交给L2可感知信息编译层。
