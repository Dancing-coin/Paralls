## DeepSeek

# 《开本》Phase 1 项目方案与主要议题

## 一、项目方案

### 1. 项目愿景

打造一款**智能体驱动的3D沉浸式动态剧本杀**，让同一个剧本每一次游戏都不同。通过AI司命实时导演、角色智能体自主博弈、3D空间音频社交，为玩家提供前所未有的推理与沉浸体验。

### 2. 产品形态

| 组件 | 说明 |
| :--- | :--- |
| **游戏客户端** | Godot 4.x 构建的3D游戏，包含剧本场景、空间音频、交互系统、UI/UX |
| **AI服务端** | Python后端，集成LLM对话、角色智能体、司命叙事引擎、模型路由 |
| **首个剧本** | 《血字的研究·变奏》——5角色（2真人+3AI）、2场景、动态案件生成 |

### 3. 核心体验闭环

```
选择剧本 → 选择角色 → 进入3D场景 → 自由探索与对话
    ↓
发现线索与秘密 → 私下/公开交流 → 新冲突涌现
    ↓
暗杀可能发生 → 最终投票/对决 → 结局揭晓 → 本局故事报告
```

### 4. 核心创新

- **动态案件生成**：每次开局凶手、动机、凶器、线索分布随机组合
- **人格驱动的AI角色**：五维人格参数、品格层、人生记忆，AI会自主撒谎、结盟、背叛
- **司命实时导演**：维护逻辑一致性，主动催化冲突，管理游戏平衡
- **3D空间音频社交**：清晰区/模糊区/静默区/耳语模式，声音博弈成为推理线索
- **玩家深度沉浸**：微表情自动映射、内心独白、凝神能力、挂机自主模式
- **智能体轻量带走**：结局时可将建立了羁绊的AI角色带回个人小世界

### 5. 技术架构

```
L1 (Godot) ↔ WebSocket ↔ L2 (Python AI服务) ↔ L3 (图片生成API)
```

- L1负责3D渲染、物理、空间音频、事件埋点
- L2负责角色智能体、司命引擎、对话生成、模型路由
- L3负责线索特写、立绘生成等视觉增强

### 6. 团队与开发计划

| 阶段 | 时间 | 目标 |
| :--- | :--- | :--- |
| Phase 0 | 1-2个月 | 原型验证：单场景+2个AI角色对话+空间音频 |
| Phase 1 MVP | 6个月 | 完整剧本闭环交付，外部玩家测试 |
| 团队规模 | 10-12人 | 客户端、后端AI、技术美术、剧本设计 |

### 7. 商业验证目标

- 单局时长45-60分钟，AI对话≥50轮
- 结局多样性≥3种，暗杀触发率30%-50%
- 玩家留存意愿≥70%，智能体带走率≥40%


## 二、Phase 1 主要议题

### 议题一：AI智能体的实时性与成本控制

**核心问题**：如何在保证AI角色反应自然（秒级延迟）的同时，控制LLM推理成本？

**应对策略**：模型路由三层架构。P0致命威胁走规则引擎（<300ms）；P1紧急对话走本地小模型（1-3B参数，<1500ms）；P2重要推理走云端大模型（<3000ms）。本地小模型处理95%日常对话，云端仅用于关键深度推理，预计单个AI同伴月成本可控制在5-15元（全云端）或更低（本地混合）。

### 议题二：动态叙事逻辑的一致性与可玩性平衡

**核心问题**：司命主动催化冲突时，如何确保不破坏案件逻辑，不干预玩家自由意志？

**应对策略**：司命四原则强制执行——间接性（不直接控制玩家）、不可见性（玩家感知不到系统干预）、逻辑自洽性（所有催化有世界观解释）、公平性（不偏袒任何一方）。司命只催化机会，不替角色做决定。所有干预经自监控系统动态调节，防止过度干预。

### 议题三：3D沉浸交互与AI感知的同步

**核心问题**：AI角色如何实时感知3D世界中的玩家行为，而不依赖昂贵的视觉识别？

**应对策略**：结构化语义事件替代截图。L1层将所有玩家行为（移动、拾取、对话、暗杀意图）转化为结构化JSON事件，通过事件总线推送至L2。每个AI角色通过“感知过滤器”按感官档案（视觉/听觉/触觉/热感）过滤，只接收其感官范围内应感知的信息。这保证了AI与人类玩家在信息获取上的公平性和毫秒级延迟。

### 议题四：用户付费意愿与市场接受度

**核心问题**：玩家是否愿意为“AI驱动的动态剧本杀”付费？目标市场是否明确？

**应对策略**：Phase 0原型测试，录制演示视频收集早期反馈。Phase 1第6月进行外部玩家测试，直接收集付费意愿数据。初期定价策略采用剧本买断制（单个剧本预估定价¥38-68）和服务器门票制，后续通过智能体带走、皮肤、小世界设定包等增值服务扩展收入。

### 议题五：内容供给的可持续性

**核心问题**：官方初期剧本有限，如何保证内容量以吸引玩家持续游玩？

**应对策略**：剧本种子库机制让同一剧本衍生出数千种不同案件组合（不同凶手、动机、凶器、线索分布），重玩价值远超传统剧本杀。后续Phase 2开放剧本编辑器引入创作者社区，Phase 3开放世界编辑器让大玩家创建主题世界。

### 议题六：技术集成的复杂度风险

**核心问题**：Godot 3D引擎、LLM推理、空间音频、事件总线等多个复杂系统的集成，是否会在Phase 1期间出现不可预见的延迟？

**应对策略**：Phase 0先行验证最核心的技术链路（Godot场景 + WebSocket + LLM对话 + 空间音频），确保技术可行后再进入完整MVP开发。每个模块定义清晰的消息协议和接口，独立开发测试后再集成。预留缓冲时间应对意外延迟。


## 三、决策建议

基于以上议题，Phase 1启动前建议确认以下关键决策：

1. **技术栈锁定**：Godot 4.x + Python FastAPI + llama.cpp + Claude/DeepSeek API，不再变更。
2. **首个剧本锁定**：《血字的研究·变奏》，5角色2场景，不再扩展内容范围。
3. **团队规模确认**：核心团队至少需1名Godot开发、1名AI工程师启动Phase 0原型。
4. **商业化路径**：Phase 1以验证体验为核心，暂不接入完整支付系统，但预留剧本买断和智能体带走的付费接口。
5. **外部测试时间表**：第6个月必须完成至少一轮外部玩家测试，数据用于决定是否进入Phase 2。

---

**一句话总结**：Phase 1的核心是“用最小成本验证最核心的假设”——AI驱动的动态剧本杀能否让玩家感受到“那个AI角色真的在骗我，而且它骗得有道理”。所有技术选型、团队配置、开发计划都围绕这个目标服务。
