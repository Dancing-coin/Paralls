## 用户

刚才提到剧本中 烧窗帘的情形，实时演算需要当前世界支持 火烧。我们的世界为了实现这些，需要提前准备什么？ 窗帘，列车壁等的在火烧下的不同状态以及火焰。 我们的剧本宇宙需要能支持的变种有很多，因此我们需要准备好全套的美术资产以供调用，除此之外还要做到什么？ 你来盘点一下大概需要哪些美术资产变种与其对应的反应（如火烧，如泡水）

## DeepSeek

为了实现《开本》中类似“烧窗帘”这种实时演算的环境交互，我们需要在 L1 确定性空间层预先准备好一套完整的环境状态系统。这不仅包括海量的美术资产变种，更关键的是驱动它们变化的底层逻辑。

以下是需要准备的完整清单：

### 一、 核心驱动：交互状态机

这是所有环境交互的“大脑”。我们需要为每一个可交互物体挂载一个状态机组件，它定义了物体在不同条件下的转化逻辑。

| 状态类型 | 触发条件 | 视觉表现 | 音效/特效 | 交互影响 |
| :--- | :--- | :--- | :--- | :--- |
| **默认状态** | 初始状态 | 常规贴图/模型 | 无 | 正常交互 |
| **燃烧状态** | 接触火源 | 焦黑贴图、火焰粒子特效、烟雾粒子特效 | 燃烧声、木材爆裂声 | 可蔓延，产生光亮，接触后受伤 |
| **烧毁状态** | 燃烧状态持续一定时间 | 完全烧毁的模型残骸、灰烬贴图 | 余烬粒子、微弱燃烧声 | 失去原有交互功能（如门烧毁后无法关闭） |
| **潮湿状态** | 接触水源、被泼水 | 深色湿润贴图、水滴粒子 | 滴水声、湿润环境音 | 无法被点燃，表面摩擦力变化 |
| **结冰状态** | 低温环境或魔法效果 | 透明冰层覆盖模型、霜冻贴图 | 冰裂声、寒冷风声 | 表面变滑，触碰可能打滑，物理阻力增加 |
| **破碎状态** | 遭受物理冲击或爆破 | 破碎的几何模型、碎片粒子 | 破碎声、玻璃散落声 | 改变空间连接性（如窗户破碎后可爬出） |

### 二、 美术资产：原子化与变种体系

我们需要将所有场景模型进行**组件化拆分**，并为其准备关键状态变种。剧本创作者和司命可以像搭积木一样组合这些资产。

**1. 可燃烧类**
- **基础资产**：木门、窗帘、木制家具、书籍/纸张、木地板、房梁等。
- **状态变种**：默认贴图 → `_charring`（焦黑） → `_burned_out`（残骸）。
- **配套资产**：瓦砾堆、灰烬贴图、烧焦的框架。

**2. 可潮湿/冰冻类**
- **基础资产**：石墙、金属表面、玻璃窗、布料、地面。
- **状态变种**：默认贴图 → `_wet`（颜色加深/高光增强） → `_iced`（透明冰壳覆盖）。
- **配套资产**：水渍贴图、冰锥模型、雪堆。

**3. 可破坏类**
- **基础资产**：玻璃窗、花瓶、木桶、锁住的箱子、薄墙。
- **状态变种**：完整模型 → `_cracked`（裂纹贴图） → `_broken`（替换为碎片几何体）。
- **配套资产**：玻璃碎片、木屑、石块。

**4. 可操作类**
- **基础资产**：门、可拉开的抽屉、可掀开的床板、壁炉、烛台。
- **状态变种**：`_open` / `_closed`，`_on` / `_off`，`_lit`（点燃） / `_unlit`（熄灭）。
- **配套资产**：门把手、钥匙孔、锁链模型。

### 三、 关键技术：程序化与预设的结合

为了保证流畅性，我们采用**“关键状态切换 + 程序化细节增强”**的策略。

-   **状态切换**：物体在关键状态（正常→燃烧→烧毁）切换时，司命会触发一个微型实时演算脚本。例如，窗帘从正常变为燃烧，系统会播放预制的“布料燃烧”程序化动画，并在顶点着色器中平滑过渡焦黑贴图。
-   **程序化细节**：对于火焰的大小、烟雾的浓度、烧毁的随机边缘等，可以使用**着色器**进行程序化生成，确保每次烧毁的痕迹都独一无二，减少对海量贴图的依赖。
-   **预制特效**：火焰、烟雾、火花、水滴等粒子特效从**原子特效库**中调用，并可根据材质（木头/布料）调整颜色和浓度。

### 四、 跨系统协同：与司命和事件总线的联动

环境变化不仅是视觉上的，它必须是叙事和博弈的一部分。

1.  **事件上报**：当物体状态发生变化时（如窗帘被点燃），L1层必须通过**事件总线**向司命和角色智能体发送结构化事件：`Environment_State_Changed { Object: Curtain_01, State: Burning }`。
2.  **司命介入**：司命收到“火势蔓延”的事件后，可能会：
    -   **环境催化**：命令“火势蔓延到相邻的地毯”。
    -   **AI引导**：让一个NPC智能体作出反应，如“上校迅速拿起外套扑火”。
3.  **AI感知**：附近的AI角色通过**感知过滤器**接收到“看到火焰”或“闻到烟味”的语义事件，并据此更新自己的行为（靠近或远离）。

### 五、 示例：一个完整的“火烧窗帘”事件流程

1.  **剧本配置**：创作者在编辑器中，为“餐车窗帘”资产挂载`[可燃烧]`组件，设置燃烧时间（30秒）、蔓延范围（2米内可燃物）和燃烧产物（烟雾、焦味）。
2.  **事件触发**：阿巴思诺特上校（AI）在餐车角落，对窗帘使用了“打火机”物品。
3.  **状态机响应**：窗帘的“可燃烧”组件收到信号，状态从“默认”切换为“燃烧”。L1层加载火焰粒子特效和焦黑贴图。
4.  **事件广播**：事件总线广播：`窗帘_01 开始燃烧`，`火势等级 1`。
5.  **智能体反应**：附近角色立即感知到。哈伯德太太（AI，胆量2）尖叫并后退。波洛（AI，高理性）抬头观察。
6.  **司命催化**：司命决定扩大事件，命令“火势蔓延到窗帘_02”。
7.  **终局**：上校（AI，胆量8）拿起外套扑火，状态机收到信号，火焰特效逐渐减弱，但窗帘模型已变为焦黑残骸。

通过这套系统，《开本》的世界不再是静态的背景，而是一个能对玩家和AI行为做出真实、动态反应的活舞台。这既需要详尽的资产储备，也依赖于事件总线和司命的全局调度。
