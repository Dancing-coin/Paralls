## 用户

我希望玩家交互过的所有角色都有自己的一份记忆，首先是群体模拟中的每个角色都在群体模拟时建立了自己的种子档案，体量不能大，并且虽然身份具备唯一性但多数记忆是同层级共享的，比如农夫群体作为农夫的记忆是相似的，可能需要区分农夫自身的其他因素；从玩家选择和这些角色开始交互时，先读取种子档案，这些角色可以使用被剧情安排好或预设的基础对话或者动作表情给ai长出档案和记忆充足的时间，同时内部开始基于档案，推演记忆，来进一步和玩家交互，这样能保证玩家的体验流程舒适。 和玩家建立过联系的角色，他的记忆需要升格存储，不再是原本的种子档案（随着司命安排群体模拟做基础更新），虽然也是由司命安排群体模拟来更新记忆，但为了方便之后玩家再次想起这个角色时能不出现失忆的情况，他的记忆只能被压缩不能被销毁，如果记忆丢失，就麻烦司命在群体模拟里给他一个剧情杀。

## DeepSeek

# 群体角色记忆系统设计

## 一、核心设计目标

玩家交互过的每一个角色，都必须拥有一份**可追溯、可延续、不可丢失**的个人记忆。这份记忆不是智能体级别的完整心智模型，而是一个从“群体种子”到“交互档案”再到“升格存储”的三层渐进式结构——体量轻、成本低、但足够支撑玩家再次相遇时的真实感。

---

## 二、三层记忆结构

### 2.1 种子档案（群体层，所有角色默认拥有）

角色在群体模拟中被创建时，自动生成一份极其轻量的种子档案。

| 字段 | 说明 | 体量 |
| :--- | :--- | :--- |
| `id` | 唯一标识 | 8字节 |
| `name` | 姓名（从姓名池随机组合） | 20字节 |
| `age` | 年龄 | 2字节 |
| `gender` | 性别 | 1字节 |
| `profession` | 职业（农夫/铁匠/商人/士兵等） | 1字节 |
| `location` | 当前所在地 | 8字节 |
| `trait_seed` | 人格倾向种子（0-255的整数，决定该角色在同层级中的行为偏移） | 1字节 |
| `birth_event` | 出生时的世界事件ID（用于生成时代背景记忆） | 4字节 |
| `group_memory_ids` | 所属群体的共享记忆ID列表（如“经历过大饥荒”、“参加过某战役”） | 可变 |

**总大小**：单个种子档案约50-100字节。百万级角色仅需约50-100MB存储。

**群体共享记忆**：同一职业、同一城邦、同一时代的角色，共享大量群体记忆。例如：
- 所有“A城邦的农夫”都共享“XX年大饥荒”的记忆
- 所有“B城邦的士兵”都共享“灰谷之战”的记忆
- 这些共享记忆只存储一份，所有角色通过ID引用

**trait_seed的作用**：一个0-255的整数，决定了该角色在同层级群体中的行为偏移。例如：
- trait_seed=0：典型农夫，忠厚老实
- trait_seed=255：不安分的农夫，总想着进城经商
- trait_seed=128：爱抱怨的农夫，对税收特别敏感

这样，即使是同一群体的角色，也会因trait_seed的不同而展现出微妙的个性差异。


## 三、交互时激活流程

当玩家首次与某个群体角色交互时，系统按以下流程处理：

### 3.1 激活流程

```
玩家与角色交互
    │
    ▼
读取种子档案
    │
    ▼
生成过渡性对话/行为（预设模板 + trait_seed微调）
    │ 目标：让玩家感受到角色有基本身份，但不深入
    │ 例子：“您好，我是城东的农夫张三。今年收成还不错。”
    │
    ├── 同时，后台异步启动记忆推演
    │
    ▼
基于种子档案 + 群体共享记忆 + trait_seed → 生成个人记忆档案
    │ 约1-3秒内完成
    │
    ▼
记忆档案就绪 → 角色可以开始深度交互
    │ 对话和行为更加个性化，不再是模板
```

### 3.2 过渡性对话与行为

在后台推演记忆的同时，角色使用预设的“过渡性对话和行为”来填充时间，确保玩家体验不卡顿。

| 群体类型 | 过渡性行为 | 过渡性对话示例 |
| :--- | :--- | :--- |
| **农夫** | 继续耕作、擦汗、喝水 | “今年的收成还不错。”“这天气，该下雨了。” |
| **铁匠** | 继续打铁、擦汗、看火候 | “最近订单多，忙不过来。”“这把剑的钢口不错。” |
| **商人** | 整理货物、记账、招呼客人 | “最近从北边来了一批好货。”“这生意，越来越难做了。” |
| **士兵** | 站岗、巡逻、擦拭武器 | “边境最近不太平。”“上次灰谷之战，我差点没能回来。” |

这些过渡性对话由群体共享记忆 + trait_seed微调生成，足够自然，但不会暴露“这个角色还没有完整记忆”的破绽。

### 3.3 记忆推演

在过渡性行为的同时，系统基于以下信息推演角色的个人记忆：

| 输入 | 说明 |
| :--- | :--- |
| **种子档案** | 年龄、性别、职业、trait_seed |
| **群体共享记忆** | 该角色所属群体的所有共享事件（饥荒、战争、政策变化等） |
| **世界历史时间线** | 该角色出生以来的所有重大世界事件 |
| **trait_seed偏移** | 基于trait_seed对该角色在共享记忆中的“个人体验”进行微调 |

**推演输出**：一份该角色的个人记忆档案，包含：
- 对世界事件的“个人视角”记忆（共享记忆 + trait_seed偏移）
- 对当前生活状态的描述
- 对所在城邦的态度
- 对未来的一些简单希望或担忧

**推演耗时**：1-3秒（在后台异步完成，不影响过渡性行为播放）

### 3.4 推演完成后

角色开始使用个人记忆档案进行交互，对话和行为变得更加个性化：

- “那年大饥荒，我家的粮仓被征了一半。说实话，到现在我对城里的老爷们还有点怨气。”
- “灰谷之战，我就在前线。那场仗打得太惨了，我的两个同乡都没回来。”


## 四、交互后：记忆升格存储

### 4.1 升格机制

与玩家建立过联系的角色，其记忆从“种子档案”升格为“个人记忆档案”，独立存储。

| 存储层级 | 内容 | 存储位置 | 体量 |
| :--- | :--- | :--- | :--- |
| **种子档案** | 基础身份 + 群体共享记忆引用 | 群体模拟数据库 | ~50-100字节 |
| **个人记忆档案** | 基础身份 + 推演记忆 + 与玩家的互动记忆 | 独立存储 | ~2-10KB |

### 4.2 更新机制

升格后的个人记忆档案由司命安排群体模拟引擎进行基础更新。

| 更新内容 | 更新方式 | 频率 |
| :--- | :--- | :--- |
| **基础状态** | 年龄增长、职业变化（可能）、所在地迁移 | 随世界时间推进自动更新 |
| **群体层记忆** | 新发生的群体事件（如“新王登基”、“战争爆发”）自动追加 | 事件发生时更新 |
| **个人互动记忆** | 与玩家的每次交互自动追加 | 交互后立即更新 |

### 4.3 记忆压缩与恢复

**压缩策略**：

| 策略 | 说明 |
| :--- | :--- |
| **时间衰减** | 超过一定时间（如游戏内数年）未使用的角色，其记忆档案被压缩为摘要 |
| **摘要保留** | 压缩后保留：基础身份、关键互动摘要（如“曾被国王赦免”）、与玩家的关系状态 |
| **细节丢弃** | 压缩后丢弃：具体对话内容、具体时间戳、次要事件细节 |

**恢复策略**：
- 玩家再次与该角色交互时，系统从摘要中快速重建该角色的“当下状态”
- 基于群体模拟的最新数据（该角色现在在哪、做什么、年龄等）更新基础状态
- 向玩家呈现时，该角色会记得“国王曾经赦免过我”，但可能记不清具体是哪一天

**数据量控制**：

| 玩家类型 | 预计交互角色数 | 存储总量（压缩后） |
| :--- | :--- | :--- |
| **轻度玩家** | 数十人 | ~100KB |
| **中度玩家** | 数百人 | ~1MB |
| **重度玩家** | 数千人 | ~10MB |
| **国王级玩家** | 上万人 | ~50-100MB |


## 五、记忆丢失的兜底机制

### 5.1 记忆丢失的定义

以下情况可能导致个人记忆档案丢失：
- 存储故障（数据库损坏、服务器迁移丢失）
- 压缩算法错误导致摘要不可恢复
- 极端情况下的人工误操作

### 5.2 司命的“剧情杀”兜底

如果某个已升格角色的记忆档案意外丢失，司命不会让该角色“凭空失忆”，而是通过群体模拟系统安排一个叙事化的“退场”或“状态变更”。

| 情况 | 司命的处理 |
| :--- | :--- |
| **角色尚未被玩家再次遇到** | 司命在群体模拟中为该角色安排一个“剧情杀”——他可能因疾病/迁徙/战争而离开了原来的位置。玩家再次来访时，会从其他角色口中得知“他已经不在这里了” |
| **角色正在被玩家交互时丢失** | 这种情况应极力避免（通过备份和冗余存储）。若万一发生，司命立即触发一个“紧急叙事”——该角色突然显得困惑、疲惫，对玩家说：“陛下，我最近记性不太好...可能是上次受伤落下的后遗症。”然后自然结束对话 |
| **角色对叙事至关重要** | 已被标记为“关键角色”的个人记忆档案，在存储层面受到额外保护：多副本备份、定期完整性校验、禁止压缩至摘要以下 |

### 5.3 叙事化退场示例

> 玩家：“我记得城东有个叫张三的农夫，上次他还送了我一篮鸡蛋。”

> 村民：“张三啊...他去年冬天染了风寒，没挺过来。可惜了，是个好人。”

司命在群体模拟中标记张三为“已死亡”，并将其从群体数据中移除。玩家不会感受到任何技术故障——只会感受到这个世界是真实的，人是有生老病死的。


## 六、完整生命周期

```
┌─────────────────────────────────────────────────────────────┐
│              群体角色的记忆生命周期                          │
│                                                              │
│  [群体创建] → 种子档案生成 (50-100字节)                      │
│       │                                                      │
│       │ 玩家首次交互                                          │
│       ▼                                                      │
│  [激活] → 过渡性行为 (预设模板) + 后台记忆推演 (1-3秒)       │
│       │                                                      │
│       │ 推演完成                                              │
│       ▼                                                      │
│  [深度交互] → 使用个人记忆档案 (2-10KB)                      │
│       │                                                      │
│       │ 交互结束                                              │
│       ▼                                                      │
│  [升格存储] → 个人记忆档案独立存储                            │
│       │                                                      │
│       │ 随世界时间推进                                        │
│       ▼                                                      │
│  [持续更新] → 群体模拟基础更新 + 新互动追加                   │
│       │                                                      │
│       │ 长时间未交互                                          │
│       ▼                                                      │
│  [压缩] → 摘要保留 (关键信息不丢失)                           │
│       │                                                      │
│       │ 玩家再次交互                                          │
│       ▼                                                      │
│  [恢复] → 从摘要 + 群体数据重建当前状态                       │
│       │                                                      │
│       │ 记忆意外丢失                                          │
│       ▼                                                      │
│  [剧情杀] → 司命安排叙事化退场，不出现“失忆”现象             │
└─────────────────────────────────────────────────────────────┘
```


**一句话总结**：《开本》SLG中的群体角色采用三层记忆结构——种子档案（轻量身份+群体共享记忆）、交互时激活（过渡性行为+后台推演）、升格存储（交互后独立保存+可压缩不可销毁+丢失时剧情杀兜底）。这套系统让每一个被玩家触碰过的角色都能“记住”这段相遇，同时将存储成本控制在合理范围内。
