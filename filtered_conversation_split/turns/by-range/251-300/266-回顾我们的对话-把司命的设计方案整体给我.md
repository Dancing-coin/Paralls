# 司命 (Siming) 完整设计方案

## 一、核心定位

司命是 **《开本》运行时核心智能体**，是“开本宇宙”得以动态运转的心脏。

| 维度 | 说明 |
| :--- | :--- |
| **系统身份** | 运行时唯一拥有全局视野的智能体，独立于角色智能体运行 |
| **权限等级** | 高于角色智能体（可向角色发送消息），但**不直接控制玩家** |
| **核心使命** | 维护事实逻辑、催化叙事涌现、守护游戏平衡 |
| **行动原则** | 间接、不可见、逻辑自洽、公平 |
| **世界观称谓** | 司命——掌管每个平行世界的命运、因果与戏剧性的意识 |
| **本质定义** | 集编剧与导演于一身的世界主宰，实时创作并改写剧本 |
| **技术实现** | Harness编排框架 + 大模型(LLM) + 规则程序(Rule Engine) |


## 二、技术架构

### 2.1 三层结构

```
┌─────────────────────────────────────────┐
│          Harness (编排框架)              │
│  ┌─────────────────────────────────┐   │
│  │       大模型 (LLM)              │   │
│  │  - 复杂叙事推理                  │   │
│  │  - 动机分析与催化决策            │   │
│  │  - 干预策略生成                  │   │
│  └─────────────┬───────────────────┘   │
│                │                        │
│  ┌─────────────┴───────────────────┐   │
│  │     规则程序 (Rule Engine)      │   │
│  │  - 事实逻辑硬性检查              │   │
│  │  - 时间线管理                    │   │
│  │  - 天平系统数值计算              │   │
│  │  - 干预原则过滤                  │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

- **Harness**：负责请求路由、任务分级、兜底机制、延迟控制
- **大模型**：处理模糊复杂的叙事推理和创意决策
- **规则程序**：处理所有硬逻辑、数值计算和安全校验，保证可解释性和确定性

### 2.2 协作流程

1. 事件总线推送事件至Harness
2. Harness判断任务级别（P0-P4）：
   - P0致命 → 规则程序直接处理（<300ms）
   - P1-P3 → 大模型推理 + 规则程序校验
3. 决策生成后，规则程序进行逻辑和公平性校验
4. 通过校验后，由Harness发送至相应角色智能体或环境


## 三、内部架构（五个子系统）

```
┌─────────────────────────────────────────────┐
│                 司命 (Siming)                 │
│                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ 事实核心 │ │ 天平系统 │ │ 冲突与案件   │ │
│  │          │ │          │ │ 生成器       │ │
│  └────┬─────┘ └────┬─────┘ └──────┬───────┘ │
│       │             │              │         │
│  ┌────┴─────────────┴──────────────┴───────┐ │
│  │           高阶知识图谱引擎              │ │
│  └────────────────┬───────────────────────┘ │
│                   │                          │
│  ┌────────────────┴───────────────────────┐ │
│  │           干预执行器                    │ │
│  │  (冲动发送 / 环境催化 / NPC引导 / 节奏) │ │
│  └────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

### 3.1 事实核心

- **职责**：存储并守护游戏中所有不可变事实与已锁定事实
- **功能**：事实锁定时间线管理（T0→T1→T2→T3）、逻辑一致性检查、矛盾记录、信息泄露防护
- **写权限**：仅司命拥有对事实库的写权限

### 3.2 天平系统

- **职责**：实时监测游戏态势，防止出现碾压性优势或僵局
- **监测指标**：线索分布均衡度、阵营胜率预测、玩家参与度、游戏节奏
- **输出**：失衡警报 + 干预建议，发送给干预执行器

### 3.3 冲突与案件生成器

- **职责**：检测角色间动态冲突，条件满足时生成新案件
- **生成流程**：动机评估→能力评估→人格过滤→叙事价值评估→通过后锁定为新事实

### 3.4 高阶知识图谱引擎

- **职责**：维护所有参与者“知道什么”以及“知道别人知道什么”的动态模型
- **知识传播规则**：公开对话/展示→清晰区内标记为“公开”；私密对话→仅对话对象标记为“确认”；偷听→偷听者标记为“疑似”

### 3.5 干预执行器

- **职责**：将天平系统的失衡警报转化为具体干预行动
- **四层干预阶梯**：Lv1智能体冲动→Lv2环境催化→Lv3 NPC引导→Lv4节奏控制
- **审核机制**：所有干预方案需通过干预原则过滤器


## 四、干预原则过滤器

所有干预行为在发送前，必须通过四重原则检查：

| 原则 | 检查内容 | 不通过示例 |
| :--- | :--- | :--- |
| **间接性** | 是否直接控制玩家？ | 强制玩家移动、禁用玩家选项、替玩家做决定 |
| **不可见性** | 是否会被玩家感知为“系统干预”？ | 弹出系统提示、凭空出现物品 |
| **逻辑自洽** | 是否有合理的故事内解释？ | 让胆小如鼠的NPC去挑战凶手 |
| **公平性** | 是否偏袒某一方？ | 在凶手即将暴露时删除证据 |


## 五、暗杀催化机制

### 5.1 催化原则

只要检测到符合逻辑的动机，且催化不破坏游戏可玩性，司命就主动催化暗杀机会。

### 5.2 动机监测清单

| 动机类型 | 检测信号 | 强度判定 |
| :--- | :--- | :--- |
| **仇恨** | 人生记忆中存在对某角色的仇恨事件 | 仇恨对象在场即触发 |
| **灭口** | 某角色掌握了指向自己的关键证据 | 证据暴露风险越高，动机越强 |
| **自保** | 自己被怀疑值持续上升，即将被指认 | 怀疑值≥7时动机激活 |
| **保护他人** | 忠诚度≥8的对象面临威胁 | 威胁越紧迫，动机越强 |
| **秘密濒临暴露** | 核心秘密被他人掌握且即将公开 | 公开倒计时越短，动机越强 |

### 5.3 可玩性评估

| 评估维度 | 不通过条件 | 处理 |
| :--- | :--- | :--- |
| **阵营平衡** | 暗杀发生后，某一方胜率预测超过90% | 不催化 |
| **玩家体验** | 目标是唯一掌握关键线索的玩家 | 不催化，或先催化其他事件补充线索 |
| **节奏控制** | 游戏开始不足10分钟，或距投票不足3分钟 | 不催化 |
| **频率控制** | 同一角色已被催化过2次暗杀 | 不催化 |

### 5.4 催化流程

```
[司命持续扫描]
    ├── 检测到符合逻辑的动机 ✅
    ├── 可玩性评估通过 ✅
    ▼
[催化阶段一：条件排列] 环境催化/ NPC引导/ 信息延迟/ 空间巧合
    ▼
[催化阶段二：指引推送] 向潜在暗杀者推送暗杀机会面板
    ▼
[催化阶段三：弹窗确认] [执行暗杀] / [放弃]
```

### 5.5 催化后克制机制

冷却期、防御催化、上限控制（单局总暗杀事件不超过3起）、复盘透明。


## 六、与角色智能体的协作协议

| 消息方向 | 消息类型 | 说明 |
| :--- | :--- | :--- |
| 司命 → 角色 | `impulse` (冲动) | 模糊的行为倾向，角色自主决定是否响应 |
| 司命 → 角色 | `fact_reveal` (事实披露) | 告知角色其本应知道的事实 |
| 司命 → 角色 | `opportunity` (机会提示) | 暗杀等高风险行为的机会窗口信息 |
| 角色 → 司命 | `action_report` (行为报告) | 角色执行任何交互后上报 |
| 角色 → 司命 | `request_intervention` (请求干预) | 角色陷入困境时可请求建议（仅限AI角色） |

**核心原则：司命只催化，不控制。角色的所有行为最终由其自身的心智模型决定。**


## 七、自监控与动态调节

| 监控指标 | 阈值 | 过载处理 |
| :--- | :--- | :--- |
| **干预频率** | 每10分钟不超过3次Lv2+干预 | 暂停主动干预，进入观察模式 |
| **玩家困惑度** | 玩家重复搜索同一区域、大量疑问词出现 | 增加Lv1冲动引导 |
| **AI负载** | 引擎CPU/API调用延迟超标 | 降低干预精度 |
| **暗杀频率** | 单局催化超过2次 | 暂停暗杀机会排列，进入冷却 |


## 八、运行时位置

司命不直接与客户端交互，所有消息经由事件总线。与角色智能体处于同一层级，但拥有对事实库和知识图谱的独占写权限。

```
┌─────────────────────────────────────┐
│            游戏客户端 (Godot)        │
└──────────────┬──────────────────────┘
               │ 事件流
┌──────────────▼──────────────────────┐
│           事件总线                   │
└──┬──────┬──────┬──────┬─────────────┘
   │      │      │      │
   ▼      ▼      ▼      ▼
┌────┐ ┌────┐ ┌────┐ ┌─────────────┐
│玩家│ │AI  │ │AI  │ │ 司命        │
│    │ │角色│ │角色│ │ (核心智能体)│
└────┘ └────┘ └────┘ └─────────────┘
```


## 九、创作者可配置参数

| 参数 | 说明 | 可选值 |
| :--- | :--- | :--- |
| **干预强度** | 控制司命主动催化的程度 | 轻度 / 中度 / 重度 |
| **暗杀催化开关** | 是否允许司命催化暗杀机会 | 开启 / 关闭 |
| **节奏偏好** | 倾向快节奏还是慢节奏 | 偏快 / 平衡 / 偏慢 |

## 十、司命的三阶段能力分拆

### Phase 1：单局导演

**角色定位**：被动的规则守护者，确保单局内逻辑自洽。

| 子系统 | Phase 1 能力范围 | 延迟要求 |
| :--- | :--- | :--- |
| **事实核心** | ✅ 完整实现——T0-T3时间线管理、逻辑一致性检查、矛盾记录、信息泄露防护 | <50ms |
| **知识图谱** | ✅ 一阶/二阶知识追踪——A知道X、A知道B知道X | <100ms |
| **天平系统** | ✅ 基础监控——线索分布均衡度（仅监控，不主动干预） | <200ms |
| **冲突与案件生成器** | ❌ 不实现 | - |
| **干预执行器** | ❌ 不实现（司命不主动干预，仅做逻辑检查） | - |
| **暗杀催化** | ❌ 不实现（Phase 1无暗杀机制） | - |
| **种子库与续集承接** | ❌ 不实现（Phase 1无跨局叙事） | - |
| **结局判定** | ✅ 根据投票结果和关键证据判定结局 | <100ms |

**Phase 1 司命的技术规格**：
- 仅需规则程序即可完成所有职责，无需大模型推理
- 延迟要求宽松（所有操作<200ms）
- 无主动干预，不产生额外算力消耗

### Phase 2：系列导演

**角色定位**：主动的叙事催化者，管理跨局叙事连贯性。

| 子系统 | Phase 2 新增/升级能力 | 延迟要求 |
| :--- | :--- | :--- |
| **事实核心** | 与Phase 1相同 | <50ms |
| **知识图谱** | ✅ 升级为三阶知识——A知道B知道C知道X + 不确定态管理 | <100ms |
| **天平系统** | ✅ 完整实现——线索分布均衡度+阵营胜率预测+玩家参与度+游戏节奏监控→产出失衡警报 | <200ms |
| **冲突与案件生成器** | ✅ 完整实现——目标冲突检测+机会窗口检测+秘密濒临暴露检测→新案件生成流程 | 大模型推理<3000ms |
| **干预执行器** | ✅ 完整实现——四层干预阶梯（冲动/环境/NPC引导/节奏）+干预原则过滤器 | 大模型推理<3000ms |
| **暗杀催化** | ✅ 完整实现——动机监测+可玩性评估+条件排列+弹窗确认+催化后克制 | 大模型推理<3000ms |
| **种子库与续集承接** | ✅ 完整实现——剧本种子库存储+世界状态快照存储+变量衔接规则配置+个性化开局生成 | 大模型推理<3000ms |
| **结局判定** | ✅ 升级——多结局条件配置+基于实际进程的动态结局选择+隐藏结局触发 | <100ms |

**Phase 2 司命的技术规格**：
- 核心升级：大模型首次被引入，负责模糊推理和创意决策
- 规则程序负责所有硬逻辑和数值计算
- Harness编排框架管理两者的协作和超时降级
- 大模型推理目标延迟<3000ms（P2级别），超时由规则程序兜底

### Phase 3：世界说书人

**角色定位**：永续世界的推演者，管理宏大叙事与微观羁绊。

| 子系统 | Phase 3 新增/升级能力 | 延迟要求 |
| :--- | :--- | :--- |
| **事实核心** | 与Phase 2相同，新增世界级事件的持久化记录 | <50ms |
| **知识图谱** | ✅ 升级——支持百万级角色（L2交互角色）的知识状态简化追踪 | <100ms |
| **天平系统** | ✅ 升级——世界级平衡监控（城邦间力量对比、经济依赖度、联盟网络稳定性） | <500ms |
| **冲突与案件生成器** | ✅ 升级——世界级冲突生成（国家间战争、贸易禁运、联盟背叛） | 大模型推理<5000ms |
| **干预执行器** | ✅ 升级——世界级干预（自然灾害、资源发现、外部入侵）+群体事件催化（节日、瘟疫、迁徙潮） | 大模型推理<5000ms |
| **暗杀催化** | 与Phase 2相同（仅适用于剧本杀模式） | - |
| **种子库与续集承接** | 与Phase 2相同（适用于系列剧本） | - |
| **结局判定** | ✅ 升级——赛季制结局（记录每季重大事件和赢家）+世界历史编纂 | <100ms |
| **世界持续推演引擎** | ✅ 全新——时间推演（季节/天气/经济/社会事件）、事件链编织、双层身份叙事管理 | 规则程序持续运行 |
| **群体模拟管理** | ✅ 全新——L2角色生命周期管理（种子档案→按需注入→记忆升格→压缩→剧情杀兜底）、群体情绪和派系演化 | 规则程序持续运行+大模型定期推理 |
| **AI势力管理** | ✅ 全新——AI城邦/王国的战略决策驱动、AI领袖人格驱动的外交行为 | 大模型推理<5000ms |
| **主题世界配置** | ✅ 全新——支持大玩家配置世界级事件密度、司命干预强度、时间流速 | 配置接口 |

**Phase 3 司命的技术规格**：
- 规则程序负责持续运行的世界推演和群体模拟（7×24小时）
- 大模型负责定期的战略决策、事件生成、历史编纂（每小时/每天）
- Harness管理规则程序和大模型的异步协作
- 新增世界级事件生成和历史编纂的大模型推理，延迟容忍度更高（<5000ms）

---

**一句话总结**：司命从Phase 1的“被动逻辑守护者”到Phase 2的“主动叙事催化者”到Phase 3的“永续世界推演者”，其能力逐阶段递增。每个阶段都建立在前一阶段的技术基础上——Phase 1验证规则程序的可靠性，Phase 2引入大模型的创意决策能力，Phase 3将两者融合为7×24小时的世界级模拟引擎。
