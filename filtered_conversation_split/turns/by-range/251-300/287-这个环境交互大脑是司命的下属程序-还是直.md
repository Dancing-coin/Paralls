## 用户

这个环境交互大脑是司命的下属程序，还是直接作为司命的功能。

## DeepSeek

在《开本》的技术架构中，环境交互的“大脑”应该是一个独立于司命的、轻量级的专用子系统，而不是司命本身的功能。它与司命是协作关系——司命是“全局叙事导演”，它是“物理环境模拟器”。两者通过事件总线通信，各司其职。

---

## 一、为什么不能是司命的功能？

| 原因 | 说明 |
| :--- | :--- |
| **延迟要求不同** | 司命处理的是“秒级”的叙事决策，而火势蔓延需要“毫秒级”的实时响应。如果由司命统一处理，P0级的火焰蔓延会被司命的LLM推理延迟拖慢 |
| **算力消耗不合理** | 用大模型推理“火焰是否蔓延到窗帘2号”是对算力的极大浪费。这是确定性物理计算，不需要AI推理 |
| **职责边界混乱** | 司命的核心使命是叙事催化，不应该被环境物理状态的细节淹没 |
| **稳定性风险** | 如果司命因云端API波动而响应变慢，整个世界的物理交互都会卡住 |
| **可解释性** | 环境物理变化需要完全确定、可复现，规则程序天然具备这一点 |


## 二、正确架构：独立子系统 + 事件总线协作

```
┌─────────────────────────────────────────────────────────┐
│                司命 (Siming)                              │
│  叙事决策、催化、干预                                     │
│  “让火焰蔓延到地毯，制造更多混乱”                         │
└──────────────────────┬──────────────────────────────────┘
                       │ 高层指令 + 状态监听
                       ▼
┌─────────────────────────────────────────────────────────┐
│              环境状态管理器 (Environment State Manager)    │
│  确定性物理计算、状态机管理、事件上报                      │
│  “火焰蔓延速度=0.3m/s，窗帘1号将在30秒后烧毁”            │
└──────────────────────┬──────────────────────────────────┘
                       │ 结构化状态事件
                       ▼
┌─────────────────────────────────────────────────────────┐
│                   事件总线                               │
└─────────────────────────────────────────────────────────┘
```

### 2.1 环境状态管理器（ESM）的核心职责

| 职责 | 说明 | 技术实现 |
| :--- | :--- | :--- |
| **状态机管理** | 维护所有可交互物体的当前状态和转化规则 | 规则程序（C++/GDScript） |
| **物理模拟** | 计算火焰蔓延、流体扩散、物体破碎等确定性物理过程 | 规则程序 + Godot物理引擎 |
| **事件上报** | 当物体状态变化时，向事件总线发送结构化事件 | 规则程序 |
| **高层指令接收** | 接收司命的催化指令（如“让火焰蔓延到此位置”），在物理规则允许的范围内执行 | 事件总线订阅 |
| **查询接口** | 向角色智能体和司命提供环境查询服务（如“查询当前燃烧区域有哪些”） | API/事件总线 |

### 2.2 ESM的工作流程

```
[司命发出高层催化指令]
    │  "让火焰蔓延到地毯"
    ▼
[ESM接收指令]
    │  检查物理可行性：地毯在窗帘的蔓延范围内吗？→ 是
    │  执行状态机：地毯状态 = 燃烧
    │  计算蔓延时间：距离2米，蔓延速度0.3m/s → 约7秒后触发
    ▼
[ESM触发状态变化]
    │  加载火焰粒子特效、替换焦黑贴图
    │  向事件总线发送：Environment_State_Changed {Object: Carpet_01, State: Burning}
    ▼
[事件总线广播]
    ├── L2角色智能体感知过滤器接收：AI角色感知到“地毯着火了”
    └── 司命接收：更新事实核心，评估是否需要进一步催化
```


## 三、司命与ESM的协作方式

| 消息方向 | 消息类型 | 说明 |
| :--- | :--- | :--- |
| **司命 → ESM** | 高层催化指令 | “在区域X触发火灾”、“让门窗状态变为封死” |
| **ESM → 司命** | 状态变化通知 | “窗帘1号已烧毁”、“火势已蔓延至车厢B” |
| **司命 → ESM** | 状态查询 | “当前燃烧区域有哪些？”、“列车尾部窗户是否可开启？” |
| **ESM → 角色智能体** | 结构化环境事件 | “你看到附近有火焰”、“你闻到烟味” |

## 五、角色智能体的“大脑”——同样独立于司命

与此同理，角色智能体的心智模型（L1-L4）也是独立运行的子系统，不是司命的功能。司命只能通过`impulse`消息间接引导，而不能直接控制角色的行为。

| 子系统 | 核心职责 | 决策方式 | 延迟要求 |
| :--- | :--- | :--- | :--- |
| **司命** | 叙事催化、冲突生成、全局调度 | LLM + 规则程序 | 秒级 |
| **角色智能体** | 感知、理解、规划、执行 | LLM + 规则程序 + 人格过滤器 | 毫秒级（P0）~ 秒级（P2） |
| **环境状态管理器** | 物理模拟、状态机 | 纯规则程序 | 毫秒级 |


**一句话总结**：环境交互“大脑”是一个独立于司命的、纯规则驱动的子系统——环境状态管理器（ESM）。它处理毫秒级的确定性物理计算，司命通过高层指令和事件监听与它协作。两者通过事件总线解耦，各司其职。
