## 叙事引擎 (Narrative Engine) 设计文档

### 一、核心定位

叙事引擎是**运行时唯一拥有全局视野的智能体**。它不直接扮演任何角色，而是作为“世界法则的具象化”，守护故事的逻辑、戏剧张力与玩家的游戏体验。

在“无限书海”的世界观中，它被称为**“书海守护者” (Keeper of the Bibliotheca)**，是维持万千书页稳定存在的意识。

| 维度 | 说明 |
| :--- | :--- |
| **系统身份** | 运行时核心智能体，独立于角色智能体运行 |
| **权限等级** | 高于角色智能体，但不直接控制玩家 |
| **核心使命** | 维护事实逻辑、催化叙事涌现、守护游戏平衡 |
| **行动原则** | 间接、不可见、逻辑自洽、公平 |

---

### 二、内部架构

叙事引擎由五个子系统构成，协同工作。

```
┌─────────────────────────────────────────────┐
│              叙事引擎 (Narrative Engine)      │
│                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────────┐ │
│  │ 事实核   │ │ 天平     │ │ 冲突与案件   │ │
│  │ 心       │ │ 系统     │ │ 生成器       │ │
│  └────┬─────┘ └────┬─────┘ └──────┬───────┘ │
│       │             │              │         │
│  ┌────┴─────────────┴──────────────┴───────┐ │
│  │           高阶知识图谱引擎              │ │
│  └────────────────┬───────────────────────┘ │
│                   │                          │
│  ┌────────────────┴───────────────────────┐ │
│  │           干预执行器                    │ │
│  │  (冲动发送 / 环境催化 / NPC引导 / 节奏) │ │
│  └────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

#### 2.1 事实核心 (Fact Core)
- **职责**：存储并守护游戏中所有不可变事实与已锁定事实。
- **功能**：
  - 事实锁定时间线 (T0-T3) 管理
  - 逻辑一致性检查：任何角色言论、行为与事实库冲突时，标记并阻止
  - 矛盾记录：当两个角色说法矛盾时，标记为“待解决矛盾”，成为潜在推理线索
  - 信息泄露防护：确保角色智能体不能说出未知信息

#### 2.2 天平系统 (Balance System)
- **职责**：实时监测游戏态势，防止出现碾压性优势或僵局。
- **监测指标**：
  - **线索分布均衡度**：关键线索是否过于集中在某一方
  - **阵营胜率预测**：基于当前已揭露事实模拟投票结果
  - **玩家参与度**：是否有玩家被边缘化（长时间无交互/无新信息）
  - **游戏节奏**：推理进度过快/过慢
- **输出**：失衡警报 + 干预建议（发送给干预执行器）

#### 2.3 冲突与案件生成器 (Conflict & Case Generator)
- **职责**：检测角色间动态冲突，并在条件满足时生成新案件。
- **触发条件检测**：
  - 目标冲突：两个角色的目标层级产生不可调和矛盾
  - 机会窗口：某个角色获得作案机会（独处、凶器在旁）
  - 秘密濒临暴露：角色的核心秘密即将被揭穿，可能铤而走险
- **生成流程**：
  1. 动机评估 (调用角色的目标/恐惧层级)
  2. 能力评估 (物理空间中的可行性)
  3. 人格过滤 (角色真的会这么做吗？)
  4. 叙事价值评估 (是否让故事更有趣)
  5. 通过后锁定为新事实

#### 2.4 高阶知识图谱引擎 (Higher-Order Knowledge Engine)
- **职责**：维护所有参与者“知道什么”以及“知道别人知道什么”的动态模型。
- **数据结构**：知识图谱，节点为事实，边为角色对事实的知识状态 (未知/疑似/确认/公开) 以及高阶边 (A知道B知道X)
- **实时更新**：每次对话、展示、目击事件都会触发图谱更新
- **推理接口**：角色智能体决策时，可调用图谱获取其视角下的高阶知识

#### 2.5 干预执行器 (Intervention Executor)
- **职责**：将天平系统的失衡警报转化为具体干预行动。
- **干预阶梯** (由弱到强)：
  - **Lv1 智能体冲动**：向符合逻辑的NPC发送模糊冲动 (如“你突然想去地下室看看”)
  - **Lv2 环境催化**：改变场景状态 (如风吹开窗帘露出线索、天气突变困住众人)
  - **Lv3 NPC引导**：向NPC发送“确凿信息” (如唤醒记忆)，推动故事
  - **Lv4 节奏控制**：触发新事件延长或缩短游戏阶段
- **审核机制**：所有干预方案需通过干预原则过滤器 (间接、不可见、逻辑自洽、公平)，通过后才能执行。

---

### 三、干预原则过滤器

| 原则 | 检查内容 | 不通过示例 |
| :--- | :--- | :--- |
| **间接性** | 是否直接控制玩家？ | 强制玩家移动、禁用玩家选项 |
| **不可见性** | 是否会被玩家感知为“系统干预”？ | 弹出系统提示、凭空出现物品 |
| **逻辑自洽** | 是否有合理的故事解释？ | 让胆小的NPC去挑战凶手 |
| **公平性** | 是否偏袒某一方？ | 在凶手即将暴露时删除证据 |

---

### 四、与角色智能体的协作协议

叙事引擎与角色智能体通过**事件总线**通信，遵循严格的消息协议。

| 消息方向 | 消息类型 | 说明 |
| :--- | :--- | :--- |
| 引擎 → 角色 | `impulse` (冲动) | 模糊的行为倾向，如“你开始怀疑XX”。角色自主决定是否响应 |
| 引擎 → 角色 | `fact_reveal` (事实披露) | 告知角色其本应知道的事实 (如“你当时确实在走廊听到了争吵”) |
| 引擎 → 角色 | `state_query` (状态查询) | 请求角色当前心理状态，用于天平评估 |
| 角色 → 引擎 | `action_report` (行为报告) | 角色执行任何交互后上报，供引擎更新事实和知识图谱 |
| 角色 → 引擎 | `request_intervention` (请求干预) | 角色陷入困境时可请求建议 (仅限AI角色，且引擎不一定响应) |

**核心原则：引擎只催化，不控制。角色的所有行为最终由其自身的心智模型决定。**

---

### 五、运行时自监控与动态调节

叙事引擎具备自监控能力，防止自身过度干预。

| 监控指标 | 阈值 | 过载处理 |
| :--- | :--- | :--- |
| **干预频率** | 每10分钟不超过3次Lv2+干预 | 暂停干预，进入观察模式 |
| **玩家困惑度** | 玩家重复搜索同一区域、对话中出现大量疑问词 | 可能适当增加Lv1冲动引导 |
| **AI负载** | 引擎CPU/API调用延迟 | 降低干预精度，只保留必要的事实一致性检查 |

---

### 六、称谓与呈现

- **内部代号**：Narrative Engine (NE)
- **世界观称谓**：“书海守护者” (Keeper of the Bibliotheca)
- **创作者可见名称**：“叙事引擎” (Narrative Engine)
- **大玩家控制台中显示**：可调整“叙事引擎干预强度” (轻度/中度/重度)，实质是调节天平系统的敏感度和干预阶梯的启用级别。

---

### 七、叙事引擎在系统中的位置

```
┌─────────────────────────────────────┐
│            游戏客户端 (Godot)        │
└──────────────┬──────────────────────┘
               │ 事件流
┌──────────────▼──────────────────────┐
│           事件总线                   │
└──┬──────┬──────┬──────┬─────────────┘
   │      │      │      │
   ▼      ▼      ▼      ▼
┌────┐ ┌────┐ ┌────┐ ┌─────────────┐
│玩家│ │AI  │ │AI  │ │ 叙事引擎    │
│    │ │角色│ │角色│ │ (核心智能体)│
└────┘ └────┘ └────┘ └─────────────┘
```

叙事引擎不直接与客户端交互，所有消息经由事件总线。它与角色智能体处于同一层级，但拥有对事实库和知识图谱的独占写权限。

---

这个设计让叙事引擎从模糊的“导演”概念变成了一个架构清晰、职责明确、可配置的运行时核心智能体，既能守护游戏逻辑，又能催化精彩的叙事涌现。
