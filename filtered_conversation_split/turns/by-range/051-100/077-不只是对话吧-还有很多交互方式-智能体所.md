## 用户

不只是对话吧，还有很多交互方式，智能体所接收的视觉信息需要和人保持一致，但智能体一直靠截图来识别太费token了，我们还需要底层的交互方式，不过重点是和人保持一致。

## DeepSeek

你说得对。智能体不能靠截图来“看”世界，那样既低效又昂贵，而且与人接收信息的方式完全不同。

智能体和人的交互信息必须**同源但不同路**：人通过3D渲染的画面和声音来感知世界，智能体则通过**结构化的语义事件流**来感知同一个世界。

---

## 核心设计原则：语义感知替代视觉感知

| 对比维度 | 人类玩家 | AI智能体 |
| :--- | :--- | :--- |
| **视觉感知** | 眼睛看3D渲染画面 | 接收结构化的“可见对象列表”和“事件描述” |
| **听觉感知** | 耳朵听空间音频 | 接收结构化的“可听事件列表”（含距离、方向、清晰度） |
| **交互执行** | 键盘/手柄操作 | 系统调用相同的交互接口 |
| **信息源** | 同一套世界状态 | 同一套世界状态 |

**关键：智能体不截图，而是直接接收Godot场景中该智能体“应该能看到/听到”的结构化信息。**

## 一、智能体的感知通道设计

### 1.1 视觉感知通道

智能体客户端维护一个实时的“感知对象列表”，由Godot服务器根据场景状态持续推送更新。

**推送条件**：
- 对象在智能体的视野范围（前方一定角度内）
- 对象在智能体的视觉距离内（受光照、遮挡影响）
- 对象是“可感知”的（非隐藏状态）

**感知对象列表格式**：

| 字段 | 说明 | 例子 |
| :--- | :--- | :--- |
| `object_id` | 唯一标识 | `char_03`, `item_12` |
| `object_type` | 类型 | `character`, `item`, `door`, `window`, `container` |
| `object_name` | 可读名称 | “福尔摩斯”、“染血的烛台”、“书房的门” |
| `position` | 相对于智能体的位置 | `{x: 3.5, y: 0, z: 2.1}` (米) |
| `distance` | 距离 | `3.5m` |
| `state` | 当前状态 | 角色：“站立，正在说话”；门：“关闭”；物品：“在地板上” |
| `visible_actions` | 可对此对象执行的交互 | `[“交谈”, “观察”, “搜身”]` |
| `notable_features` | 值得注意的特征 | 角色：“面色苍白，右手有血迹”；物品：“上面刻着字母R” |
| `last_update` | 最后更新时间戳 | `2026-05-18T19:05:23Z` |

**更新机制**：
- 新对象进入视野 → 推送 `object_entered` 事件
- 对象离开视野 → 推送 `object_exited` 事件
- 对象状态变化 → 推送 `object_state_changed` 事件
- 每2-3秒全量同步一次（轻量心跳）

### 1.2 听觉感知通道

智能体接收结构化的“可听事件列表”。

**推送条件**：
- 声源在智能体的听觉半径内
- 考虑物理阻挡（门、墙衰减）

**听觉事件格式**：

| 字段 | 说明 | 例子 |
| :--- | :--- | :--- |
| `source_id` | 声源对象ID | `char_02` |
| `source_name` | 可读名称 | “华生医生” |
| `sound_type` | 类型 | `speech`, `footstep`, `door_open`, `item_drop`, `scream`, `explosion` |
| `content` | 如果是说话，内容是文本 | “我昨晚在书房看到了一个人影...” |
| `clarity` | 清晰度 | `clear` / `muffled` / `distant` / `barely_audible` |
| `distance` | 距离 | `5m` |
| `direction` | 方向 | `front-left`, `behind`, `above` |
| `emotion` | 说话者的情绪 | `nervous`, `angry`, `calm` |
| `timestamp` | 时间戳 | `2026-05-18T19:05:30Z` |

**清晰度判定规则**：

| 清晰度 | 条件 | 智能体获得的信息 |
| :--- | :--- | :--- |
| `clear` | 清晰区内，无遮挡 | 完整对话文本 + 情绪 + 说话者身份确认 |
| `muffled` | 模糊区 或 门后 | 关键词片段 + 模糊情绪 + 说话者身份“疑似” |
| `distant` | 远距离或墙后 | 仅知“有人在说话”或“有脚步声”，无内容 |
| `barely_audible` | 极远 | 仅知“有动静”，无法判断类型 |

### 1.3 事件感知通道

除了视觉和听觉，智能体还接收环境中发生的“非接触事件”。

| 事件类型 | 触发条件 | 智能体收到的信息 |
| :--- | :--- | :--- |
| **环境变化** | 灯光熄灭、窗户被风吹开 | `environment_changed: {type: "lights_out", location: "大厅"}` |
| **物品被移动** | 有人拾取或移动了物品 | `item_moved: {item: "烛台", from: "桌上", to: "某人背包"}` (仅当智能体当时在场景中且可视时) |
| **公共事件** | 尖叫、尸体被发现 | `public_event: {type: "scream", location: "书房", time: "19:05"}` |
| **状态变化** | 角色受伤、角色死亡 | `character_state_changed: {character: "玛丽", state: "injured"}` |

## 二、智能体的交互执行通道

智能体执行交互时，**调用与玩家相同的交互接口**。

| 交互类型 | 玩家操作 | 智能体执行方式 | 调用接口 |
| :--- | :--- | :--- | :--- |
| **移动** | WASD | 目标点路径规划 | `move_to(target_position, gait)` |
| **拾取物品** | 点击拾取 | 导航到物品位置 + 拾取 | `pickup_item(item_id)` |
| **使用物品** | 背包中使用 | 选择物品 + 使用 | `use_item(item_id, target)` |
| **对话** | 语音输入 | LLM生成文本 + TTS输出 | `speak(text, mode, target)` |
| **展示物品** | 点击展示 | 展示物品给目标 | `show_item(item_id, target_id)` |
| **开关门** | 点击门 | 导航到门 + 开关 | `toggle_door(door_id)` |
| **观察** | 聚焦观察 | 调用感知系统获取详情 | `observe(target_id)` → 返回 `notable_features` |
| **隐藏/躲藏** | 点击隐藏 | 移动到隐藏位置 + 进入隐藏状态 | `hide(hiding_spot_id)` |

**关键设计**：智能体执行任何交互，都会产生与玩家操作相同的事件广播。其他智能体和玩家通过各自的感知通道接收这些事件。

## 三、感知数据流架构

```
┌─────────────────────────────────────────────────────┐
│               Godot 场景服务器                        │
│  ┌──────────────────────────────────────────────┐   │
│  │          世界状态管理器                        │   │
│  │  - 所有对象的位置/状态                        │   │
│  │  - 物理碰撞/遮挡信息                          │   │
│  │  - 空间音频传播范围                           │   │
│  └──────────────────┬───────────────────────────┘   │
│                     │                               │
│  ┌──────────────────┴───────────────────────────┐   │
│  │          感知过滤器（Per-Character）          │   │
│  │  为每个角色计算：                             │   │
│  │  - 视野内可见对象列表                         │   │
│  │  - 听觉半径内可听事件列表                     │   │
│  │  - 环境事件列表                               │   │
│  │  考虑：距离、朝向、光照、遮挡、状态           │   │
│  └──────┬──────────────┬──────────────┬─────────┘   │
│         │              │              │             │
└─────────┼──────────────┼──────────────┼─────────────┘
          ▼              ▼              ▼
    ┌─────────┐    ┌─────────┐    ┌─────────┐
    │ 玩家A   │    │ 玩家B   │    │ AI智能体│
    │ 客户端  │    │ 客户端  │    │ 客户端  │
    │         │    │         │    │         │
    │ 3D渲染  │    │ 3D渲染  │    │ 语义    │
    │ 空间音频│    │ 空间音频│    │ 感知    │
    │         │    │         │    │ 数据    │
    └─────────┘    └─────────┘    └─────────┘
```

**感知过滤器是核心**：它为每个角色（无论人类还是AI）计算“此刻应该感知到什么”。人类客户端的输出是渲染画面和音频流，AI客户端的输出是结构化语义数据。两者基于完全相同的过滤逻辑。

## 四、智能体感知数据到决策的映射

智能体的L1感知层接收到的，不再是“像素”，而是这份语义事件流。L2理解层直接处理这些结构化数据。

| 感知数据 | L2理解层处理 |
| :--- | :--- |
| 看到“福尔摩斯，面色苍白，右手有血迹” | 推论：福尔摩斯可能受伤，或曾接触血迹。更新怀疑值 |
| 听到“玛丽用紧张的声音说：我什么都不知道” | 推论：玛丽可能在撒谎。情绪“紧张”与“无罪”不符 |
| 听到模糊区的“遗嘱...那天晚上...” | 推论：疑似有人在讨论遗嘱和案发当晚。标记为“疑似”知识 |
| 感知到“书房的门从关闭变为打开” | 推论：有人进入了书房。如果自己本应在书房，产生警觉 |
| 看到“染血的烛台在地板上” | 推论：这可能是凶器。如果自己知道这把烛台属于某人，更新推理链 |

## 五、人类与智能体感知的一致性保证

| 一致性维度 | 保证方式 |
| :--- | :--- |
| **能看到什么** | 同一套视野计算（距离+角度+遮挡），人类看到3D渲染，AI收到对象列表 |
| **能听到什么** | 同一套空间音频距离衰减计算，人类听到声音，AI收到听觉事件 |
| **清晰度一致** | 清晰区/模糊区/静默区的判定规则完全相同 |
| **状态同步** | 世界状态管理器是唯一真相源，所有客户端同步同一份状态 |
| **交互权限一致** | 同一套交互条件检查（距离、能力、状态） |

## 六、性能优化策略

| 策略 | 说明 |
| :--- | :--- |
| **增量更新** | 感知过滤器只在对象进入/离开/状态变化时推送更新，不持续全量同步 |
| **优先级排序** | 距离近的对象更新频率更高，远处的降低频率 |
| **批量推送** | 将多个小变化合并为一个批量更新消息 |
| **AI感知节流** | AI智能体的感知更新频率可略低于人类客户端刷新率，如每0.5秒推送一次（人类在60fps下每帧更新画面） |
| **不重要事件过滤** | 对叙事无影响的微小事态（如NPC眨眼）不生成语义事件 |

## 七、总结

智能体不截图，不识别图像。它们通过与人类完全同源的**结构化语义感知通道**来理解世界：

- **视觉** = 可见对象列表 + 显著特征
- **听觉** = 可听事件列表 + 清晰度分级
- **环境** = 环境变化事件 + 物品状态更新

这套系统让智能体在信息获取上与人类保持完全一致——它们看到的是人类能看到的东西的语义描述，听到的是人类能听到的声音的语义描述。而交互执行时，它们调用与人类完全相同的游戏接口。

**这既保证了公平性，又让智能体的决策有可追溯的逻辑链，同时避免了视觉识别的高成本和高延迟。**
