## DeepSeek

叙事引擎作为运行时核心智能体，其技术实现由 **Harness（编排框架）** 统一包装，内部由 **大模型（LLM）** 与 **规则程序（Rule Engine）** 协同驱动。

### 🧠 智能体构成

```
┌─────────────────────────────────────────┐
│          Harness (编排框架)              │
│  ┌─────────────────────────────────┐   │
│  │       大模型 (LLM)              │   │
│  │  - 复杂叙事推理                  │   │
│  │  - 动机分析与催化决策            │   │
│  │  - 对话策略生成                  │   │
│  └─────────────┬───────────────────┘   │
│                │                        │
│  ┌─────────────┴───────────────────┐   │
│  │     规则程序 (Rule Engine)      │   │
│  │  - 事实逻辑硬性检查              │   │
│  │  - 时间线管理                    │   │
│  │  - 天平系统数值计算              │   │
│  │  - 干预原则过滤                  │   │
│  └─────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

- **Harness**：负责请求路由、兜底、延迟控制，确保硬实时任务（如P0致命威胁）由规则程序立即处理，复杂任务由大模型推理，并管理超时回退。
- **大模型**：处理模糊、复杂的叙事推理，如“此刻催化哪个机会最具戏剧性？”“该NPC是否应产生怀疑冲动？”，输出结构化决策。
- **规则程序**：处理所有硬逻辑、数值计算和安全校验，如事实一致性检查、天平系统指标计算、干预原则过滤等，保证可解释性和确定性。

### 🔄 协作流程

1. **事件感知**：事件总线推送至Harness。
2. **任务分级**：Harness判断任务级别（P0-P4）。
   - P0致命 → 规则程序直接处理（<300ms）。
   - P1-P3 → 大模型推理 + 规则程序校验。
3. **决策生成**：大模型输出决策草案，规则程序进行逻辑和公平性校验。
4. **干预执行**：通过校验后，由Harness发送至相应角色智能体或环境。

这一定义已补充进叙事引擎设计文档的架构部分。
