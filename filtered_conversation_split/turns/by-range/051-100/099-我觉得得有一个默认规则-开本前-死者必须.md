我觉得得有一个默认规则，开本前，死者必须是npc（npc的定义为非参与者），局内发生暗杀才会导致参与者死亡。 局内必须有多个npc增强体验，npc可以是智能体驱动也可以是纯程序驱动，可以由剧本经营者也就是大玩家设置，但剧本本身会有硬性规则，有些npc对体验的重要程度必须使用智能体驱动。

## DeepSeek

# 默认规则：死者与NPC定义

## 一、核心规则

### 1.1 死者规则

| 规则项 | 内容 |
| :--- | :--- |
| **开本前死者** | 必须是NPC（非参与者），即初始案件的死者不得是任何真人玩家或AI智能体扮演的角色 |
| **局内暗杀死者** | 可以是任何角色——NPC、真人玩家、AI智能体 |
| **参与者定义** | 所有由真人玩家或AI智能体扮演的角色 |

**设计逻辑**：
- 初始案件的死者是NPC，确保所有参与者在游戏开始时都“活着”，都有完整的游戏体验
- 任何参与者都不会在开局就被剥夺游戏资格
- 局内暗杀导致的死亡，是玩家行为或智能体决策的结果，而非剧本的强制安排
- 这保证了“同一个剧本，每一次游戏都不同”的核心承诺

### 1.2 NPC定义与分类

| 类型 | 定义 | 驱动方式 | 示例 |
| :--- | :--- | :--- | :--- |
| **非参与者NPC** | 初始案件的死者、功能性角色 | 纯程序驱动 或 智能体驱动 | 初始死者、路人、仆人、商贩 |
| **参与者NPC** | 由AI智能体扮演的剧本角色 | 必须使用智能体驱动 | 嫌疑人、关键证人、侦探助手 |

---

## 二、NPC驱动方式的决策规则

### 2.1 剧本硬性规则

剧本创作者在编辑器中，可以为每个NPC设置**最低驱动要求**：

| 驱动要求 | 说明 | 适用场景 |
| :--- | :--- | :--- |
| **必须智能体驱动** | 该NPC对体验至关重要，大玩家不可降级 | 核心嫌疑人、关键证人、复杂人格角色 |
| **建议智能体驱动** | 降级会降低体验，但大玩家可自行决定 | 次要证人、边缘关联人 |
| **纯程序驱动** | 功能性角色，无需智能体 | 路人、仆人、初始死者 |

### 2.2 大玩家控制台配置

| 配置项 | 选项 | 说明 |
| :--- | :--- | :--- |
| **全局NPC驱动策略** | 全部智能体 / 按剧本规则 / 全部纯程序 | 大玩家可全局设置 |
| **单个NPC覆写** | 仅对“建议智能体驱动”和“纯程序驱动”的NPC可降级 | “必须智能体驱动”的NPC不可被覆写 |

---

## 三、局内NPC的数量与功能要求

### 3.1 最低NPC数量

| 剧本规模 | 最低非参与者NPC数量 | 说明 |
| :--- | :--- | :--- |
| 小型（4-5人） | 3-5个 | 含初始死者、1-2个关键证人、1-2个功能性NPC |
| 中型（6-7人） | 5-8个 | 含初始死者、3-4个证人/知情人、2-3个功能性NPC |
| 大型（8人以上） | 8-12个 | 含初始死者、多个证人、多个功能性NPC |

### 3.2 NPC的功能角色

| 角色类型 | 功能 | 驱动方式 |
| :--- | :--- | :--- |
| **初始死者** | 案件的核心，提供法医线索 | 纯程序（尸体状态） |
| **关键知情人** | 掌握关键线索，可被询问、威胁、收买 | 必须智能体 |
| **功能性NPC** | 提供场景服务（管家、厨师）、制造环境氛围 | 纯程序 |
| **动态知情人** | 游戏中因目击而获知，司命动态生成 | 智能体驱动 |
| **红鲱鱼** | 提供误导线索，增加推理难度 | 智能体或纯程序 |

---

## 四、参与者死亡规则

### 4.1 参与者死亡后的处理

| 死亡类型 | 处理方式 |
| :--- | :--- |
| **真人玩家死亡** | 转为旁观者模式，仍可观看游戏进程，但失去投票权和交互能力 |
| **AI智能体死亡** | 该智能体退出游戏，其所掌握的信息成为“永远消失的秘密”，但已有的对话记录和留下的物证保留 |

### 4.2 防止游戏过早结束

| 保护机制 | 说明 |
| :--- | :--- |
| **司命监控** | 如果暗杀导致某一方必败或推理链断裂，司命不催化该暗杀机会 |
| **最低参与者数** | 游戏至少需要3名存活参与者才能继续。低于3人时，司命触发“救援”或“提前投票” |

---

## 五、规则在剧本编辑器中的配置

### 5.1 NPC配置面板

| 配置项 | 说明 |
| :--- | :--- |
| NPC名称、身份 | 基础信息 |
| NPC类型 | 非参与者 / 参与者 |
| 驱动要求 | 必须智能体 / 建议智能体 / 纯程序 |
| 初始状态 | 存活 / 初始死者 |
| 关键信息 | 该NPC知道什么（写入事实数据库） |
| 人格配置 | 仅智能体驱动的NPC需要 |

### 5.2 大玩家控制台显示

- 剧本中所有NPC列表，标注驱动要求和当前驱动方式
- “必须智能体”的NPC不可更改，标注🔒
- 降级“建议智能体”NPC时，弹出体验风险提示

## 六、与现有系统的整合

### 6.1 对事实锁定时间线的影响

| 时间节点 | 调整 |
| :--- | :--- |
| **T0（剧本创作）** | NPC的驱动要求在此阶段由创作者设定 |
| **T1（房间创建）** | 初始案件框架随机生成，初始死者从一个或多个“非参与者NPC”中选定 |
| **T2（玩家加入）** | 凶手从AI智能体扮演的“参与者NPC”中随机选定，真人玩家被排除。初始死者已是NPC，不影响T2锁定 |
| **T3（游戏中）** | 暗杀可导致参与者（玩家或AI）死亡 |

### 6.2 对司命暗杀催化的影响

- 初始死者已是NPC，不参与暗杀动机检测
- 司命催化暗杀时，目标可以是任何存活角色（NPC、玩家、AI智能体）
- 若目标是“必须智能体”的NPC，其死亡可能对推理链产生重大影响，司命需额外评估可玩性

---

**总结：开本前，死者必为NPC；开本后，暗杀可致任何人死亡。这一规则确保了所有参与者的初始体验完整，同时为局内叙事涌现保留了充分空间。**
