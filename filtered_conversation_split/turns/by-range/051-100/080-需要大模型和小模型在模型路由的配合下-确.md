## 模型路由架构：大模型与小模型的分工协作

### 一、核心设计原则

| 原则 | 说明 |
| :--- | :--- |
| **硬上限保证** | 无论LLM负载如何，所有智能体响应必须在人类常规反应时间内完成（对话类≤3秒，威胁类≤300ms） |
| **小模型兜底** | 每个AI角色配备本地小模型，大模型超时则小模型立即接管 |
| **复杂度分流** | 简单对话走小模型，复杂推理走大模型，致命威胁走规则引擎 |
| **快可调慢** | 小模型反应太快时，可注入人工延迟来模拟自然停顿 |
| **慢不可忍** | 大模型超过硬上限，直接丢弃结果，小模型结果已发出 |

---

### 二、模型三层架构

```
┌─────────────────────────────────────────────────────────┐
│                    模型路由调度器                         │
│              （判断任务复杂度 + 实时负载 + 超时控制）     │
└──────────┬──────────┬──────────┬────────────────────────┘
           │          │          │
           ▼          ▼          ▼
    ┌──────────┐ ┌──────────┐ ┌──────────┐
    │ L1 规则   │ │ L2 小模型 │ │ L3 大模型 │
    │ 引擎     │ │ （本地）  │ │ （云端）  │
    │          │ │          │ │          │
    │ 延迟：   │ │ 延迟：   │ │ 延迟：   │
    │ 50-150ms │ │ 200-800ms│ │ 800-3000ms│
    │          │ │          │ │          │
    │ 处理：   │ │ 处理：   │ │ 处理：   │
    │ 本能反应 │ │ 常规对话 │ │ 复杂推理 │
    │ 固定模式 │ │ 简单推理 │ │ 策略规划 │
    │ 威胁响应 │ │ 信息确认 │ │ 长篇叙述 │
    └──────────┘ └──────────┘ └──────────┘
```

### 三、任务分级与模型分配

| 任务等级 | 任务类型 | 分配模型 | 硬上限 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| **P0 致命** | 暗杀意图感知、被突然攻击、发现尸体 | L1 规则引擎 | 300ms | 不经过模型推理，预置本能反应 |
| **P1 紧急** | 被出示关键证据、被公开指控、核心秘密濒临暴露 | L2 小模型（主）<br>L3 大模型（并行） | 1500ms | 小模型快速回应，大模型在后台生成更优回应，若及时则替换 |
| **P2 重要** | 被私下质问、发现重要线索、知情人提供情报 | L3 大模型（主）<br>L2 小模型（兜底） | 3000ms | 优先大模型，超时则小模型接管 |
| **P3 普通** | 闲聊、一般询问、日常互动 | L2 小模型（主）<br>L3 大模型（可选） | 2500ms | 小模型直接回应，大模型不参与 |
| **P4 背景** | 听到远处声音、看到他人移动、环境变化 | L1 规则引擎 或 忽略 | 0-100ms | 无需生成回应，仅更新感知状态 |

### 四、模型路由的决策流程

```
[感知事件到达]
    ↓
[紧急度评估] (<10ms)
  - P0致命？ → 直接L1规则引擎
  - P1紧急？ → L2小模型主回应，L3大模型并行备用
  - P2重要？ → L3大模型主回应，L2小模型设超时兜底
  - P3普通？ → L2小模型直接回应
  - P4背景？ → 静默更新状态
    ↓
[执行选定模型]
    ↓
[硬上限计时器启动]
    ↓
┌─ 硬上限到达前完成 → 返回结果，正常执行
└─ 硬上限到达仍未完成 → 兜底模型结果立即执行
    - 如果L3大模型超时 → L2小模型的兜底回应发出
    - 如果L2小模型也超时 → L1规则引擎的预设回应发出
```

---

### 五、兜底机制详解

#### 5.1 L3大模型超时 → L2小模型兜底

当L3大模型在硬上限时间内未完成推理时，L2小模型提前准备好的兜底回应立即发出。

| 情境 | L3大模型目标 | L2小模型兜底回应示例 |
| :--- | :--- | :--- |
| 被质问“昨晚你在哪” | 生成详细的不在场证明叙述 | “我...我需要想想。昨晚的事情有些模糊。” |
| 被出示关键证据 | 生成巧妙的解释或反击 | “这...这不是我的。我从未见过这件东西。”（符合人设的否认） |
| 发现重要线索 | 生成推理分析和后续计划 | “这个发现很重要。我需要再看看周围有没有其他线索。” |

**L2小模型的任务**：不是生成完美回应，而是生成**符合人设的、不泄露信息的、为L3争取时间的过渡性回应**。

#### 5.2 L2小模型也超时 → L1规则引擎兜底

极少数情况（如本地设备异常），L1规则引擎提供最后的兜底：

| 人格类型 | 超时兜底回应 |
| :--- | :--- |
| 高胆量+高理性 | “请稍等，我在思考这个问题。” |
| 低胆量 | “我...我不知道该说什么。” （后退一步） |
| 高心机 | 沉默，嘴角微动，做出思考的表情 |

### 六、并行竞速机制

对于P1和P2任务，L2小模型和L3大模型**同时启动**。

| 策略 | 说明 |
| :--- | :--- |
| **L2先回应** | 小模型快速生成回应，在硬上限时间到达时先行发出 |
| **L3后替换** | 如果L3大模型在回应发出后的短时间内（如500ms内）完成，且质量显著更高，可替换L2的回应。替换仅允许一次，且发生在角色尚未说出下一个字之前 |
| **L3补充** | 如果L3大模型在回应发出较长时间后才完成，不再替换，而是作为后续补充回应（如“等等，我再补充一点...”） |

**竞速窗口**：

```
[事件到达] 
  → L2小模型启动（目标800ms）
  → L3大模型启动（目标1500ms）
  
  T+800ms: L2结果就绪，但等待至硬上限
  T+1000ms: 硬上限到达，L2结果发出
  T+1200ms: L3结果就绪 → 检查是否可替换
    - 若L3质量更高 且 角色尚未继续说话 → 替换为L3结果
    - 若角色已说出L2回应 → 不再替换，L3作为后续补充
  T+2000ms: L3结果就绪 → 远超窗口，仅作为后续补充
```

### 七、小模型的技术选型

| 模型类型 | 规格 | 延迟 | 用途 |
| :--- | :--- | :--- | :--- |
| **本地小模型** | 1-3B参数，本地运行 | 200-800ms | 常规对话、兜底回应、过渡性话语 |
| **本地微调** | 用剧本杀对话数据微调 | - | 确保小模型能生成符合人设的简短回应 |

**小模型的能力边界**：
- ✅ 符合人设的简短回应（1-3句话）
- ✅ 基本的疑问和反问
- ✅ 过渡性话语（“让我想想”、“我不确定”）
- ✅ 情绪表达（恐惧、愤怒、悲伤）
- ❌ 复杂策略规划
- ❌ 长篇叙述
- ❌ 高阶推理

### 八、人类化延迟注入

当小模型反应过快时，注入人工延迟来模拟自然停顿。

| 注入规则 | 延迟量 |
| :--- | :--- |
| 简单问候（“你好”） | 注入至 500-800ms |
| 一般询问 | 注入至 1000-2000ms |
| 需要思考的问题 | 注入至 2000-3000ms |
| 紧急回应 | 不注入，越快越好 |

**注入方式**：在模型结果返回后、执行前，根据任务紧急度和人格参数计算所需的“自然停顿时间”，不足则补充延迟。

---

### 九、监控与动态调整

模型路由调度器持续监控所有智能体的响应延迟，并动态调整策略。

| 监控指标 | 动态调整 |
| :--- | :--- |
| **L3大模型平均延迟上升** | 增加P2任务降级为L2处理的比例 |
| **L3大模型超时率 > 10%** | 暂停L3处理P2任务，全部降级为L2，直到恢复 |
| **L2小模型延迟上升** | 减少并发L2推理数，增加L1规则引擎的覆盖范围 |
| **某智能体连续多次超时** | 该智能体暂时切换为“紧张/混乱”状态，行为模式更简单 |
