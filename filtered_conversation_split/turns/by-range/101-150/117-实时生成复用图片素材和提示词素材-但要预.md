## 修正后的实时任务处理策略

### 核心原则

**优先级排序**（从高到低）：

| 优先级 | 策略 | 说明 |
| :--- | :--- | :--- |
| **P0 (最高)** | **完美调用** | WOW时刻种子与当前剧情节点精确匹配，直接调用。这不是“复用”，而是这个剧情节点本就该有的视觉呈现 |
| **P1** | **种子微调** | 有相似种子，快速微调后使用 |
| **P2** | **实时全新生成** | 预估生成时间满足流畅性要求时，进行实时生成 |
| **P3** | **降级方案** | 生成时间不满足要求时，立即降级为通用占位或纯文字呈现 |

**关键原则**：P0优先于一切。P2必须预估时间，预估不通过直接跳P3。

---

### 预估生成时间机制

在触发实时生成前，系统必须先回答一个问题：**“生成这张图/视频需要多长时间？”**

| 预估因素 | 说明 |
| :--- | :--- |
| **模型负载** | 当前生成服务的排队任务数、GPU占用率 |
| **生成复杂度** | prompt长度、所需分辨率、是否视频（视频耗时远超图片） |
| **历史同类任务耗时** | 相似prompt的历史生成时间统计 |
| **当前网络延迟** | 模型服务与客户端的往返时间 |

**预估公式**：
```
预估耗时 = 排队时间 + 模型推理时间 + 传输时间
```

**硬性时间上限**：
- 图片生成：3秒
- 视频生成：不适用于实时（视频只走预生成或后台替换）

---

### 完整决策流程

```
[司命判定：此时刻需要WOW时刻]
    │
    ▼
[P0 精确匹配检查]
    │
    ├── 种子库中存在与当前剧本ID+故事线ID+节点ID精确匹配的WOW种子？
    │   ├── 是 → 完美调用，直接呈现（<100ms）
    │   └── 否 → 继续
    │
    ▼
[P1 相似种子检查]
    │
    ├── 存在相似种子（同剧本、同类型节点、相似prompt）？
    │   ├── 是 → 预估微调时间
    │   │   ├── 预估 ≤ 1.5s → 微调生成
    │   │   └── 预估 > 1.5s → 放弃P1，继续
    │   └── 否 → 继续
    │
    ▼
[P2 实时生成预估]
    │
    ├── 预估生成时间 ≤ 3s？
    │   ├── 是 → 启动实时生成 + 客户端子弹时间/动态转场
    │   └── 否 → 跳至P3
    │
    ▼
[P3 降级]
    │
    └── 立即呈现通用占位图或纯文字戏剧化提示
        └── 后台异步生成，完成后存入种子库供下次P0调用
```

---

### 完美调用（P0）的积累机制

P0的优先级最高，意味着我们需要最大化P0的覆盖率。这通过以下机制实现：

| 积累方式 | 说明 |
| :--- | :--- |
| **每次实时生成后归档** | 任何P1或P2生成的内容，完成后立即与当前故事线ID+节点ID绑定，存入种子库，成为未来P0的素材 |
| **后台批量预生成** | 开本前，司命预测本次可能触发的故事线分支，提前在后台生成对应的WOW时刻种子 |
| **高频故事线优先** | 推荐算法统计高频触发的故事线节点，对这些节点优先进行预生成和质量优化 |
| **跨剧本相似节点复用** | 不同剧本但同类型节点（如“发现尸体”），可共享部分素材，降低新剧本的冷启动成本 |

### 大玩家配置面板

| 配置项 | 说明 | 默认值 |
| :--- | :--- | :--- |
| **WOW时刻开关** | 是否启用L3视觉增强 | 开启 |
| **P0完美调用** | 始终启用，不可关闭 | 启用 |
| **P1微调生成** | 是否允许微调生成 | 开启 |
| **P2实时生成** | 是否允许实时全新生成 | 开启 |
| **实时生成配额** | 单局游戏P2实时生成的最大次数 | 3次 |
| **超时阈值** | P2预估生成时间的上限 | 3秒 |

---

### 总结

WOW时刻的调用策略，核心是**P0优先，P2预估，P3兜底**：

- **P0完美调用**是最高优先级，是体验的基线，越多越好
- **P2实时生成**必须预估时间，预估不通过立即降级
- 每次实时生成的结果都会反哺种子库，让未来的P0覆盖率越来越高
- 游戏流畅性永远不被牺牲
