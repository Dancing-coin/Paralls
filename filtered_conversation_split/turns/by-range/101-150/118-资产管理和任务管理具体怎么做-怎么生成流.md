## L3视觉增强层：资产管理与任务管理详细设计

L3视觉增强层是“开本”沉浸感的核心组件，它负责在关键时刻生成高质量图片或视频。为了实现“最高优先级完美调用，实时生成仅作补充且需预估时间，所有生成结果反哺种子库”的闭环，我们需要一套**分层资产管理**和**智能任务调度**系统。

---

### 一、L3资产管理：四层原子化体系

资产按**原子化程度**分层管理，越底层复用率越高，越上层体验越完整。所有资产都带有**内容指纹**和**剧情绑定信息**。

| 层级 | 名称 | 描述 | 例子 | 生成成本 | 绑定关系 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **L3-0** | **原子素材** | 透明背景的元素、独立的光影/纹理模板、提示词片段 | “一把染血的维多利亚匕首”、“悲伤眼睛光影模板”、“提示词：哥特式走廊” | 低（批量预生成） | 无剧情绑定，仅标签 |
| **L3-1** | **组件模板** | 由原子素材组合成的半成品，可直接用于合成 | “角色A愤怒表情组件”（五官+光影）、“雨夜街道背景”、“对峙场景构图” | 低（可预生成） | 弱绑定（题材、风格） |
| **L3-2** | **WOW时刻种子** | 与特定故事节点绑定的完整视觉内容 | 剧本《血字》-节点“发现尸体”的图片及其prompt、参数 | 高（实时生成） | 强绑定：`剧本ID+故事线ID+节点ID` |
| **L3-3** | **故事线合集** | 某一故事线所有WOW时刻种子的集合 | 《血字》-“玛丽是凶手”故事线的全部关键节点CG | 累积成本 | 完整故事线绑定 |

**资产管理原则**：
- **统一元数据**：所有资产附带标签（风格、时代、情绪、角色、物品类型等）。
- **内容指纹**：基于prompt、参数和图像hash生成唯一指纹，用于检索和去重。
- **来源追溯**：记录创作者（官方AI、玩家贡献）、授权方式、版本历史。

### 二、种子库结构：剧情绑定与快速检索

种子库是L3-2的核心存储，采用**剧情绑定索引**：

```
WOW种子记录：
{
  "seed_id": "seed_001",
  "fingerprint": "abc123...",
  "binding": {
    "script_id": "blood_letter",
    "timeline_id": "timeline_A_mary_guilty",
    "story_node_id": "node_discover_body"
  },
  "content_type": "image",
  "prompt": "一间维多利亚式书房，壁炉旁躺着一具男尸...",
  "style_template": "dark_gritty",
  "image_url": "https://...",
  "quality_score": 4.8,
  "reuse_count": 12
}
```

**索引维度**：
- **精确索引**：`剧本ID + 故事线ID + 节点ID` → O(1)直接命中（P0）。
- **模糊索引**：基于节点类型（“对峙”、“发现线索”）、角色、情绪等标签检索相似种子（P1）。
- **素材索引**：基于L3-0/1标签检索可组合的原子素材和组件。

### 三、任务管理与生成流程

任务管理器（Task Manager）是司命与生成服务之间的桥梁，它接收司命的WOW触发指令，执行**预估→决策→执行→归档**的闭环。

#### 1. 任务生成流程

```
司命触发WOW时刻（携带绑定信息、戏剧价值、prompt等）
        │
        ▼
  ┌─────────────────┐
  │  任务管理器      │
  │  0. 预估时间     │ ← 检查生成服务负载、复杂度
  └────────┬────────┘
           │
           ▼
  ┌─────────────────┐
  │  1. P0完美调用   │
  │  精确检索种子库  │
  └────────┬────────┘
           │ 命中？
           ├── 是 → 直接获取图片，<100ms呈现，记录复用。流程结束。
           └── 否 ↓
  ┌─────────────────┐
  │  2. P1种子微调   │
  │  模糊检索相似种子│
  └────────┬────────┘
           │ 找到相似？
           ├── 是 → 预估微调耗时 ≤ 1.5秒？
           │        ├── 是 → 发起微调生成 → 呈现（1-1.5秒）→ 归档为新种子
           │        └── 否 → 放弃微调，转P2
           └── 否 ↓
  ┌─────────────────┐
  │  3. P2实时全新生成│
  │  预估完整生成耗时│
  └────────┬────────┘
           │ 预估 ≤ 3秒（图片）？
           ├── 是 → 启动实时生成（客户端子弹时间配合）→ 呈现 → 归档为新种子
           └── 否 ↓
  ┌─────────────────┐
  │  4. P3降级方案   │
  │  即时呈现占位图  │
  └────────┬────────┘
           │
           ▼
      后台异步生成（若戏剧价值够高）→ 优化后更新种子库，替换占位图记录
```

#### 2. 预估时间模型

任务管理器在决定是否实时生成前，必须预估耗时：

```
预估总时间 = 排队延迟 + 推理时间 + 传输时间

- 排队延迟：当前生成服务GPU任务队列长度 × 平均任务时间
- 推理时间：基于模型基准（如SDXL 1.5秒/图）、生成步数、分辨率计算
- 传输时间：生成结果大小 / 带宽
```

若预估时间超过硬上限（图片3秒），则直接降级。

#### 3. 客户端配合（掩盖延迟）

当P1或P2生成时，客户端采用**子弹时间**和**转场特效**掩盖1-3秒延迟：
- 慢动作 + 景深变化 + 情绪光晕
- 先浮现文字提示（“你注意到一个致命的细节…”）
- 图像从模糊到清晰渐进呈现

### 四、L3与种子库协同：自适应进化闭环

每一次生成和调用，都会反哺种子库，形成持续进化：

1.  **完美调用（P0）**：被调用的种子`reuse_count`+1，提升质量评分。高频种子将获得**后台离线优化**资格（使用更强模型重新生成提升画质）。
2.  **微调/实时生成（P1/P2）**：生成结果自动记录prompt、参数和最终图像，与当前剧情节点绑定，成为新的WOW种子（赋予`seed_id`），直接入库。**下次开本遇到相同节点，即可P0完美调用**。
3.  **后台优化任务**：系统持续扫描低分种子（因当时紧急生成质量不佳），在后台用大模型重新生成，并替换原文件（旧版本仍可回溯）。
4.  **组件/素材库更新**：成功的生成结果会被拆解——提取干净的匕首素材、表情模板等，存入L3-0/1，供未来合成使用，形成**原子化复用**。
5.  **玩家贡献**：玩家在“本局相册”中可主动标记喜爱的AI生成图，经审核后加入种子库。

---

### 五、大玩家控制面板

大玩家可配置L3策略：

- **WOW开关**：全局开关。
- **生成配额**：单局P2实时生成次数上限（超出则只走P1/P3）。
- **成本偏好**：从“极致复用”（减少生成，倾向标准化体验）到“极致惊喜”（允许更多实时生成，独特体验但成本高）。
- **超时阈值**：可调实时生成超时上限（默认为3秒）。

---

### 六、总结

这套协同体系的核心思想是：**实时生成是奢侈的创作，其目的就是为了让那一刻成为永恒的种子。** 通过P0优先调用、P2预估降级和完整的归档流程，L3层既保证了游戏的流畅性，又在每一次开本中不断积累资产，使“WOW时刻”越来越丰富，成本越来越低，体验越来越好。
