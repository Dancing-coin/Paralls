## 用户

想要实现这样的实时演出，我们需要做到什么

## DeepSeek

要实现“司命实时写剧本 → 实时写控制脚本 → 角色智能体实时演 → 实时演算引擎完美呈现”这一终极闭环，我们需要在技术、资产和流程上实现以下关键能力：

---

## 一、司命：从叙事导演到技术导演的跃升

司命不再只是输出“让角色A悲伤”这样的模糊指令，而是直接输出**可被实时演算引擎执行的导演脚本**。

### 1. 导演脚本协议
定义一套结构化的JSON格式，描述一个完整的演出序列。

```json
{
  "sequence_id": "seq_confront_01",
  "duration": 8.0,
  "camera": {
    "shots": [
      {"time": 0.0, "type": "push_in", "target": "clue_knife", "duration": 2.0, "fov": 35},
      {"time": 2.0, "type": "cut", "target": "char_A", "shot_type": "closeup", "shake": "subtle"},
      {"time": 5.0, "type": "dolly", "path": "arc_around_AB", "duration": 3.0}
    ],
    "post_process": {"vignette": 0.4, "saturation": -0.2, "color_grade": "cold_blue"}
  },
  "characters": {
    "char_A": {
      "action": "react_shock",
      "blend_shape": {"fear": 0.8, "surprise": 0.6},
      "gaze_target": "clue_knife",
      "body_ik": {"right_hand": "point_at_clue"}
    },
    "char_B": {
      "action": "step_back",
      "blend_shape": {"guilt": 0.7, "fear": 0.4},
      "gaze_target": "char_A",
      "micro_expression": "lip_tremble"
    }
  },
  "environment": {
    "lights": {"main": 0.3, "spot_on_clue": 1.2, "color": "cold"},
    "weather": "rain_intensify",
    "physics": {"table": "slight_shake"}
  },
  "audio": {
    "music": "transition_to_tense",
    "sfx": ["heartbeat_fast", "clock_tick_loud"],
    "ambient": "wind_howl_increase"
  }
}
```

### 2. 脚本生成能力
司命需要具备以下能力，才能实时生成上述脚本：
-   **场景理解**：读取当前场景的拓扑结构、可用摄像机位置、灯光配置、角色位置。
-   **资产检索**：从资产库中快速找到可用的动作、表情、特效、音效。
-   **镜头语言知识**：内置基本的电影语法（正反打、过肩镜头、推拉摇移、景别切换）。
-   **节奏控制**：根据戏剧张力，动态调整演出时长和剪辑节奏。

### 3. 实时调整能力
在演出进行中，如果玩家做出了影响剧情的操作（如突然指认、打断对话），司命必须能够：
-   **中断当前演出**（带过渡动画，而非生硬切断）。
-   **生成新的分支脚本**，无缝衔接新的剧情走向。

## 二、角色智能体：从对话引擎到表演引擎

角色智能体需要将自己的内部状态，实时映射为司命可调用的表演参数。

### 1. 表演参数接口
每个角色智能体对外暴露一组标准化的表演参数，供司命的导演脚本直接引用：

| 参数类别 | 参数示例 | 驱动方式 |
| :--- | :--- | :--- |
| **身体动作** | `action`: "walk", "run", "step_back", "collapse" | 动画状态机 + 程序化动画 |
| **面部表情** | `blend_shape`: {"fear": 0.8, "anger": 0.2} | 形态键混合 |
| **眼神注视** | `gaze_target`: "char_B", "item_X", "avoid_eye_contact" | IK眼球追踪 |
| **口型同步** | `lip_sync`: 自动匹配当前TTS音频流 | 音频分析驱动 |
| **手势** | `gesture`: "point", "clench_fist", "open_arms" | IK手部控制 |
| **微表情** | `micro_expression`: "lip_tremble", "eye_twitch" | 高频形态键叠加 |
| **生理反应** | `physiology`: "sweat", "blush", "tremble" | 粒子效果 + 骨骼抖动 |

### 2. 实时映射规则
角色智能体的心智模型（压力值、情绪标签、信任/怀疑值、撒谎状态）会自动映射为上述表演参数。司命可以在此基础上叠加导演意图（如“此时需要更强的恐惧表现”），但不能违背角色的核心人格（高胆量者不会被强制表现崩溃）。

## 三、实时演算引擎：Godot的极限调用

Godot引擎需要具备以下能力，才能作为这个实时演出系统的执行终端：

### 1. 高性能渲染
-   支持多摄像机同步渲染（用于分屏、画中画）。
-   实时后处理效果切换（色调映射、景深、运动模糊）无性能尖峰。
-   动态光照和阴影的即时响应。

### 2. 程序化动画系统
-   动画状态机支持外部实时注入参数（如`fear`值直接驱动形态键）。
-   IK系统支持多目标动态切换（手部指向、眼球追踪、脚部贴合地面）。
-   物理模拟（布料、刚体）可在演出中被触发和控制。

### 3. 脚本化控制接口
-   为司命提供一个**实时控制API**，允许它在运行时：
    -   创建/销毁虚拟摄像机。
    -   切换摄像机并设置运镜路径。
    -   修改任何物体的材质参数、灯光颜色和强度。
    -   触发粒子效果和音效。
    -   向角色发送表演指令。

### 4. 无缝过渡
-   从自由游玩状态到演出状态，以及从演出状态返回自由游玩，必须有平滑的过渡动画（如镜头拉远再切入），避免生硬跳变。

---

## 四、资产库：原子化、可组合、可检索

实时演出的质量上限，直接取决于资产库的丰富程度和检索效率。

| 资产类型 | 原子化粒度 | 示例 |
| :--- | :--- | :--- |
| **动作片段** | 单个动作（2-5秒） | "震惊后退"、"愤怒拍桌"、"偷偷窥视" |
| **表情模板** | 单情绪形态键组合 | "恐惧70%+惊讶30%"、"悲伤50%+愤怒50%" |
| **摄像机预设** | 单镜头类型 | "特写-推近"、"双人过肩"、"环绕" |
| **灯光预设** | 单场景光照方案 | "烛光审讯"、"月光密室"、"暴风雨窗边" |
| **音效片段** | 单音效 | "心跳加速"、"钟表滴答"、"远处尖叫" |
| **粒子特效** | 单特效 | "烛火熄灭"、"玻璃碎裂"、"雨水流淌" |

**检索系统**：司命通过语义标签（如“恐惧+震惊+维多利亚时代”）在毫秒级内检索并组合这些原子资产。

## 五、低延迟通信架构

整个实时演出管线必须在极低延迟下运行：

| 环节 | 目标延迟 | 关键技术 |
| :--- | :--- | :--- |
| 司命判定触发WOW时刻 | < 100ms | 事件总线 + 预加载的规则引擎 |
| 司命生成导演脚本 | < 200ms | 模板化脚本 + 实时参数填充（LLM仅用于创意决策，不生成完整脚本） |
| 脚本传输至Godot | < 50ms | 本地进程间通信（若司命与引擎同机部署）或WebSocket |
| Godot执行第一帧渲染 | < 33ms | 预加载资产、预热着色器 |
| **总延迟** | **< 400ms** | 从触发到画面呈现的总时间 |

**关键**：司命不实时生成完整的LLM推理文本，而是：
1.  **预编译模板**：常见的演出模式（对峙、发现线索、情绪崩溃）都有预制的脚本模板。
2.  **实时参数注入**：司命只决定“谁、在哪、什么情绪、什么镜头”，填入模板的空白处。
3.  **LLM仅用于创意决策**：只有当模板无法覆盖的复杂叙事出现时，司命才调用LLM进行脚本创作，但此时不追求实时（可以用子弹时间掩盖延迟）。

## 六、预生成与缓存策略

并非所有演出都需要从零开始实时生成：

| 策略 | 适用场景 |
| :--- | :--- |
| **预编译模板** | 常见演出模式，脚本框架已存在 |
| **种子库复用** | 相同剧情节点已演出过，直接调用历史脚本 |
| **后台预生成** | 开本前，司命预测可能触发的分支，提前生成脚本 |
| **实时全新生成** | 涌现的新剧情、玩家独特行为触发的独一无二时刻 |

---

## 七、测试与迭代

1.  **导演模拟器**：开发一个内部工具，让设计师可以输入一个剧情场景，观察司命生成的导演脚本和实时演出效果，快速迭代。
2.  **自动回归测试**：每次更新资产库或司命逻辑，自动运行数百个预设场景，检测是否有演出异常。
3.  **玩家反馈闭环**：玩家在游戏结束后可标记“最震撼的演出时刻”和“出戏的演出时刻”，反哺司命的优化。

## 总结：实现路线图

| 阶段 | 目标 | 核心交付 |
| :--- | :--- | :--- |
| **Phase 1** | 基础实时演算 | Godot支持角色动作、表情、口型、基础摄像机切换 |
| **Phase 2** | 脚本化控制 | 司命输出结构化导演脚本，Godot可解析执行 |
| **Phase 3** | 原子资产库 | 建立动作、表情、摄像机、灯光预设库，支持语义检索 |
| **Phase 4** | 实时闭环 | 司命实时生成脚本，角色实时表演，引擎实时渲染，<400ms全链路 |
| **Phase 5** | 智能进化 | 种子库积累、模板优化、玩家反馈闭环、后台预生成 |

这就是《开本》从“动态剧本杀”到“实时即兴戏剧”的完整技术愿景。
