## DeepSeek

我们可以将整体开发划分为四个阶段，每个阶段都有明确的目标、交付物和团队配置，由核心到外围逐步构建。

---

## 总体开发路线图

### Phase 0：原型验证（1-2个月）

**目标**：用最小成本验证“智能体驱动3D对话”的核心体验是否成立。

**核心交付**：
- 一个单场景（如书房），包含基础3D资产和光照。
- 2个AI角色，可进行实时对话（文本输入+语音输出）。
- 基础空间音频（玩家靠近/远离能听到不同音量）。
- 1个可交互物品（点击后生成线索特写，调用你的图片工作流）。
- 一个简易司命原型：确保AI角色不说出未知信息。

**团队配置**：
- 1名Godot开发者（搭建场景、角色、音频、交互）
- 1名AI工程师（对接LLM、TTS、简单知识库）
- 你（提供L3图片生成接口）

**里程碑**：录制一段视频——玩家走进书房，AI角色主动打招呼，玩家打字质问，AI语音回答，玩家点击桌上物品后浮现一张AI生成的线索图。若体验流畅，则继续。

---

### Phase 1：MVP核心闭环（6个月）

**目标**：交付首个可玩剧本《血字的研究·变奏》，验证动态叙事核心。

**核心交付**：
- 完整客户端：两个3D场景、空间音频、物品交互、信息共享、投票。
- 完整剧本：5角色（2真人+3AI），案件规则、线索系统、人格档案。
- 角色智能体引擎：人格加载、三道过滤器、动态状态、自主行为。
- 司命核心：事实数据库、逻辑检查、知识图谱、基础天平。
- 房间系统：创建/加入、角色锁定、T0-T2事实坍缩。
- L3基础版：预生成角色立绘，线索特写实时生成。

**不包含**：剧本编辑器、大玩家控制台、暗杀机制、迷宫、区块链。

**团队配置**：
- 2名Godot开发者（客户端框架、UI、动画状态机、L3 Manager）
- 1名后端工程师（房间管理、状态同步、事件总线）
- 2名AI工程师（智能体引擎、司命、模型路由、TTS集成）
- 1名技术美术（场景建模、光照、角色绑定）
- 你（L3工作流对接，预生成资产）
- 1名剧本设计师（编写《血字》人格、线索、案件规则）

**里程碑**：
1. 第2个月：两个场景可探索，角色可移动和交互。
2. 第3个月：AI角色能对话和自主移动，空间音频运行。
3. 第4个月：完整的案件流程跑通（线索→推理→投票→结局）。
4. 第6个月：外部玩家测试，收集反馈。

---

### Phase 2：深度机制与创作者工具（6-12个月）

**目标**：解锁暗杀、伪装等深度机制，交付剧本编辑器Alpha。

**新增交付**：
- 暗杀机制完整实现（条件检测、阶段化感知、弹窗、痕迹生成）。
- 伪装系统（公开/真实档案、物理道具、知情人网络）。
- 迷宫与时空机制（空间重映射、时间循环、多重时间线）。
- 剧本编辑器Alpha：角色编辑、场景编辑、案件规则配置。
- 大玩家控制台Alpha：服务器部署、剧本策展、简单规则微调。
- 第二个官方剧本（如《白蛇传·浮生》）。

**团队扩展**：
- 增加1名前端工程师（编辑器UI）
- 增加1名工具开发者（编辑器与引擎集成）
- 增加1名系统策划（机制平衡与测试）

**里程碑**：内部创作者能用编辑器制作一个简单剧本并成功运行。

---

### Phase 3：生态与扩展（12-24个月）

**目标**：开放创作者生态，实现商业闭环。

**新增交付**：
- 资产市场（剧本、角色、场景交易）
- 区块链确权与智能合约分账
- Fork与版本管理系统
- 大玩家服务器完整解决方案（一键部署、GM工具箱、经营分析）
- 更多官方平行世界和剧本
- 跑团模式、派对游戏模式等扩展类型

**团队扩展**：
- 增加2名后端/区块链工程师
- 增加1名安全工程师
- 增加社区运营团队

## 关键技术栈建议

| 层次 | 推荐技术 |
| :--- | :--- |
| **L1 客户端** | Godot 4.x (GDScript + C++) |
| **空间音频** | Godot内置音频引擎 + Steam Audio插件 |
| **L2 后端** | Go / Rust (房间管理、事件总线) |
| **L2 AI** | Python (模型路由、智能体引擎) + llama.cpp/本地小模型 + 云端LLM API |
| **TTS** | 自部署XTTS/Edge-TTS或商业API，支持情绪参数和流式输出 |
| **STT** | Whisper流式识别 |
| **L3** | 你现有的图片/视频生成工作流，封装为API |
| **数据存储** | PostgreSQL (事实库、用户数据) + Redis (房间状态缓存) + 向量数据库 (角色记忆) |
| **消息队列** | RabbitMQ / NATS (事件总线) |
| **区块链** | Polygon/Ethereum L2 (资产确权、智能合约) |

## 风险与应对

| 风险 | 应对措施 |
| :--- | :--- |
| LLM延迟过高 | 模型路由+小模型兜底+流式输出+预生成缓存，确保硬上限 |
| 3D交互与AI协同复杂 | Phase 0先行验证，定义清晰的事件总线和消息协议 |
| 剧本内容生产瓶颈 | 先在Phase 2交付编辑器，用官方剧本测试工具链，再开放给创作者 |
| 用户接受度不确定 | 每个Phase结束都进行真人测试，及时调整设计 |
| 成本控制 | L3生成使用预生成+缓存，LLM调用优先本地小模型，云端大模型用于高价值场景 |

## 下一步行动

1. **立即启动Phase 0**：搭建最简Godot场景，接入一个LLM，让角色能说话，让你自己或一位朋友体验一次“与AI角色的3D对话”。
2. **并行启动L1资产生产**：技术美术开始制作《血字》的两个场景和5个角色模型（白模即可，后续细化）。
3. **定义事件总线协议**：后端和AI工程师共同制定L1→L2→L1的JSON消息规范，这是后续所有协同的基础。

这样，我们就有了一条从“一个人走通”到“一个团队交付”再到“一个生态繁荣”的清晰路径。
