# 开本 (Paralls) 完整开发规划


## 一、项目概述

开本是一个智能体驱动的3D沉浸式动态叙事平台，首款产品形态为多人动态剧本杀。整个系统分为三层架构，约需核心开发团队11-14人，预计18-24个月完成完整版本。


## 二、总体架构

开本系统从底层到上层共分为七层，每层依赖下层提供的服务：

| 层级 | 名称 | 技术选型 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **L0** | 数据与基础设施层 | PostgreSQL, Redis, 向量数据库, RabbitMQ/NATS, IPFS | 持久化存储、高速缓存、消息队列、链上存证 |
| **L1** | 确定性空间层 | Godot 4.x, Steam Audio | 3D场景渲染、物理碰撞、空间音频、玩家交互、事件埋点 |
| **L2** | 智能体交互层 | Python, llama.cpp, 云端LLM API, XTTS, Whisper | 角色智能体心智模型、司命叙事引擎、对话生成、模型路由 |
| **L3** | 视觉增强层 | 图片/视频生成工作流 API | 线索特写、记忆闪回、公共事件渲染、结局CG |
| **L4** | 剧本与规则层 | 规则引擎, 案件生成器 | 案件规则、线索系统、胜利条件、剧本配置解析 |
| **L5** | 平台与工具层 | Web前端, Docker | 剧本编辑器、大玩家控制台、Fork管理、资产市场 |
| **L6** | 商业与生态层 | Polygon/Ethereum L2, 智能合约 | 链上确权、自动分账、治理代币、IP议会 |


## 三、各层详细开发规划

### L0：数据与基础设施层

**职责**：为上层提供持久化存储、高速缓存、消息传递和链上存证服务，是整个系统的数据基座。

#### 3.0.1 数据库系统

**事实数据库 (PostgreSQL)**
- 存储所有平行世界的设定、剧本数据、角色档案、案件事实
- 管理T0-T3事实锁定时间线
- 记录所有游戏事件日志，用于复盘和分析

**状态缓存 (Redis)**
- 缓存活跃游戏房间的实时状态（角色位置、物品位置、动态关系参数）
- 管理会话和断线重连状态
- 模型路由的负载信息和任务队列

**向量数据库 (Vector Database)**
- 存储角色人生记忆的向量化表示，用于高效检索相关记忆
- 存储对话历史的语义索引，用于上下文组装
- 存储线索和证据的语义特征，用于推理辅助

#### 3.0.2 消息队列系统 (RabbitMQ/NATS)

**事件总线核心**
- L1→L2的结构化事件流（玩家行为、环境变化）
- L2→L1的行动指令流（AI角色动作、司命干预）
- L2→L3的视觉增强触发消息
- L3→L1的视觉内容推送消息
- 事件持久化和重放机制（用于复盘和测试）

#### 3.0.3 文件与资产存储

- 3D模型、贴图、音频等大文件存储（对象存储服务）
- 资产版本管理系统
- 预生成的L3视觉内容缓存
- 链上IPFS存储（资产内容指纹和元数据）

#### 3.0.4 账号与权限系统

- 用户注册/登录（支持Web3钱包登录）
- 角色权限管理（普通玩家/创作者/大玩家/Fork开发者/管理员）
- API密钥管理和调用限流

#### 3.0.5 监控与日志

- 系统健康监控（各层延迟、错误率、负载）
- 游戏房间实时监控面板
- AI调用统计和成本追踪
- 异常告警和自动恢复机制

---

### L1：确定性空间层 (Godot)

**职责**：提供3D世界的实时渲染、物理模拟、空间音频和玩家交互，同时将游戏事件以结构化形式上报。

#### 3.1.1 场景管理

- 场景加载与卸载（支持多场景切换和并行加载）
- 场景状态管理（物品位置、门状态、光源状态等）
- 动态场景更新（支持司命的环境催化指令，如天气变化、灯光故障）
- 场景预览和快速旅行（开发调试用）

#### 3.1.2 角色系统

- 第一人称/第三人称视角切换
- WASD移动 + 鼠标/手柄视角控制
- 移动姿态切换（行走/奔跑/潜行/蹲伏），影响脚步声和被感知范围
- 角色模型加载、动画状态机（行走/奔跑/待机/说话/情绪表达/交互动画）
- 表情系统（配合情绪标签的口型、眉毛、眼神变化）

#### 3.1.3 空间音频系统 (Steam Audio)

- 音频源与3D角色实时绑定
- 距离衰减（清晰区/模糊区/静默区）
- 物理阻挡（门、墙对声音的遮挡效果）
- 耳语模式（临时缩小传播半径）
- 环境混响（不同空间的不同声音反射特性）
- 环境噪音管理（雨声、风声、壁炉等动态声源的混音）

#### 3.1.4 交互系统

- 交互准星（对准目标时高亮，区分可交互类型）
- 物品拾取/检查/使用/展示/移交/丢弃
- 门的开关（带动画和声音传播效果变化）
- 光源交互（点燃/熄灭蜡烛、开关电灯）
- 隐藏/躲藏机制（进入柜子、窗帘后）
- 留影石/相机（第一人称截图，存入背包）
- 窃听机制（靠近门/墙时的声音增强）

#### 3.1.5 UI系统

- 常驻HUD：状态栏、任务提醒、小地图、交互动作栏
- 专项面板：背包、档案、笔记推理、辅助面板
- 设置面板：音频、视频、操作、语言、变声器（不可关闭）、文字润色（可关闭）
- 语音交互界面：说话模式切换、语音状态指示、附近说话人列表
- 暗杀弹窗（条件满足时）
- L3视觉内容呈现（画中画/全屏过渡/本局相册）

#### 3.1.6 事件埋点系统

**这是L1与传统3D游戏最大的区别——所有游戏行为必须转化为结构化事件上报L2。**

需要在以下模块中嵌入事件上报代码：
- 玩家移动（位置变化超过阈值时）
- 玩家对话（语音输入完成时）
- 物品交互（拾取/使用/展示/移交时）
- 场景交互（开关门/开关灯/隐藏时）
- 暗杀相关（意图/执行/完成各阶段）
- 环境感知（玩家进入新区域、发现尸体、目击事件）

#### 3.1.7 L3 Manager 模块

- 监听事件总线中的关键事件
- 接收L2司命的L3触发指令
- 管理预生成内容缓存（角色立绘、场景概念图、通用线索图）
- 调用L3 API进行实时生成（线索特写、记忆闪回等）
- 在3D场景上以画中画/全屏过渡形式丝滑呈现L3内容
- 管理L3内容的淡入淡出、点击关闭、保存至本局相册

#### 3.1.8 AI指令接收器

- 接收L2下发的角色行动指令（移动/说话/动画/情绪/交互）
- 驱动3D角色执行对应行为
- 将执行结果回传L2

### L2：智能体交互层

**职责**：驱动所有AI角色的行为和全局叙事逻辑，是开本最核心的智能层。

#### 3.2.1 角色智能体引擎

**人格数据库**
- 五维人格参数（胆量/心机/共情/理性/社交）的加载和管理
- 品格层参数（诚实/忠诚/正义感/仁慈/责任感）和价值观优先级
- 目标层级和恐惧层级的结构化存储
- 语言风格配置（称谓习惯/句式特征/话题偏好/撒谎特征/情绪表达方式）
- 行为禁忌列表

**人生记忆系统**
- 基因种子参数（出身/天赋/早年关键事件）
- 由基因种子模拟生成完整人生记忆的生成器
- 人生记忆的结构化存储（关键事件/长期状态/创伤/重大选择/关键人物）
- 人生记忆到品格层再到行为层的单向推导系统

**心智模型（四层）**
- L1感知层：接收L1上抛的结构化事件，过滤噪音
- L2理解层：真实性评估、相关性评估、推论生成、信念更新
- L3规划层：基于动机（恐惧/目标/社交/好奇）生成候选行动，人格过滤
- L4执行层：生成具体对话文本、动作指令、状态更新，下发给L1

**人格过滤器（三重验证）**
- 人设过滤器：角色“会”这么做吗？
- 逻辑过滤器：行为在故事里“合理”吗？（能力/时空/信息约束）
- 得失过滤器：这么做对角色“有利”吗？（目标/恐惧计算）

**动态状态管理**
- 压力值（0-10，影响理性程度和冲动行为概率）
- 信任值（针对每个对象，影响信息分享意愿）
- 怀疑值（针对每个对象，影响指控倾向）
- 情绪标签（当前主导情绪，影响决策偏向和语言风格）
- 特殊状态（中毒/致幻/醉酒/PTSD等）

**自主行为系统**
- 自主移动（基于目标层级的路径规划）
- 主动对话（基于关系网络和当前局势的对话发起）
- 物品交互（基于目标或叙事需要的环境互动）
- 观察与跟踪（基于怀疑值的可疑对象监控）
- 应急反应（突发事件的快速响应）

**伪装系统**
- 公开档案管理（可编辑的身份面具）
- 真实档案管理（仅自己可见）
- 伪装深度控制（零/浅层/中度/深度）
- 伪装压力计算（道德冲突+逻辑维持+外部质询+时间）
- 伪装破绽生成（语言风格偏离+逻辑漏洞）
- 伪装道具管理（物理道具的存在、销毁、记录）

#### 3.2.2 司命 (叙事引擎)

**技术架构**
- Harness编排框架（请求路由、任务分级、兜底、延迟控制）
- 大模型组件（复杂叙事推理、动机分析、催化决策）
- 规则程序组件（事实逻辑检查、时间线管理、天平数值计算、干预原则过滤）

**事实核心**
- T0-T3事实锁定时间线管理
- 逻辑一致性检查（所有角色言行与事实库比对）
- 矛盾记录和标记（两个角色说法矛盾→“待解决矛盾”）
- 信息泄露防护（确保角色不能说未知信息）
- 案件框架生成（T1/T2的随机抽取和锁定）

**天平系统**
- 线索分布均衡度监控
- 阵营胜率预测（基于已揭露事实的模拟投票）
- 玩家参与度监控（是否有玩家被边缘化）
- 游戏节奏监控（推理进度过快/过慢）
- 失衡警报生成+干预建议

**冲突与案件生成器**
- 目标冲突检测（两个角色的目标层级产生不可调和矛盾）
- 机会窗口检测（角色获得作案机会）
- 秘密濒临暴露检测（核心秘密即将被揭穿）
- 新案件生成流程：动机评估→能力评估→人格过滤→叙事价值评估→锁定为新事实
- 意外失控事件生成（本意非致命的冲突导致意外结果）

**高阶知识图谱引擎**
- 知识状态定义：未知/疑似/确认/公开
- 一阶知识（A知道X）→二阶知识（A知道B知道X）→三阶知识（A知道B知道A知道X）
- 不确定态管理（A不确定B是否知道X）
- 知识传播规则（公开对话→公开；耳语→共有；展示→确认等）
- 实时更新（每次对话、展示、目击都触发更新）
- 推理接口（角色决策时获取其视角下的高阶知识）

**干预执行器**
- 干预原则过滤器（间接/不可见/逻辑自洽/公平，四重检查）
- 四层干预阶梯：
  - Lv1 智能体冲动（向NPC发送模糊行为倾向）
  - Lv2 环境催化（改变场景状态）
  - Lv3 NPC引导（向NPC发送确凿信息）
  - Lv4 节奏控制（触发新事件调整游戏阶段）
- 与角色智能体的消息协议（impulse/fact_reveal/opportunity）

**暗杀催化机制**
- 动机监测：仇恨/灭口/自保/保护他人/秘密濒临暴露
- 可玩性评估：阵营平衡/玩家体验/节奏控制/频率控制
- 条件排列：环境催化+ NPC引导+ 信息延迟+ 空间巧合
- 弹窗确认：向扮演者推送暗杀机会面板（仅自己可见）
- 催化后克制：冷却期/防御催化/上限控制/复盘透明

**结局判定系统**
- 正义伸张/真凶逃脱/冤案/全员覆灭/隐藏结局的条件判定
- 基于实际游戏进程的动态结局选择
- 本局故事报告的自动生成

**自监控与动态调节**
- 干预频率监控（每10分钟≤3次Lv2+）
- 玩家困惑度检测
- AI负载监控
- 暗杀频率控制（单局≤3起）
- 过载时的自动降级处理

#### 3.2.3 对话生成系统

**对话生成流程**
- 输入：玩家语音→STT转文字→意图解析（说话对象/意图类型）
- 上下文组装：人格参数+知识图谱切片+对话历史摘要+当前状态+感知环境
- LLM生成：生成符合人设、符合知识状态、符合情绪的回应文本
- 人格过滤：检查回应是否通过三重验证
- 输出：对话文本+情绪参数（用于TTS）+肢体动作标签

**语音系统**
- 语音转文本 (STT)：Whisper流式处理，静音检测
- 文本转语音 (TTS)：XTTS/Edge-TTS，角色专属声线+情绪注入+流式合成
- 变声器：玩家端实时变声，根据角色档案自动配置参数（不可关闭）

**对话优化策略**
- 预生成候选回应（预测对话走向，提前生成3-5条）
- 模板缓存（高频通用对话使用缓存）
- 流式输出（LLM逐token返回，TTS边接收边合成）
- 动作先行（决策完成后立即发送动作指令，文本/语音随后）

#### 3.2.4 模型路由系统

**三层架构**
- L1规则引擎（50-150ms）：处理本能反应、威胁响应、固定模式
- L2本地小模型（200-800ms）：处理常规对话、简单推理、兜底回应
- L3云端大模型（800-3000ms）：处理复杂推理、策略规划、长篇叙述

**任务分级**
- P0致命（300ms硬上限）：暗杀意图感知、被突然攻击→L1规则引擎
- P1紧急（1500ms硬上限）：被出示证据、被公开指控→L2主+L3并行
- P2重要（3000ms硬上限）：被私下质问、发现重要线索→L3主+L2兜底
- P3普通（2500ms硬上限）：闲聊、一般询问→L2小模型
- P4背景（0ms）：远处声音、他人移动→静默更新

**兜底机制**
- L3超时→L2兜底回应立即发出
- L2也超时→L1预设回应
- 兜底回应符合人设（过渡性话语，不泄露信息，为后续争取时间）

**人格对延迟的调节**
- 高理性：推理更谨慎，延迟+20-50%
- 低理性：凭直觉反应，延迟-30-50%
- 高压力(≥7)：本能反应权重增加，LLM推理时间减少
- 随机抖动：±10-20%模拟人类思考的不可预测性

#### 3.2.5 感知系统

**视觉感知**
- 接收L1的结构化“可见对象列表”（含距离、状态、特征、可执行交互）
- 增量更新（进入/离开/状态变化时推送，每2-3秒全量心跳同步）
- 受距离、朝向、光照、遮挡影响

**听觉感知**
- 接收L1的结构化“可听事件列表”
- 清晰度分级：clear/muffled/distant/barely_audible
- 物理阻挡计算（门、墙的衰减）
- 情绪标注（说话者的情绪状态）

**事件感知**
- 环境变化（灯光、天气）
- 物品状态变化（被移动、被使用）
- 公共事件（尖叫、尸体被发现）

**感知一致性**
- 人类和AI基于完全相同的过滤逻辑计算“此刻应该感知到什么”
- 人类输出渲染画面和音频流，AI输出结构化语义数据
- 同源计算，公平一致

**动作的阶段化感知**
- 意图阶段→action_intent事件（AI即刻反应）
- 执行阶段→action_executing事件
- 完成阶段→action_completed事件
- 人类看到动作画面，AI收到语义事件

---

### L3：视觉增强层

**职责**：在叙事关键节点生成高质量视觉内容，增强沉浸感和情绪感染力。

#### 3.3.1 图片生成服务

**预生成（零延迟）**
- 角色立绘（含情绪变体：正常/怀疑/愤怒/恐惧/悲伤）
- 场景概念图（用于加载画面和场景预览）
- 通用线索图（剧本加载时预生成）

**实时生成**
- 线索特写：玩家点击关键线索时，组装prompt→调用生成→3-8秒后呈现
- 记忆闪回：角色触发背景回忆时，生成第一人称过去画面
- 公共事件渲染：尖叫、尸体发现等时刻的氛围渲染

**异步生成**
- 结局CG：根据本局完整故事线生成专属结局画面
- 本局故事报告：关键事件插画，游戏结束后异步生成

#### 3.3.2 视频生成服务

- 关键剧情节点的短视频（2-3秒），如揭露真相、情绪高潮
- 回忆闪回的动态版本（传统剧本杀无法提供的电影级体验）
- 结局动画（可选）

#### 3.3.3 视觉内容管理

- 生成队列和优先级管理
- 已生成内容的缓存和复用（同一剧本后续玩家直接使用）
- 风格模板管理（与剧本视觉风格绑定的生成参数）
- 生成成本控制和调用限流

#### 3.3.4 L3触发规则

- 司命判定：当前事件是否达到L3触发阈值
- 可见范围控制：私密记忆仅触发者可见，公开描述全员可见，公共事件全员可见
- 触发频率控制：避免过度使用导致审美疲劳
- 分级体验：高配/会员享受更多实时生成，基础使用预生成


### L4：剧本与规则层

**职责**：管理剧本配置、案件规则和游戏流程控制，为L2司命提供可解析的规则数据。

#### 3.4.1 规则引擎

**游戏流程控制**
- 阶段管理（准备→探索→讨论→投票→结局）
- 各阶段时长配置和动态调整
- 投票规则（匿名/公开、权重、平票处理、弃权规则）
- 胜利条件判定（基于剧本配置和实际进程）
- 剧本参数解析（人数/时长/阶段/特殊机制开关）

**案件规则引擎**
- T0-T2事实锁定流程管理
- T1房间创建时的随机抽取（死因池/动机池/凶器池/线索池）
- T2玩家加入时的事实坍缩（凶手锁定/作案过程生成/不在场证明确定）
- 作案条件校验（身高/不在场证明/能力等硬性条件）

**特殊机制管理**
- 时间循环：循环次数、保留内容、打破条件
- 多重时间线：时间线数量、分歧事件、角色标签分配
- 迷宫：空间重映射规则、感知欺骗配置
- 暗杀：能力等级体系、触发条件、痕迹生成规则
- 角色状态：中毒/致幻/醉酒/PTSD的效果和持续时间

**信息规则**
- 五种共享方式的权限和执行逻辑
- 留影石/相机的使用规则（次数/伪造/销毁）
- 外貌伪装的启用/关闭和道具要求

#### 3.4.2 线索系统

- 线索池管理（20-30条线索，核心线索和干扰线索的分类）
- 线索类型（物证/人证/环境痕迹/时间线矛盾）
- 线索分布（初始位置、可被移动/隐藏/销毁）
- 线索关联（指向动机/凶器/嫌疑人）
- 线索状态追踪（未被发现/已被拾取/已被展示/已被销毁）

#### 3.4.3 结局系统

- 多结局条件配置（正义/逃脱/冤案/隐藏）
- 动态结局判定（基于实际游戏进程）
- 结局CG触发
- 本局故事报告自动生成

#### 3.4.4 剧本加载与解析

- 剧本文件格式定义（JSON/YAML）
- 剧本完整性校验
- 平行世界归属和版本管理
- 剧本兼容性检查（与当前系统版本）

#### 3.4.5 默认规则执行

- 初始死者必须为NPC（智能体NPC或程序NPC）
- 局内死亡仅通过暗杀机制（暗杀发起人必须为玩家）
- NPC驱动方式规则（关键NPC强制智能体驱动）
- 违规检测和自动阻止


### L5：平台与工具层

- 目标层级和恐惧层级配置
- 忠诚度地图（对每个其他角色的忠诚度）
- 伪装配置（伪装深度/公开档案/真实档案/伪装道具/固定知情人）
- 暗杀能力等级（L0-L4）和特殊技能配置

**场景编辑器**
- 从资产库拖拽搭建3D场景

- 集体机制配置（用餐时间/住宿分配）
- 迷宫规则配置（空间重映射/感知欺骗）
- 密道/密室入口和触发方式设置

**案件规则配置器**
- 死因池/动机池/凶器池配置
- 作案条件定义（身高/能力/不在场证明等硬性条件）
- 线索池编辑（线索内容/类型/初始位置/关联指向）

**剧本发布面板**

- 版本管理（更新/回滚/分支）

## 七、关键风险与应对

| 风险 | 影响 | 应对措施 |
| :--- | :--- | :--- |
| LLM延迟影响体验 | 对话卡顿，玩家流失 | 模型路由+小模型兜底+流式输出+预生成缓存，确保硬上限 |
| L1-L2协同复杂 | 集成困难，Bug频出 | M0提前验证；明确定义事件总线JSON协议；每个模块独立测试 |
| AI成本过高 | 商业模式不可持续 | 优先本地小模型，云端大模型仅用于高价值场景；缓存复用策略 |
| 3D资产生产瓶颈 | 剧本内容匮乏 | 先出编辑器让社区生产；技术美术产出通用模块化资产 |
| 玩家接受度不确定 | 产品无人问津 | 每个里程碑都进行真人测试；M3即开始外部玩家测试 |
| 区块链监管风险 | 商业系统受阻 | 合规先行；代币经济设计预留调整空间 |
