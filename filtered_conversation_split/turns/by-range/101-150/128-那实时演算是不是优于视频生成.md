## 用户

那实时演算是不是优于视频生成？

## DeepSeek

不是简单的“优于”，而是**适用场景不同**，且实时演算在《开本》的需求下占据绝对主导地位。

---

## 实时演算 vs 视频生成：核心差异

| 维度 | 实时演算 | 视频生成 |
| :--- | :--- | :--- |
| **生成方式** | 游戏引擎实时渲染 | AI模型推理生成 |
| **延迟** | 毫秒级（16-33ms/帧） | 秒级到分钟级 |
| **交互性** | 完全交互，可随时改变 | 无交互，生成后不可改 |
| **动态适应** | 自动适应任何角色外观、装备、场景状态 | 需重新生成才能改变 |
| **成本** | 一次性开发成本，运行时几乎零成本 | 每次生成消耗token |
| **视觉上限** | 受引擎和美术资产限制 | 可达到照片级真实或任意艺术风格 |
| **可控性** | 精确到每一帧、每一个元素 | 依赖prompt和模型，有随机性 |
| **与游戏逻辑同步** | 天然同步 | 需额外同步机制 |

---

## 在《开本》中，实时演算占据绝对主导

### 实时演算的优势场景（绝大多数情况）

| 场景 | 为什么必须用实时演算 |
| :--- | :--- |
| **角色日常动作与表情** | 需要毫秒级响应，基于心智状态实时变化 |
| **对话中的口型同步** | 必须与TTS语音流实时匹配 |
| **玩家控制的角色** | 玩家输入需要即时反馈，任何延迟都不可接受 |
| **镜头运动与切换** | 司命需要根据实时局势灵活调整景别和焦点 |
| **场景动态变化** | 灯光、天气、物理交互需要根据游戏状态实时响应 |
| **暗杀与追逐** | 需要实时物理判定和即时反馈 |
| **WOW时刻的实时演出版本** | 可完美适应玩家装扮、任意角色组合、任意场景状态 |

### 视频生成的优势场景（少数高价值时刻）

| 场景 | 为什么用视频生成 |
| :--- | :--- |
| **超越引擎能力的视觉风格** | 如油画风格、水墨风格的回忆闪回 |
| **极度复杂的特效** | 如大规模的粒子魔法、流体模拟（引擎做太贵） |
| **需要离线高质量渲染的场景** | 如结局CG，玩家愿意等待 |
| **作为素材库积累** | 生成后存入种子库，未来可直接复用 |

---

## 结论：两者是主次关系，不是竞争关系

```
《开本》的视觉呈现策略：

┌─────────────────────────────────────────┐
│  实时演算（主引擎）                      │
│  - 占据95%以上的视觉呈现                 │
│  - 角色动作、表情、口型                  │
│  - 镜头调度、场景变化                    │
│  - 日常交互反馈                         │
│  - 大多数WOW时刻的基础版本               │
└─────────────────────────────────────────┘
                    ↑
                    │ 司命判断：需要超越引擎能力的视觉冲击？
                    │
                    ▼
┌─────────────────────────────────────────┐
│  视频生成（L3增强层）                    │
│  - 仅在高价值、高戏剧性时刻触发          │
│  - 作为实时演算的补充和升级              │
│  - 生成结果反哺种子库                    │
└─────────────────────────────────────────┘
```

**一句话总结：实时演算是《开本》视觉体验的“主食”，视频生成是“珍馐”。主食保证玩家时刻有饭吃，珍馐让某些时刻格外难忘。两者配合，才能既保证流畅性，又创造高光时刻。**
