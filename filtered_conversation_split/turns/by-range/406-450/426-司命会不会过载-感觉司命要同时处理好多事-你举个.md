### 司命的应对机制：Harness的任务分级与降级

Harness在检测到队列积压时，自动执行以下策略：

**第一层：P0抢占（<50ms）**
- 暗杀条件检测和弹窗推送直接跳过队列，走规则程序的快速通道
- 隆巴德在T+12秒看到暗杀弹窗——这是硬实时任务，绝对不能延迟

**第二层：P1规则程序并发（<200ms）**
- 事实核心的记录、知识图谱的更新、天平的基础评估——这些都由规则程序处理，不经过LLM
- 规则程序是确定性的、毫秒级的，不会因为LLM推理延迟而卡住

**第三层：P2 LLM推理排队（<3000ms）**
- 需要LLM推理的任务（干预决策、冲突生成、环境催化）进入LLM推理队列
- Harness根据任务的紧急程度排序：
  1. 艾瑟尔坦白的干预决策（优先级最高——她马上就要坦白了，司命需要决定是否催化）
  2. 隆巴德暗杀的平衡评估（暗杀弹窗已经推送，但后果评估可以稍后）
  3. 阿姆斯特朗逃脱的干预评估（他还在撬锁，有时间窗口）
  4. 火灾蔓延的催化决策（ESM已经在自动蔓延，司命只需决定是否额外催化）

**第四层：P3降级与丢弃（超时时）**
- 暴风雨加剧的催化决策——如果LLM推理超时，直接丢弃，让ESM自己运行
- 结局预测——如果来不及，等游戏进入投票阶段再算


### 如果LLM推理队列积压严重怎么办？

| 积压场景 | 应对策略 |
| :--- | :--- |
| 所有P2任务都在排队，LLM推理延迟达到上限 | Harness将优先级最低的任务降级——火灾催化决策直接丢弃，让ESM自己运行物理规则；阿姆斯特朗逃脱的干预评估推迟到下一轮 |
| LLM响应超时（超过3000ms硬上限） | 降级为规则程序兜底——规则程序根据预设的简单规则执行干预（如“若一方过于强势，随机选择一个弱势方AI发送模糊冲动”） |
| 多个LLM推理任务需要同时执行 | 司命的设计支持多个LLM推理任务并行——每个任务独立的上下文窗口，互不阻塞 |

### 高负荷下司命的“降级宣言”

在T+65秒这个高负荷时刻，司命的Harness会做出以下决策：

1. **P0暗杀弹窗**：立即推送，零延迟。隆巴德看到弹窗，他可以选择动手或放弃。

2. **P1规则任务**：全部在200ms内完成。事实核心记录所有事件，知识图谱更新所有人的知识状态。

3. **P2 LLM推理**：
   - 艾瑟尔坦白的干预决策——最高优先级，LLM推理中。如果她坦白，整个游戏的格局会改变。
   - 隆巴德暗杀的后果评估——排队中。暗杀弹窗已经推送，后果评估可以等隆巴德做出选择后再进行。
   - 阿姆斯特朗逃脱的干预——排队中。他还在撬锁，有时间。
   - 火灾蔓延的催化——降级。ESM已经在自动计算火焰蔓延，不需要司命额外催化。

4. **P3暴风雪催化**：丢弃。暴风雪由ESM和天气系统自主运行，不需要司命干预。

司命不会“同时处理所有事”。它通过Harness的任务分级，确保硬实时任务（P0/P1）永远不会被LLM推理阻塞，而需要深度推理的任务（P2）按优先级排队，低优先级任务在积压时被丢弃或降级为规则兜底。

---

**一句话总结**：司命在高负荷状态下通过Harness的四级任务分级（P0抢占、P1规则并发、P2 LLM排队、P3降级丢弃）来防止过载。硬实时任务走规则程序的快速通道，毫秒级响应；需要深度推理的任务按优先级排队；低优先级任务在积压时被丢弃或降级。司命永远不会因为LLM推理延迟而错过暗杀弹窗或逻辑矛盾检测。
