## 重新定义：点云过渡 vs 视觉障眼法

它们的核心区别不在于“有没有视觉效果”，而在于**视觉效果的底层数据来源**。

| 维度 | 点云过渡系统 | 视觉障眼法系统 |
| :--- | :--- | :--- |
| **数据支撑** | **有中间态数据**——在两个端点模型之间，通过数学插值生成真实的中间形态 | **无中间态数据**——没有可插值的端点模型，只能用一个特效覆盖整个切换过程 |
| **视觉变化本质** | 物体本身的形态、颜色、材质在**连续变化**——窗帘真的在从完好变到烧毁，小猫真的在从幼崽变到成年 | 物体本身**没有连续变化**——它是被一个外部特效“遮住”后瞬间切换的。窗帘不是“变”成灰烬的，它是在火焰粒子背后“替换”成灰烬模型的 |
| **渲染方式** | 高斯泼溅点云的实时渲染——每一帧都是真实的几何形态 | 粒子特效、动态着色器、全息投影——这些是“氛围”，不是物体本身 |
| **适用场景** | 生物生长（有幼崽和成年两个端点）、物体燃烧（有完好和烧毁两个端点）、物件培育（有种子和成品两个端点） | 瞬间附魔（没有“半附魔”形态）、形态进化（没有“半进化”形态）、服装换装（不能“半穿着”） |
| **技术依赖** | 依赖美术资产——需要为每个端点制作对应的3D模型或点云快照 | 不依赖美术资产——只需要预制一套通用的特效模板 |


## 为什么需要分开？

### 1. 数据条件不同

点云过渡能用的前提是：**存在两个（或多个）可被插值的端点模型**。

- 生物成长：有幼崽模型和成年模型 → 可以插值
- 物体燃烧：有完好模型和烧毁模型 → 可以插值
- 物件培育：有种子模型和成品模型 → 可以插值

但以下场景**没有中间态数据**：

- 一把剑从“普通”瞬间变成“火焰附魔”——没有“半附魔”的模型
- 一只蜥蜴“进化”成巨龙——这是两个完全不同的物种，没有可插值的端点
- 角色换装——不能“半穿着”一件衣服

这些场景只能用视觉障眼法来掩盖模型切换。

### 2. 美术成本不同

| | 点云过渡 | 视觉障眼法 |
| :--- | :--- | :--- |
| **美术投入** | 高——每个需要平滑过渡的物体都需要制作端点模型 | 低——一套特效模板可以复用于所有跳跃式变体场景 |
| **适用频率** | 核心资产（主角、重要生物、关键物件） | 所有资产（包括临时生成的、玩家自建的、没有端点数据的） |

如果所有跳跃式变体都要求制作端点模型，美术成本将不可承受。视觉障眼法是低成本覆盖长尾场景的方案。

### 3. 玩家感知不同

| | 点云过渡 | 视觉障眼法 |
| :--- | :--- | :--- |
| **玩家看到的** | 物体真的在变——窗帘的纤维在卷曲、小猫的腿在变长 | 物体被遮住了，再出现时已经变了——窗帘被火焰吞没，火焰散去后已是灰烬 |
| **叙事感受** | “我见证了它的成长/变化” | “它经历了某种仪式/蜕变” |

两种感受都是合理的，但适用于不同的叙事场景。生物成长需要“见证感”，所以用点云过渡。魔法附魔需要“仪式感”，所以用视觉障眼法。


## 完整决策流程

```
物体需要发生视觉变化
    │
    ├── 有两个（或多个）可插值的端点模型？
    │   ├── 是 → 点云过渡系统
    │   │       在端点之间实时渲染平滑中间态
    │   │       适用：生物生长、物体燃烧/潮湿/破碎、物件培育
    │   │
    │   └── 否 → 视觉障眼法系统
    │            │
    │            ├── 瞬间附魔/升级 → 元素爆发（火焰/冰霜/雷电粒子爆发，1秒内切换模型）
    │            ├── 形态进化 → 结茧/能量场（光柱包裹，内部切换，破茧而出）
    │            ├── 服装换装 → UI过场动画（帷幕/转盘，动画后切换模型）
    │            ├── 物体消失/替换 → 沙化/光化（旧模型粒子化飘散，新模型粒子聚合）
    │            └── 建造/编辑模式 → 全息投影（半透明发光，快速生长动画压缩至2-3秒）
```


## 一句话总结

你的判断完全正确——点云过渡系统依赖中间态数据，而视觉障眼法系统用于无数据支撑的场景。两者分开的逻辑正是：**有数据 → 点云过渡（真实连续变化）；无数据 → 视觉障眼法（特效遮蔽切换）**。它们共同覆盖了《开本》世界引擎中所有类型的视觉变化需求。
