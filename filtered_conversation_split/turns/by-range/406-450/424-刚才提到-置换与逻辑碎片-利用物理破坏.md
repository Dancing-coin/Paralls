## 一、“爆破重建”的两阶段拆解

### 第一阶段：墙体破碎 —— 点云过渡

| 要素 | 说明 |
| :--- | :--- |
| **数据条件** | 有“完整墙体”和“破碎墙体”两个端点模型（或点云快照） |
| **驱动者** | ESM（环境状态管理器）——判定受力超过墙体坚固度阈值，触发破坏状态机 |
| **视觉执行** | **点云过渡系统**——根据ESM传来的破坏进度（0.0→1.0），在“完整”和“破碎”两个端点之间实时渲染中间态。墙体不是瞬间消失的，而是从受力点开始出现裂纹，裂纹蔓延，然后碎块剥落、飞溅 |
| **这是真实的连续变化** | 每一帧，墙体的几何形态都在变——从一面完整的墙，变成一堆碎块。这不是“遮住后替换”，而是“真的在碎” |

### 第二阶段：烟尘遮蔽 + 门体生成 —— 视觉障眼法

| 要素 | 说明 |
| :--- | :--- |
| **数据条件** | 门的生成是瞬间的——没有“半扇门”的中间态。门和墙是完全不同的物体，没有可插值的端点 |
| **驱动者** | 依然是ESM——墙体完全破碎后，触发“生成门”的逻辑 |
| **视觉执行** | **视觉障眼法系统**——第一阶段产生的碎片和烟尘（这些烟尘本身就是破碎点云过渡的副产品）形成了天然的视觉遮蔽。在烟尘最浓密的1-2秒内，底层逻辑完成门的生成，等烟尘散去，门已经在那里了 |

## 二、两者的分工逻辑

| 阶段 | 用什么 | 为什么 |
| :--- | :--- | :--- |
| **墙体从完整到破碎** | 点云过渡 | 有“完整”和“破碎”两个端点数据，可以生成真实的连续破碎过程 |
| **碎片烟尘遮蔽视野** | 视觉障眼法（利用了点云过渡的副产品） | 烟尘是破碎过程的自然产物，不需要额外“制造”遮蔽——破碎本身就在制造烟尘 |
| **门在烟尘中生成** | 视觉障眼法（逻辑层瞬间替换） | 没有“半扇门”的数据，门只能瞬间生成。烟尘提供了自然的视觉掩护 |

---

## 三、为什么不是“点云过渡直接变出门”？

因为**墙和门是完全不同的物体，不存在可插值的端点**。点云过渡的核心能力是在两个“同类但不同形态”的端点之间生成中间态——比如完好的墙和破碎的墙，它们是同一个物体的不同状态。但墙和门是不同的物体——一个是墙体，一个是门框+门板。它们之间没有连续的形态变化路径。你不能把一面墙“过渡”成一扇门——你只能把墙拆掉，然后在原来的位置装上门。

所以这个场景的正确逻辑是：
1. 用点云过渡把墙变成一堆碎块（有数据支撑的连续变化）
2. 碎块散落产生的烟尘自然遮蔽了视野（障眼法的天然掩护）
3. 在烟尘中瞬间完成门的生成（无数据支撑的瞬间切换）

## 四、与你之前提出的“跳跃式变体”的关系

你之前提到的“跳跃式变体”——瞬间附魔、形态进化、服装换装——没有第一阶段（没有可插值的端点数据），所以只能纯靠障眼法。而“爆破重建”有第一阶段（墙体破碎有端点数据），所以它同时用到了两者。

| 场景 | 有端点数据？ | 用点云过渡？ | 用障眼法？ |
| :--- | :--- | :--- | :--- |
| 瞬间附魔 | ❌ 无“半附魔”形态 | ❌ | ✅ 元素爆发 |
| 形态进化 | ❌ 无“半进化”形态 | ❌ | ✅ 结茧/能量场 |
| 服装换装 | ❌ 无“半穿着”形态 | ❌ | ✅ UI过场动画 |
| **爆破重建** | ✅ 有“完整墙”和“破碎墙” | ✅ 墙体碎裂过程 | ✅ 烟尘掩护门体生成 |

## 五、一句话总结

“爆破重建”是点云过渡和视觉障眼法协作的典型案例——墙体碎裂有端点数据，用点云过渡驱动真实的连续破碎；门体生成无端点数据，用碎裂产生的天然烟尘作为障眼法完成瞬间切换。两者在同一个场景中分层协作，各司其职。这验证了我们将两者分开设计的逻辑：它们解决的是不同数据条件下的不同问题。
