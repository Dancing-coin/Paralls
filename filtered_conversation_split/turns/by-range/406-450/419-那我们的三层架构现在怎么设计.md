## DeepSeek

基于我们刚才对世界引擎的完整梳理——**人物定制、生物生态、物件创造和世界建造**——以及此前确立的**创作者设计层 vs 玩家体验层**的分工，我们的三层架构需要进行一次完整的升级，将所有新模块合理地分配到各层中。

## 《开本》世界引擎三层架构（升级版）

### 一、L1 确定性空间层（Godot运行时 + 规则封装）

**核心职责**：世界的一切“看得见、摸得着”的东西，都在这一层运行。它是玩家和创作者直接交互的界面。

| 模块 | 创作者设计 | 玩家体验 | 技术实现 |
| :--- | :--- | :--- | :--- |
| **体素引擎** | 使用世界编辑器绘制地形、放置体素方块、设计建筑 | 在允许区域自由放置和破坏方块、使用建筑蓝图一键生成建筑 | Godot Voxel + 自研八叉树存储 + 网格生成 |
| **捏脸系统** | 定义形态键范围、创建种族模板、上传自定义发型/纹身资产 | 在边界内自由调节滑块、选择种族基础模板、装备装饰资产 | Blend Shape（形态键） + humanizer插件参考 |
| **生物渲染** | 设计生物的3D外观、各生长阶段的模型变体 | 在自己的领地中观察生物生长、发现变异个体 | 阶段式模型 + 点云过渡（GDGS插件） |
| **物件渲染** | 设计零件的3D模型、定义材质贴图 | 在匠造工作台组装零件、查看成品外观 | 模块化模型 + Material Maker材质系统 |
| **动作库** | 定义动作模板、为不同种族/体型配置IK参数 | 角色根据情境和人设自动选择动作、动作流畅适配自定义体型 | 标准化动作模板 + IK逆向运动学 |
| **场景渲染** | 拼接场景、放置预制件、设计光照和天气 | 在主题世界中自由探索、在自己的领地中建造 | Godot渲染引擎 + ESM天气系统 |
| **空间音频** | 定义音效范围、环境混响参数 | 体验清晰区/模糊区/静默区的声音博弈 | Steam Audio + WebRTC |
| **事件埋点** | — | — | 所有玩家交互行为向L2上抛结构化事件 |

**关键变化**：L1层新增了体素引擎、捏脸系统、生物物件渲染模块，以及配套的动作库适配。这些模块在Godot引擎基础上封装，玩家和创作者通过统一的客户端交互。


### 二、L2 智能体交互层（Python后端 + AI服务）

**核心职责**：世界的“逻辑、生态和故事”在这一层运行。它是司命、角色智能体、生物引擎和物件引擎的所在地。

| 模块 | 创作者设计 | 玩家体验 | 技术实现 |
| :--- | :--- | :--- | :--- |
| **司命（叙事引擎）** | 配置世界法则（重力、火焰蔓延速度）、定义事件触发条件 | 体验动态叙事——暗杀机会弹窗、天平系统平衡、结局判定 | Harness + LLM + 规则程序 |
| **角色智能体引擎** | 定义角色的五维人格、品格层、人生记忆、语言风格 | 与拥有独立人格的AI角色自由对话、建立羁绊、带走同伴 | 心智模型(L1-L4) + 人格过滤器 + 对话生成 |
| **生物引擎** | 设计基因模板——定义物种的器官组件、行为参数、生长曲线、变异规则、栖息地要求 | 购买基因模板、投放培育生物、观察生长繁衍、收集产物、发现和交易变异个体 | 基因模板解析器 + 种群繁衍引擎 + 司命时间线管理 |
| **物件引擎** | 设计零件蓝图——定义零件的几何、材质、属性加成；设计合成配方；定义生长式物件的培育条件 | 按配方组装零件、选择材质定制属性、培育生长式物件 | 蓝图解析器 + 材质标签动态匹配 + 合成规则引擎 |
| **感知系统** | — | — | 结构化语义事件 + 感知过滤器 + 阶段化感知 |
| **模型路由** | — | — | 三层架构(P0-P4) + 硬上限 + 兜底降级 |
| **事件总线** | — | — | WebSocket + NATS混合架构 |
| **世界快照系统** | — | — | PostgreSQL + 离线时间线补全 |
| **世界映射引擎** | 定义场景连接关系、跨世界资产版权规则 | — | 世界快照 + 区块链确权 + 资产追溯 |

**关键变化**：L2层新增了生物引擎和物件引擎，它们是创作者设计蓝图和玩家体验规则的执行者。司命的职责从“单局导演”扩展为“世界推演者”——管理生物的生长时间线、物件的培育进度、离线时间线中的生态变化。


### 三、L3 视觉增强层（生成管线 + 实时演算）

**核心职责**：世界的“高光时刻”在这一层被捕捉和呈现。它是WOW时刻、点云过渡和生成式内容的所在地。

| 模块 | 创作者设计 | 玩家体验 | 技术实现 |
| :--- | :--- | :--- | :--- |
| **点云过渡系统** | 为生物的各生长阶段、物件的各培育阶段提供端点快照 | 观察生物从幼崽到成年的平滑生长、物件从种子到成品的连续变化 | 4DGS + 变形场 + GDGS插件 |
| **WOW时刻导演** | 定义关键事件的视觉触发条件（如建筑落成、新物种诞生、生物变异） | 在关键时刻看到实时演算的戏剧化镜头——建筑拔地而起、生物破茧成蝶 | 司命镜头调度 + 实时演算 + 粒子特效 |
| **图片生成** | 定义物种图鉴模板、建筑效果图风格 | 建筑落成时获得纪念图、新物种诞生时获得图鉴、生物变异时获得对比照 | P0/P1/P2分层策略 + 预生成 + 实时生成 |
| **视频生成（离线）** | 预生成生物生态纪录片、建筑漫游视频 | 在小世界中观看培育成果的回顾视频 | 异步生成 + 种子库复用 |
| **资产预览** | 在市场中展示建筑蓝图的效果图、生物基因模板的预览动画 | 在购买前预览建筑效果、生物外观 | 预生成 + 实时演算 |

**关键变化**：L3层的点云过渡系统从“生物成长可视化”扩展为“物件培育可视化”——无论是生物的幼年到成年，还是物件的种子到成品，都由点云过渡驱动平滑的视觉变化。WOW时刻的触发条件也从“案件高潮”扩展为“创造里程碑”——建筑落成、新物种诞生、稀有变异出现。

## 五、三层之间的协同

| 协同链路 | 说明 | 示例 |
| :--- | :--- | :--- |
| **L1 → L2** | 玩家交互行为通过事件埋点上报，结构化事件进入事件总线 | 玩家在匠造工作台组装了一把剑 → L2物件引擎接收事件，计算最终属性 |
| **L2 → L1** | L2的决策结果返回L1，驱动角色行为、环境变化 | 司命判定建筑条件满足 → L1播放建造动画；生物引擎判定繁殖条件满足 → L1生成新个体 |
| **L2 → L3** | 司命判定触发高光时刻，向L3发送生成请求 | 建筑落成 → L3生成纪念图；稀有变异出现 → L3生成对比照 |
| **L3 → L1** | L3的生成内容返回L1，以画中画、全屏过渡等形式呈现 | 点云过渡的中间态实时渲染在L1的场景中；纪念图在L1的UI中浮现 |

**一句话总结**：《开本》世界引擎的新三层架构在原有基础上新增了体素引擎、捏脸系统、生物引擎、物件引擎和扩展后的点云过渡系统。L1承载所有“看得见摸得着”的交互，L2承载所有“逻辑、生态和故事”的智能，L3承载所有“高光时刻”的视觉呈现。三层通过事件总线解耦协作，共同构成一个完整的“世界引擎”。
