## 体素引擎的核心技术栈

| 技术模块 | 核心挑战 | 已有成熟方案 |
| :--- | :--- | :--- |
| **八叉树存储** | 管理海量方块数据，稀疏存储 | 学术界已有成熟优化方案，基于空间分割的加速结构（如八叉树、KD树）已被广泛应用 |
| **网格生成** | 将方块数据转为可渲染的三角面，剔除被遮挡的面 | Godot Voxel提供了完整的`VoxelTool`和缓冲区技术，支持平滑体素数据的获取与精确挖掘效果计算 |
| **光照计算** | 体素世界的光照传播、亮度更新 | Godot Voxel支持自定义无光照shader，通过BFS查找受影响的方块并迭代亮度 |
| **异步加载** | 无限世界的区块流式加载，不卡顿主线程 | 已有的体素引擎可以支持异步区块和网格生成，在消费级硬件上稳定运行于144 FPS+ |

Godot Voxel（`Zylann/godot_voxel`）是一个专门为Godot开发的C++模块，提供了完整的体素渲染、编辑和地形生成功能，是Godot生态中最成熟的体素方案。

## 与《开本》现有系统的集成

体素引擎只需要负责**方块数据的存储和渲染**，而《开本》的差异化能力由现有系统提供：

| 系统 | 在体素建造中的角色 |
| :--- | :--- |
| **ESM（环境状态管理器）** | 为每个方块赋予材质属性——木质方块可燃烧、石质方块不可燃、金属方块可导电。方块被放置后自动继承材质模板的物理规则 |
| **物品流转追踪器** | 记录方块被谁放置、何时放置、使用了什么材料 |
| **事件总线** | 广播方块放置/破坏事件，供司命和AI同伴感知 |
| **司命** | 管理建造日志，在离线时间线补全中记录“建筑已动工” |
| **AI同伴** | 感知建筑变化，对新建成的建筑发表看法 |

体素引擎是**渲染层**，我们的ESM、司命、事件总线是**规则层**——两者通过事件总线解耦协作。

---

## 推荐方案：集成而非自研

我们不需要从零研发八叉树、网格生成、光照计算。在Godot生态中，已经有多个成熟的开源体素方案可以选型，我们需要做的是在这些方案基础上封装《开本》特有的规则层：

| 封装层 | 内容 |
| :--- | :--- |
| **材质属性绑定** | 将ESM的材质模板映射到体素方块的类型ID |
| **建造权限管理** | 基于《开本》的领地系统和原住居民身份，控制谁能在哪里建造 |
| **建造事件上报** | 每次放置/破坏方块时向事件总线广播精确的结构化事件 |
| **蓝图化导出** | 将建筑结构序列化为《开本》的建筑图纸格式，支持交易和跨世界导入 |
