## 用户

刚才提到硬件优化，能不能暂时不做？

## DeepSeek

可以暂时不做硬件优化，但在架构上必须留下扩展接口。这是一个典型的“先用现成的跑通，再逐步优化”的阶段策略。

## 一、为什么可以暂时不做

| 原因 | 说明 |
| :--- | :--- |
| **过早优化是万恶之源** | 我们现在甚至没有一个可运行的Demo。在没有性能数据的情况下做硬件优化，完全是“在黑暗中开枪” |
| **现成的工具已经足够跑通原型** | Godot 4.x的默认渲染管线、llama.cpp的默认配置、WebSocket的默认参数，都足以支撑Phase 0的文字原型和Phase 1的单局剧本 |
| **真正的性能瓶颈还没暴露** | 我们的核心假设还没有被验证——AI角色能否在社交推理中自主博弈？玩家是否愿意为动态剧本付费？这些问题比“GPU利用率是否达到85%”重要一万倍 |
| **硬件优化的前提是有东西可优化** | 当你的帧率从60掉到15，当你的AI推理延迟从500ms飙升到5000ms，当你发现一张4090跑不动3个7B模型——这时候再优化，才有数据支撑，才有针对性 |

## 二、但必须留下哪些扩展接口

虽然硬件优化可以暂时不做，但架构设计必须在初期就预留扩展点：

| 接口 | 用途 | 实现方式 | Phase 1就要做 |
| :--- | :--- | :--- | :--- |
| **AI推理的模型切换接口** | 未来在本地小模型和云端大模型之间灵活切换 | 定义统一的`ModelInference`抽象类，实现`LocalLLM`和`CloudLLM`两个子类 | ✅ 必须。这是AI成本控制的基础 |
| **渲染管线的画质分级接口** | 未来根据硬件能力动态调整3D画质 | 定义`QualityPreset`枚举（Low/Medium/High/Ultra），为每个美术资产准备多级LOD | ✅ 必须。这是全平台覆盖的基础 |
| **ESM物理计算的精度分级接口** | 未来根据CPU能力调整物理模拟精度 | 定义`PhysicsPrecision`枚举（简化为高频两种模式） | ✅ 必须。否则低配设备跑不动ESM |
| **GPU任务的优先级调度接口** | 未来在渲染、AI推理、粒子特效之间动态分配GPU资源 | 定义`GPUTaskPriority`枚举，所有GPU任务实现统一接口 | ⚠️ 可推迟到Phase 2 |
| **云端/本地算力的动态调度接口** | 未来根据硬件评级自动决定任务上云还是本地执行 | 定义`ComputeRouter`抽象类，接收硬件基准测试结果，返回任务分配策略 | ⚠️ 可推迟到Phase 2 |
| **多线程并发的任务队列接口** | 未来将ESM物理、AI推理、渲染同步等任务分配到多核CPU | 定义`TaskScheduler`抽象类，支持任务优先级和并行度配置 | ⚠️ 可推迟到Phase 3 |

## 三、Phase 1需要做的最基础优化

“暂时不做深度硬件优化”不等于“完全不考虑性能”。以下是Phase 1必须做的最基础优化：

| 优化项 | 说明 | 为什么必须做 |
| :--- | :--- | :--- |
| **3D模型LOD分级** | 每个模型至少准备2-3级精度（高精度用于第一人称近距离，低精度用于远景） | 否则一个贝克街客厅就吃掉8GB显存 |
| **音频流式加载** | 空间音频按需加载，不要把所有音效一次性加载到内存 | 否则一个剧本的音频就占满内存 |
| **事件总线的消息批处理** | 多个同类事件（如5个AI角色同时移动）合并为一个批量推送 | 否则网络延迟会严重影响AI响应速度 |
| **LLM推理的本地兜底** | 即使全用云端API，也必须准备一个极简的本地规则引擎作为兜底 | 否则API宕机时游戏完全不可玩 |

## 四、推荐的实施路径

| 阶段 | 硬件相关的工作 | 目标 |
| :--- | :--- | :--- |
| **Phase 0** | 零硬件优化。用默认配置跑通文字原型 | 验证核心体验 |
| **Phase 1** | 实现必要的扩展接口（模型切换、画质分级、物理精度分级）+ 最基础优化（LOD、音频流式、消息批处理、本地兜底） | 交付MVP，覆盖主流中端配置（GTX 1060级别） |
| **Phase 2** | 实现GPU任务优先级调度接口、云端/本地算力动态调度接口 | 开始覆盖高端和低端两极配置 |
| **Phase 3** | 全面硬件优化——CPU/GPU异构计算、GPU-Driven渲染、异步计算队列、移动端NPU适配 | 全平台覆盖，从旗舰PC到低端手机 |

**一句话总结**：硬件优化可以暂时不做，但必须在架构上留下足够的扩展接口。Phase 1的核心任务是“跑通”和“验证”，不是“优化”和“极致”。我们先用现成的工具把东西做出来，等性能瓶颈真正暴露时，再拿着数据去做针对性的优化。
