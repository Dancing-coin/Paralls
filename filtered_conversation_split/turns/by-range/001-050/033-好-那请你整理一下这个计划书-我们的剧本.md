# 《无限书海》计划书

## 一、产品概述

**《无限书海》** 是一个智能体驱动的3D沉浸式动态叙事平台。首款产品形态为**多人动态剧本杀**，玩家与AI智能体共同参演一场谋杀谜案，通过自由探索、实时对话、空间互动来影响剧情走向——真正的凶手、作案过程、结局都由玩家的行为实时决定，而非预设的剧本。

**核心承诺：同一个剧本，每一次游戏都不同。**

---

## 二、产品：动态剧本杀

### 2.1 核心体验闭环

```
选择剧本 → 选择角色 → 进入3D场景 → 自由探索与对话
    ↓
发现线索与秘密 → 私下/公开交流 → 新冲突涌现
    ↓
新案件可能发生 → 最终投票/对决 → 结局揭晓 → 本局故事报告
```

### 2.2 首发剧本：《血字的研究·变奏》

| 项目 | 内容 |
| :--- | :--- |
| **背景** | 1890年，伦敦。侦探福尔摩斯邀请几位与案件相关的人士齐聚贝克街221B |
| **时长** | 45-60分钟 |
| **角色** | 5名（2名真人玩家 + 3名AI智能体） |
| **场景** | 贝克街客厅、旅馆房间（两个3D场景自由切换） |
| **核心机制** | 初始案件为引子，玩家行为可触发全新案件 |

**首发角色：**

| 角色 | 身份 | 类型 | 核心设定 |
| :--- | :--- | :--- | :--- |
| 福尔摩斯 | 侦探 | AI智能体 | 已掌握关键线索，需要有人帮他串联真相 |
| 华生医生 | 医生/助手 | AI智能体 | 私下怀疑福尔摩斯这次判断有误 |
| 玛丽·萨瑟兰 | 死者遗孀 | AI智能体 | 心机深沉，表面悲伤实则暗藏秘密 |
| 亨利·贝克 | 死者商业伙伴 | 真人玩家A | 与死者有财务纠纷 |
| 艾琳·艾德勒 | 神秘女郎 | 真人玩家B | 真实身份是私家侦探 |

### 2.3 事实锁定时间线

| 时间节点 | 锁定内容 | 未锁定内容 |
| :--- | :--- | :--- |
| T0：剧本创作完成 | 世界观、角色设定、场景、基础规则、作案条件池 | 具体案件事实 |
| T1：游戏房间创建 | 案件框架（死因类型、关键线索分布） | 凶手身份、作案细节 |
| T2：玩家选择角色并加入 | **全部初始案件事实**（凶手、动机、作案过程） | 无 |
| T3：游戏进行中 | 无新增锁定 | 叙事路径、新案件、结局走向 |

**T3阶段允许：**
- 玩家行为触发全新谋杀案
- 新案件的凶手可以是真人玩家或AI智能体
- 新案件的动机和过程完全由当前局势实时生成

## 三、工具：内容生产与配置系统

### 3.1 剧本编辑器（创作者工具）

面向剧本创作者的视觉化编辑环境。

| 模块 | 功能 | 使用者 |
| :--- | :--- | :--- |
| **角色编辑器** | 配置角色基础信息、五维人格参数、目标层级、恐惧层级、语言风格、忠诚度关系 | 剧本创作者 |
| **场景编辑器** | 拖拽式搭建3D场景，为物体设置可交互属性、关联线索 | 场景美术师 |
| **案件规则配置器** | 定义作案条件、动机池、线索池、初始案件生成逻辑 | 剧本创作者 |
| **故事线预览器** | 模拟AI跑完剧本，观察不同变量下的叙事走向 | 剧本创作者 |

### 3.2 大玩家控制台

面向服务器经营者的管理后台。

| 功能 | 说明 |
| :--- | :--- |
| **剧本库管理** | 策展自家服务器的剧本列表，选择启用/禁用 |
| **规则微调** | 在有限范围内调整游戏参数（时长、投票规则、线索密度等） |
| **服务器状态监控** | 实时查看活跃房间数、玩家在线数、AI负载 |
| **GM工具箱** | 以“神”的身份介入游戏，广播事件、调整参数 |

### 3.3 玩家客户端

| 功能 | 说明 |
| :--- | :--- |
| **角色选择与准备** | 浏览可选角色、查看背景简介、确认加入 |
| **3D场景交互** | 第一/第三人称视角、WASD移动、物品点击交互 |
| **空间音频语音** | 清晰区/模糊区/静默区、耳语模式、物理阻挡 |
| **线索与证据系统** | 物品检查、拾取、展示 |
| **本局故事报告** | 游戏结束后生成专属时间线，记录本局所有关键事件 |

## 五、商业系统

### 5.1 收益模型

| 收入来源 | 说明 | 分成比例 |
| :--- | :--- | :--- |
| **剧本售卖** | 官方及创作者出售剧本 | 官方30% / 创作者70% |
| **资产交易** | 角色、场景、机制包交易 | 官方20% / 创作者80% |
| **大玩家服务器收入** | 大玩家自定收费模式（门票、订阅、装饰品） | 官方抽成15% |
| **官方服务器** | 官方运营高品质体验服 | 100%归官方 |
| **会员订阅** | 高级功能（更多角色槽位、专属剧本、优先匹配） | 100%归官方 |

### 5.2 创作者经济闭环

```
创作者上传剧本/资产
    ↓
链上确权，生成内容指纹
    ↓
其他玩家/大玩家购买或引用
    ↓
智能合约自动分配收益
    ↓
创作者获得持续版税收入
    ↓
激励更多优质创作
```

### 5.3 确权与分账

- 所有资产（角色、场景、剧本、机制）在提交时自动生成内容指纹并上链存证
- 引用关系完全追溯，每一次复用都记录在链
- 智能合约自动执行分账，无需人工结算
- 发行治理代币，早期贡献者、优质创作者、大玩家组成IP议会，参与生态治理

## 六、IP举例：《白蛇传·浮生》

### 6.1 为什么选《白蛇传》

- 东方文化母题，全球认知度正在上升
- 角色关系极富张力：人妖恋、姐妹情、佛妖对立
- 天然适配剧本杀的情感冲突和阵营对抗
- 法术、变身、水漫金山等元素可成为独特的游戏机制

### 6.2 世界观框架

**核心概念：** 所有传说都在“无限书海”中平行存在。在这个“书页”里，白素贞的结局尚未写定，法海的坚持尚未被证明是绝对正确，许仙的懦弱也尚未铸成不可挽回的后果。

**核心母题：** 执念与放下、天理与人情、真相与选择

### 6.3 角色设定

| 角色 | 身份 | 类型 | 五维人格 (胆量/心机/共情/理性/社交) | 核心秘密 |
| :--- | :--- | :--- | :--- | :--- |
| 白素贞 | 千年蛇妖 | AI/玩家 | 8/5/9/6/8 | 为报恩而来，但妖性未泯 |
| 许仙 | 药铺大夫 | AI/玩家 | 3/4/8/5/7 | 已隐约察觉到妻子的异常 |
| 小青 | 青蛇 | AI/玩家 | 8/4/7/3/8 | 对姐姐绝对忠诚，对人类充满不信任 |
| 法海 | 金山寺住持 | AI/玩家 | 9/5/2/9/3 | 坚信自己的除妖是绝对正义 |
| 神秘香客 | 药铺常客 | AI/玩家 | 6/7/5/6/6 | 真实身份是五百年前被白素贞所伤之人的后代 |

### 6.4 可能的案件框架

- **初始事件：** 药铺一夜之间，一名病人离奇死亡，死状可疑
- **作案条件池：**
  - 死者体内检测出蛇毒（指向白素贞/小青）
  - 死者生前最后服用的药方被人调换（指向许仙/香客）
  - 现场留有佛门法器痕迹（指向法海）
- **动态演化可能：**
  - 法海可能是借除妖之名，行私刑之实
  - 白素贞可能是被陷害，也可能确实失控
  - 许仙可能为保护妻子，主动认罪
  - 小青可能未经姐姐同意，私下动手

### 6.5 一局可能的游戏流程

1. **开局：** 玩家们在药铺聚集，死者家属哭诉。法海断言是妖孽作祟。白素贞面色凝重。
2. **探索：** 玩家分头查看死者的药方、药渣、房间。有人发现药方被调换，有人发现蛇鳞。
3. **冲突：** 法海当众指认白素贞。许仙为妻子辩护。小青怒斥法海诬陷好人。
4. **新案件涌现：** 在所有人争论不休时，独自前往金山寺调查的玩家被发现昏迷在寺门外。AI导演判定：有人在阻止真相暴露。新的冲突被触发。
5. **最终对决：** 所有真相浮出水面。真凶可能是一开始的道貌岸然者，也可能是所有人共同导致的悲剧。
6. **结局：** 根据玩家们的选择，可能出现：真凶伏法、白素贞为保护许仙而离开、法海放下执念、许仙觉醒主动追回白素贞等多种结局。
