## 用户

想打造这样的剧本杀世界，剧本编辑器需要能够写出怎么样的剧本？世界观设定，时间，场景设定，人物设定，开本前的故事得是固定的吧，哪些是不能固定的呢？

## DeepSeek

你问到了剧本编辑器最核心的设计问题：**一份“剧本”里，哪些是创作者必须写死的，哪些是留给系统动态生成的。**

答案是：**开本前的历史是固定的，开本后的真相是随机的，游戏中的叙事是涌现的。**

---

## 一、剧本的固定部分（创作者在编辑器中设定）

这些是剧本的“骨架”，决定了游戏的世界观、角色和基本规则，在 **T0（剧本创作时）** 永久锁定。

### 1. 世界观设定
- 时代背景（如“1890年维多利亚时代伦敦”）
- 地理/社会背景（如“伦敦东区，雾都，贫富差距大”）
- 特殊规则（如“魔法存在”、“蒸汽朋克科技”）

### 2. 时间设定
- 故事发生的具体日期和时间（如“1890年11月9日晚7点至10点”）
- 关键时间节点（如“晚8点发现尸体”、“晚9点警察到达”）

### 3. 场景设定
- 所有可进入场景的名称、描述、3D布局
- 每个场景中的可交互物品（家具、摆件、隐藏空间）
- 场景之间的连接关系（如“客厅通过走廊连接书房”）

### 4. 人物设定（所有角色）
这是剧本资产的核心，无论该角色由玩家还是AI扮演。

| 设定项 | 说明 |
| :--- | :--- |
| **基础信息** | 姓名、年龄、职业、外貌描述 |
| **公开背景** | 所有人都知道的表面经历 |
| **核心秘密** | 该角色不想让人知道的真相（如“被死者勒索”、“真实身份是私生子”） |
| **五维人格参数** | 胆量/心机/共情/理性/社交（0-10） |
| **目标层级** | 按优先级排序的目标列表 |
| **恐惧层级** | 按强度排序的恐惧列表 |
| **忠诚度地图** | 对每个其他角色的忠诚度（-10到10） |
| **语言风格** | 称谓习惯、句式特征、话题偏好、撒谎时的特征、情绪表达方式 |
| **行为能力** | 角色能做什么（如“会开锁”、“会医术”、“身体孱弱不能奔跑”） |

### 5. 开本前的故事（固定历史）
这是所有角色在游戏开始前已经经历的事件，是事实数据库的基石。

| 内容 | 说明 |
| :--- | :--- |
| **死者信息** | 姓名、身份、与各角色的关系 |
| **案发前事件** | 案发前一天/几小时内，各角色在做什么、见过谁、说过什么 |
| **固定人际关系** | 角色之间早已存在的恩怨、秘密协议、目击事件 |

**为什么这些必须固定？** 因为它们是逻辑推理的基础。如果连“死者是谁”、“角色之间有什么恩怨”都随机，那推理就失去了锚点。

### 6. 案件生成规则池
创作者不指定具体凶手和作案过程，而是定义**生成规则和候选池**。

| 配置项 | 说明 |
| :--- | :--- |
| **死因** | 固定（如“钝器击打致死”）或提供候选池（如“中毒/刀伤/窒息”） |
| **作案条件** | 凶手必须满足的客观条件，如“身高≤死者”、“案发时无不在场证明”、“能接触到凶器” |
| **动机池** | 3-5种可能的作案动机（如“财务纠纷”、“情杀”、“灭口”、“意外过失”） |
| **凶器池** | 可能成为凶器的物品列表（如“烛台”、“镇纸”、“丝巾”） |
| **线索池** | 20-30条线索，每条线索指向特定动机、凶器或嫌疑人；分为“核心线索”（必出现）和“干扰线索”（随机出现） |
| **不在场证明配置** | 每个角色在案发时的位置和行为，以及谁可以为其作证（部分角色的不在场证明可能依赖他人证词，形成可变的逻辑链） |

## 二、剧本的随机部分（系统在运行时生成）

这些在 **T1（房间创建）** 和 **T2（玩家加入）** 时锁定。

### T1：房间创建时随机生成
| 生成项 | 说明 |
| :--- | :--- |
| **具体死因** | 从创作者配置的死因池中随机选择 |
| **具体凶器** | 从凶器池中随机选择 |
| **动机** | 从动机池中随机选择 |
| **核心线索子集** | 从线索池中随机抽取5-8条作为本局核心线索 |
| **不在场证明的具体形态** | 某些角色的不在场证明是否成立，随机决定（但需满足逻辑约束） |

### T2：玩家选择角色后锁定
| 生成项 | 说明 |
| :--- | :--- |
| **凶手身份** | 从所有满足作案条件的**AI角色**中随机选择（真人玩家不能是初始案件的凶手） |
| **完整作案过程** | 基于凶手的背景、动机、能力，生成具体的作案时间线、手法、是否有目击者 |
| **凶手的行为逻辑** | 凶手在游戏开始前的准备行为（如伪造不在场证明、销毁证据） |

### T3：游戏进行中涌现
| 涌现内容 | 说明 |
| :--- | :--- |
| **NPC的所有对话和行动** | 基于人格过滤器和当前局势实时生成 |
| **新案件** | 玩家行为触发的新谋杀或意外事件 |
| **结局** | 根据玩家投票和关键证据是否被发现，动态决定 |

## 三、剧本编辑器需要提供的功能模块

| 编辑模块 | 对应固定部分 | 对应随机部分配置 |
| :--- | :--- | :--- |
| **世界观与场景编辑器** | 设定时代、时间、场景布局、物品 | - |
| **角色编辑器** | 完整人格参数、背景故事、秘密、关系 | 标记哪些角色可作为凶手候选 |
| **历史事件编辑器** | 案发前事件时间线、固定人际关系 | - |
| **案件规则配置器** | 死因类型 | 作案条件池、动机池、凶器池、线索池、不在场证明配置 |
| **故事线预览器** | - | 模拟多次随机生成，观察叙事多样性，检查逻辑漏洞 |

## 四、总结：固定与随机的边界

| 类别 | 固定（创作者设定） | 随机（系统生成） |
| :--- | :--- | :--- |
| **世界观** | ✅ 全部 | ❌ |
| **场景** | ✅ 全部 | ❌ |
| **角色人设** | ✅ 全部（人格、背景、秘密） | ❌ |
| **案发前历史** | ✅ 全部 | ❌ |
| **案件事实** | ❌ | ✅ 凶手、动机、凶器、作案过程 |
| **线索分布** | 部分（线索池、核心线索类型） | 部分（具体哪些线索出现、位置） |
| **不在场证明** | 部分（角色位置、可作证人） | 部分（证词是否成立） |
| **游戏过程叙事** | ❌ | ✅ 全部实时涌现 |

**一句话：创作者写“谁是谁，发生过什么”，系统决定“这次是谁干的，故事怎么演”。**

这就是Paralls（平行岛）的剧本编辑器的核心设计逻辑。它让同一份剧本拥有理论上无限的平行世界版本，而每个版本都在逻辑上自洽、在体验上新鲜。
