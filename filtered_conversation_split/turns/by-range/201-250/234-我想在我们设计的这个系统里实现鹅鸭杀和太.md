## DeepSeek

在《开本》现有架构下实现《鹅鸭杀》和《太空杀》的玩法，不仅完全可行，而且能让这类游戏实现质的飞跃——从固定规则的社交推理，升级为**动态涌现的、有独立人格的、3D沉浸式的无限变体**。

## 一、可行性评估

| 维度 | 现有支持 | 需要新增/调整 |
| :--- | :--- | :--- |
| **核心玩法** | 阵营对抗、投票机制、空间音频、自由移动 | 任务系统、职业/角色系统、胜利条件扩展 |
| **3D场景** | 场景交互、物品拾取使用、机关迷宫 | 特定地图（太空飞船、鹅鸭岛风格） |
| **AI智能体** | 完整人格驱动、自主行为、伪装撒谎 | AI执行任务的动机、AI主动制造混乱 |
| **信息博弈** | 公共/共有/高阶知识、偷听、空间音频 | 视野遮挡、监控摄像头、尸体报告机制 |
| **匹配系统** | 多种匹配模式、AI填补 | 房间人数扩展（8-16人） |
| **司命** | 全局叙事管理、催化冲突 | 任务分配调度、事件触发 |

**结论**：核心架构完全支持，主要工作是**新增玩法模板**和**扩展部分机制**，而非重构底层。


## 二、核心玩法系统设计

### 1. 通用玩法模板引擎

我们需要一个**可配置的社交推理玩法模板**，让创作者可以像配置剧本杀一样，自定义规则：

```
玩法模板配置项：
├── 阵营定义（数量、名称、胜利条件）
├── 角色/职业列表（各角色专属技能、所属阵营）
├── 任务系统（任务类型、分布、完成条件）
├── 地图配置（场景连接、关键区域、视野遮挡）
├── 击杀机制（冷却时间、击杀距离、尸体报告范围）
├── 投票机制（投票时间、票数规则、平票处理）
└── 司命干预强度（随机事件频率、平衡催化程度）
```

### 2. 阵营系统扩展

我们已有的剧本杀阵营系统需要扩展为更通用的版本：

| 阵营类型 | 说明 | 胜利条件示例 |
| :--- | :--- | :--- |
| **任务方（船员/鹅）** | 完成所有任务或投票淘汰所有内鬼 | 任务进度100% / 内鬼全部出局 |
| **内鬼方（鸭子/内鬼）** | 击杀足够多的人或破坏关键设施 | 存活人数≤内鬼人数 / 致命破坏成功 |
| **中立方** | 独立于两方的特殊胜利条件 | 存活到最后 / 被投票出局反而获胜 |
| **恋人/组合** | 两人绑定，共同胜利或共同失败 | 无论哪方获胜，只要两人都存活即共同胜利 |

### 3. 角色/职业系统

创作者可自定义角色池，每个角色有独特技能和所属阵营：

| 角色类型 | 技能示例 | 设计要点 |
| :--- | :--- | :--- |
| **信息型** | 查看玩家阵营、查看地图某区域、追踪足迹 | 获取信息但不能直接击杀 |
| **行动型** | 快速击杀（冷却短）、远程击杀、隐身、传送 | 执行击杀或躲避 |
| **干扰型** | 破坏任务设施、制造假尸体、关灯、制造噪音 | 制造混乱，为内鬼创造机会 |
| **保护型** | 守护指定玩家、报警后获得额外保护时间 | 保护任务方 |
| **欺骗型** | 死后仍可发言（但不可投票）、伪装死亡、投票权重加倍 | 利用信息差博弈 |

### 4. 任务系统

这是与剧本杀最大的不同之处——需要新增一个完整的任务系统：

**任务类型**：

| 任务类型 | 交互方式 | 示例 |
| :--- | :--- | :--- |
| **点击交互** | 走到指定位置点击完成 | 刷卡、连接电线、输入密码 |
| **小游戏** | 弹出简化小游戏界面 | 接管道、匹配颜色、快速反应 |
| **多步骤** | 需要按顺序完成多个步骤 | 先拿钥匙→再开柜子→最后取文件 |
| **合作任务** | 需要两人同时完成 | 同时按下两个开关 |
| **携带物品** | 需要先找到某物品再带到某处 | 拿灭火器去引擎室 |

**任务与游戏节奏**：
- 任务总量和难度决定游戏时长
- 内鬼可以假做任务（播放动画但进度不涨）
- 任务进度是全队可见的公共知识
- 任务进度达到100%是任务方的胜利条件之一

### 5. 击杀与报告机制

我们已有的暗杀机制需要调整为适合快节奏社交推理的版本：

| 要素 | 设计 |
| :--- | :--- |
| **击杀方式** | 内鬼靠近目标后点击击杀按钮，有短暂冷却时间（如30-60秒） |
| **击杀距离** | 必须非常接近目标（1-2米） |
| **尸体报告** | 任何玩家发现尸体后可点击“报告”按钮，触发全员会议 |
| **报告范围** | 必须在尸体清晰区内才能报告（5-10米） |
| **目击** | 任何人看到击杀行为，可直接在会议中指认 |
| **AI的击杀行为** | AI内鬼基于人格参数决定击杀时机——高胆量者更激进，高心机者更谨慎 |

### 6. 视野与感知调整

为适应快节奏社交推理，感知系统需要增加以下配置：

| 要素 | 设计 |
| :--- | :--- |
| **视野遮挡** | 墙壁、大型设备等遮挡视线，背后不可见 |
| **灯光系统** | 部分区域可被内鬼破坏导致灯光熄灭，视野大幅缩小 |
| **监控系统** | 特定位置可查看其他区域的监控画面（在太空杀题材中常用） |
| **脚步声** | 我们已有的移动姿态系统直接可用——奔跑声大、潜行声小 |

### 7. 司命的角色转型

在这个玩法中，司命从“编剧”转型为“游戏裁判”：

| 司命职责 | 说明 |
| :--- | :--- |
| **任务分配** | 为每个玩家随机分配任务列表 |
| **事件触发** | 在游戏中期触发随机事件（如“氧气泄漏，所有人必须在30秒内去引擎室”） |
| **平衡催化** | 如果内鬼方过于弱势，司命可能触发“设施故障”为内鬼创造机会 |
| **AI玩家管理** | 控制AI内鬼的击杀节奏，控制AI任务方的任务完成速度 |


## 三、实现方案

### Phase 1：基础模板（1-2个月）

1. **玩法配置器**：在剧本编辑器（或独立工具）中增加“社交推理玩法”模板
2. **阵营与胜利条件**：扩展现有阵营系统，支持多阵营自定义
3. **任务系统**：新增基础任务类型（点击交互、简单小游戏）
4. **击杀与报告**：扩展暗杀系统，增加尸体报告和会议触发
5. **地图模板**：提供一个太空飞船或鹅鸭岛风格的示例地图
6. **AI适配**：让角色智能体理解任务和击杀逻辑

### Phase 2：深度机制（3-4个月）

1. **角色技能系统**：完整实现自定义角色池和技能机制
2. **视野与监控**：增加视野遮挡、监控摄像头等机制
3. **中立阵营**：实现多种中立胜利条件
4. **事件系统**：司命驱动的随机事件和平衡催化
5. **更多地图**：扩展地图模板库

### Phase 3：社区创作（5-6个月）

1. **完整编辑器**：创作者可以完全自定义玩法规则
2. **地图编辑器**：创作者可以创建自己的地图
3. **社区模板**：创作者发布和分享自定义玩法模板

| **暗杀机制** | 内鬼击杀行为（简化版） |

| **匹配系统** | 8-16人房间匹配，AI填补 |
| **司命** | 任务分配、事件触发、平衡催化 |
| **3D场景与交互** | 可交互物品、场景探索 |

**一句话总结：在《开本》现有架构上实现《鹅鸭杀》《太空杀》类玩法，核心工作是新增任务系统、扩展阵营胜利条件、增加角色技能框架，以及为司命增加“游戏裁判”模式。我们的智能体系统、空间音频、信息博弈机制，将使这类游戏从“固定规则的社交推理”升级为“有独立人格的、动态涌现的、3D沉浸式的无限变体”。**
