# 事件总线 + 空间音频 设计方案

## 一、事件总线

### 1.1 核心定位

事件总线是《开本》三层架构的**神经中枢**。所有L1（确定性空间层）、L2（智能体交互层）、L3（视觉增强层）之间的通信，全部通过事件总线完成，实现完全解耦。

### 1.2 架构设计

```
┌─────────────────────────────────────────┐
│               事件总线                    │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │         消息路由器 (Router)       │   │
│  │   - 消息队列管理                  │   │
│  │   - 优先级调度                    │   │
│  │   - 广播/单播/组播路由            │   │
│  └──────────────────────────────────┘   │
│                                          │
│  ┌────────────────┐ ┌────────────────┐  │
│  │  实时通道       │ │  可靠通道      │  │
│  │  (低延迟)       │ │  (持久化)      │  │
│  │  WebSocket/QUIC │ │  RabbitMQ/NATS │  │
│  └────────────────┘ └────────────────┘  │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │         事件持久化                 │   │
│  │   - 事件日志存储 (PostgreSQL)      │   │
│  │   - 事件重放引擎                  │   │
│  │   - 审计与复盘                    │   │
│  └──────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 1.3 消息协议

所有事件采用统一的JSON消息格式：

```json
{
  "event_id": "evt_20260520_001",
  "timestamp": "2026-05-20T19:05:23.456Z",
  "priority": "P2",
  "source": {
    "layer": "L1",
    "component": "godot_client",
    "character_id": "char_player_A"
  },
  "type": "player_speech",
  "routing": {
    "pattern": "broadcast",
    "scope": "room_12345",
    "targets": ["char_B", "char_C"]
  },
  "payload": {
    "content": "你昨晚在哪？",
    "mode": "public",
    "position": {"x": 3.5, "y": 1.7, "z": 2.1},
    "audio_radius": 10.0
  }
}
```

### 1.4 事件类型定义

| 事件类别 | 具体事件 | 优先级 | 发送方 | 接收方 |
| :--- | :--- | :--- | :--- | :--- |
| **玩家行为** | 移动、对话、拾取、使用、展示、开关门、投票、暗杀 | P1-P3 | L1 | L2 |
| **AI行为** | AI移动、AI对话、AI表情变化、AI交互 | P1-P3 | L2 | L1 |
| **环境事件** | 灯光变化、天气变化、门状态变化、物品被移动 | P3 | L1 | L2 |
| **感知事件** | 可见对象列表更新、可听事件列表更新 | P2 | L1→感知过滤器→L2 | L2 |
| **叙事事件** | 司命干预指令、暗杀催化、新案件生成 | P0-P2 | L2(司命) | L2(角色智能体)/L1 |
| **视觉增强** | L3触发请求、L3内容推送 | P3 | L2(司命)→L3 | L1 |
| **系统事件** | 房间创建/销毁、角色加入/退出、状态同步 | P1 | L1 | 所有 |

### 1.5 路由模式

| 模式 | 说明 | 使用场景 |
| :--- | :--- | :--- |
| **广播** | 发送给房间内所有客户端和服务 | 公共对话、公共事件 |
| **单播** | 发送给指定接收方 | 私密对话、司命→特定角色指令 |
| **组播** | 发送给满足条件的角色组 | 清晰区内所有角色、某阵营所有角色 |
| **发布/订阅** | 服务订阅感兴趣的事件类型 | L3订阅“关键线索发现”事件 |

### 1.6 优先级与硬实时保障

| 优先级 | 事件类型 | 延迟上限 | 处理方式 |
| :--- | :--- | :--- | :--- |
| **P0** | 暗杀意图、致命威胁 | <50ms | 实时通道，跳过队列直接处理 |
| **P1** | 玩家对话、状态同步 | <100ms | 实时通道，队列优先 |
| **P2** | 感知事件、AI行为 | <200ms | 实时通道，正常排队 |
| **P3** | 环境事件、视觉增强 | <500ms | 可靠通道 |

### 1.7 感知过滤器的位置

感知过滤器是事件总线上的一个**中间处理层**，在L1事件到达L2角色智能体之前执行：

```
L1 (Godot) → 原始事件 → 事件总线 → 感知过滤器 → 角色专属感知事件 → L2角色智能体
```

每个角色有一个独立的感知过滤器实例，根据其感知档案（视觉/听觉/触觉能力、当前状态）过滤和转换事件。


## 二、空间音频

### 2.1 核心定位

空间音频是《开本》实现**声音博弈**的核心机制。它不仅是技术实现，更是游戏玩法的一部分——声音是推理线索，是社交策略，是暗杀的风险因素。

### 2.2 系统架构

```
┌─────────────────────────────────────────┐
│          空间音频服务器                   │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │       音频场景管理器              │   │
│  │   - 3D音频源注册与位置绑定        │   │
│  │   - 声学空间定义（混响/材质）      │   │
│  │   - 环境噪音管理                  │   │
│  └──────────────────────────────────┘   │
│                                          │
│  ┌────────────────┐ ┌────────────────┐  │
│  │  传播计算引擎   │ │  介质阻挡计算   │  │
│  │  - 距离衰减    │ │  - 门/墙的衰减  │  │
│  │  - 空气吸收    │ │  - 透射/绕射    │  │
│  │  - 多普勒效应  │ │  - 材质影响     │  │
│  └────────────────┘ └────────────────┘  │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │       音频流混合器                │   │
│  │   - 多音源实时混音                │   │
│  │   - 耳语模式处理                  │   │
│  │   - HRTF空间化渲染                │   │
│  └──────────────────────────────────┘   │
│                                          │
│  ┌──────────────────────────────────┐   │
│  │       听觉事件生成器              │   │
│  │   - 清晰度判定                    │   │
│  │   - 结构化听觉事件输出            │   │
│  └──────────────────────────────────┘   │
└─────────────────────────────────────────┘
```

### 2.3 听觉区域划分

| 区域 | 距离 | 音频效果 | 语义信息（AI感知） |
| :--- | :--- | :--- | :--- |
| **清晰区** | 0-N米 | 全音量，无衰减 | `clarity: "clear"` → 完整对话文本+情绪+说话者身份确认 |
| **模糊区** | N-M米 | 低通滤波+音量衰减30%-50% | `clarity: "muffled"` → 关键词片段+模糊情绪+说话者身份“疑似” |
| **静默区** | M米以外 | 完全静音 | 无事件推送 |

- N和M的值由角色感知档案和环境因素动态决定
- 默认值：N=5米（室内）/ N=10米（室外），M=15米（室内）/ M=30米（室外）

### 2.4 介质阻挡计算

| 介质类型 | 衰减效果 | 实现方式 |
| :--- | :--- | :--- |
| **木门** | 清晰区→模糊区 | 低通滤波+音量-6dB |
| **石墙** | 清晰区→静默区 | 完全阻隔，仅低频可透射 |
| **玻璃窗** | 清晰区→模糊区（可看到口型） | 低通滤波+音量-3dB |
| **书架/屏风** | 轻微衰减 | 音量-2dB，无滤波 |
| **开放走廊** | 增强传播 | 听觉半径+20%，混响增加 |

**计算流程**：
1. 从声源向听者做射线检测
2. 记录穿过的介质类型和数量
3. 累计衰减系数
4. 输出最终的清晰度等级

### 2.5 耳语模式

| 要素 | 设定 |
| :--- | :--- |
| **触发方式** | 玩家手动切换或AI自主决定 |
| **清晰区半径** | 缩小至1米 |
| **模糊区** | 1-3米（极低音量，无法辨别内容） |
| **偷听机制** | 当非对话参与者进入1米清晰区时，对话双方屏幕出现“有人靠近”提示，偷听者可听到内容 |
| **AI决策** | AI角色根据人格参数决定何时使用耳语模式（高心机者更常用） |

### 2.6 环境噪音系统

| 噪音类型 | 影响 | 策略用途 |
| :--- | :--- | :--- |
| **持续噪音**（雨声、风声、壁炉声） | 所有听觉半径缩短20%-30% | 天然密谈保护伞 |
| **突发噪音**（雷声、尖叫、物品掉落） | 瞬间掩盖所有语音 | 暗杀最佳时机 |
| **人群噪音**（多人同时说话） | 清晰区重叠，信息混杂 | 浑水摸鱼的机会 |
| **静默环境**（深夜、密室） | 听觉半径扩大，脚步声等细微声音被放大 | 行动风险极高 |

### 2.7 技术选型

| 组件 | 技术选择 | 说明 |
| :--- | :--- | :--- |
| **3D音频引擎** | Steam Audio | 开源，支持物理遮挡、混响、HRTF |
| **音频传输** | WebRTC | 低延迟，自适应码率 |
| **语音编码** | Opus | 高音质低延迟，支持多采样率 |
| **HRTF渲染** | Steam Audio内置 | 头部相关传输函数，实现精准3D定位 |
| **回音消除** | WebRTC内置AEC | 防止回音和啸叫 |

### 2.8 与事件总线的集成

空间音频服务器同时向两个通道输出：

| 输出通道 | 内容 | 用途 |
| :--- | :--- | :--- |
| **音频流** | 实时混音的音频数据 | 通过WebRTC发送给玩家客户端 |
| **结构化事件** | 听觉事件（谁说了什么、清晰度、位置） | 通过事件总线发送给L2感知过滤器，供AI角色感知 |


## 三、事件总线与空间音频的协同

### 3.1 声音事件的完整流转

```
[玩家A说话]
    │
    ▼
[L1 语音采集] → 音频流 → 空间音频服务器
    │
    ├── [音频处理] → HRTF空间化 → WebRTC → 各玩家客户端
    │
    └── [语义分析] → 结构化听觉事件
            │
            ▼
        [事件总线] → 感知过滤器(为每个角色独立计算)
            │
            ├── 角色B在清晰区 → clarity: "clear" → 完整文本
            ├── 角色C在模糊区 → clarity: "muffled" → 关键词片段
            └── 角色D在静默区 → 无事件
```

### 3.2 AI角色的“偷听”决策

1. AI角色收到“模糊区有人说话”的听觉事件
2. 心智模型L2理解层分析：关键词+情绪+说话者身份“疑似”
3. 心智模型L3规划层决策：
   - 高心机+高胆量：悄悄靠近偷听
   - 低胆量：远离，避免被发现
   - 高社交：直接走过去加入对话
4. L4执行层：生成移动指令+表情+对话

### 3.3 空间音频作为暗杀条件

事件总线持续推送位置和声音事件，司命通过分析这些事件判断暗杀条件是否满足：

- 目标是否在独处？（位置事件+无其他角色在清晰区）
- 暗杀者的接近是否可能被听到？（脚步声分析+环境噪音状态）
- 暗杀行为是否会被目击或听到？（视野计算+听觉半径计算）
