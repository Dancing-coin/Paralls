## 方案演进盘点

### 一、产品名称与世界观

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 产品名 | 无限书海 / Paralls | **开本 / Paralls** | “开本”更符合剧本杀圈层认知，动词化命名降低传播门槛 |
| 世界观总称 | 无限书海 | **开本宇宙** | 产品名统一为“开本”后，世界观自然统一 |
| 叙事引擎名称 | 叙事导演 / 书页守护者 | **司命 (Siming)** | 需体现命运、报应、戏剧化三重含义，司命是中国神话中掌管命运与因果的神祇 |


### 二、叙事引擎的定位

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 司命的本质 | 中央控制系统 / 功能模块 | **运行时核心智能体**，由Harness+大模型+规则程序组成 | 必须是“活着的实时编剧”，而非被动的规则执行器 |
| 司命的角色 | 被动的规则守护者 | **集编剧与导演于一身的世界主宰**，实时创作并改写剧本 | 需主动催化叙事涌现，而非等待事件发生 |
| 司命与角色智能体的关系 | 导演控制演员 | **平等的智能体**，引擎只催化不控制，通过impulse消息间接引导 | 角色的自主意志不能被破坏 |


### 三、剧本的形态

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 剧本的本质 | 固定故事 + 随机凶手 | **种子 + 生长规则**（多可能性多线剧本 + 涌现机制） | 每次开本必须产生独一无二的体验 |
| 剧本种子库 | 无 | **可能性模块的集合**（角色池、动机池、线索池、结局条件等），每次开本后反哺种子库 | 需支持司命个性化开局和种子持续进化 |
| 续集承接 | 未讨论 | **世界状态快照 + 变量衔接规则**，前作结局通过快照影响续作 | 需解决不同玩家玩出不同结局后，续集如何个性化承接的问题 |
| 结局的发散性 | 无限 | **结局是有限的结构性框架，细节和过程是无限的** | 续集种子需要锚定有限的结构性结局才能设计 |


### 四、AI陪伴的形态

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| AI陪伴的根本来源 | 剧本杀中的功能性NPC | **在共同经历的故事中自然涌现的羁绊** | 情感不能靠设定，要靠并肩作战、舍命相救等真实事件 |
| 智能体带走机制 | 玩家点击按钮购买 | **双向叙事仪式**：玩家主动邀请→司命判断关系→人格过滤器决策→自然表达→坦白与契约 | 不能是系统弹窗，必须是一场由人格驱动的关键叙事事件 |
| 智能体跨世界使用 | 未讨论 | **需遵守世界压制**：主场无敌，客场受限。能力必须被目标世界规则压制 | 一个魔王不能带着灭世能力碾压武侠世界 |
| 智能体经济 | 无 | **智能体私房钱系统**：独立、闭环、受司命调控。来源：剧本预设、工作收入、大玩家津贴、玩家赠予。用途：为你消费、投资自己、共同消费 | 需让智能体成为“会给予的独立伙伴”，而非吞金兽 |
| 智能体“私房钱”来源 | 含“玩家消费分成” | **移除消费分成**，保留剧本预设、工作收入、大玩家津贴、玩家赠予、原世界资产 | “消费返利”让玩家感知为系统返还折扣，破坏沉浸感 |


### 五、暗杀机制

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 暗杀与伪装的关系 | 暗杀绑定在“重度伪装”下 | **暗杀与伪装彻底解耦**，是独立的核心机制 | 暗杀也可能是仇恨驱动、证据危机、意外冲突，不限于伪装者 |
| 暗杀发起人 | 未明确限定 | **必须是玩家**（人类或智能体玩家），NPC不可主动暗杀 | NPC是增强体验的，不能成为叙事主导者 |
| 暗杀触发方式 | 玩家想杀就杀 | **五重条件必须全部满足**（致命动机+信息空窗期+独处窗口+能力匹配+代价评估）+司命弹窗确认 | 暗杀是迫不得已的选择，不是随意操作 |
| 司命在暗杀中的角色 | 被动检测 | **主动催化**：只要检测到符合逻辑的动机且不破坏可玩性，就主动排列条件、推送指引、弹窗确认 | 司命是“机会创造者”，不替角色做决定 |


### 六、智能体感知

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 智能体如何感知世界 | 截图+多模态模型分析 | **结构化语义事件流 + 感知过滤器**，绝对不依赖截图 | 截图太慢、太贵、不精确；结构化事件毫秒级且100%精确 |
| 盲人角色的感知 | 未讨论 | **感知档案**：视觉禁用→听觉范围扩大50%+触觉+热感，严格按感官能力过滤 | 感知必须符合角色的物理和认知限制 |
| 不在感知范围内的事件 | 可能被推送给智能体 | **绝不推送**：感知过滤器严格按空间范围、物理遮挡、角色状态过滤 | 智能体不能是“全知全能的上帝视角” |


### 七、WOW时刻与视觉增强

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| WOW时刻的实现方式 | 纯视频生成 | **实时演算为主引擎（95%），视频生成为素材库（5%）** | 实时演算零延迟、可交互、自适应玩家装扮；视频生成太慢太贵，但适合做离线素材库 |
| WOW时刻的触发方式 | 事件触发 | **司命控制**：司命是全局戏剧效果的掌控者，考虑节奏、token消耗、可复用性 | 需统一调度，避免滥用导致审美疲劳或成本失控 |
| 实时生成 vs 复用 | 优先实时生成 | **P0完美调用优先**（与故事节点精确匹配的种子直接复用），P1微调，P2实时生成（需预估时间），P3降级 | 游戏流畅性永远优先；P0不是“复用”，而是该节点本就该有的视觉呈现 |
| 生成等待的处理 | 无 | **符合剧情逻辑的等待演绎**（子弹时间、角色内心戏、环境感知停顿） | 不能让玩家干等进度条，要把等待变成沉浸体验的一部分 |


### 八、商业模式

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 免费与付费的关系 | 模糊 | **付费是门票，探索是乐园**。付费决定你能进哪个世界，进入后所有探索完全自由，绝不被打断 | 自由探索与付费的天然冲突需要根本性解决 |
| 剧本体验模式 | 单次门票 | **买断制 + 门票制 + 会员制 并存** | 不同玩家有不同需求：想尝鲜、想收藏、想畅玩 |
| 永久使用权的保障 | 官方兜底 | **官方提供有限免费的云存档（有时限）+ P2P自建服务器 = 玩家自己永久保存** | 官方不能被“永久”绑架；真正的永久属于玩家自己的硬盘 |
| GM的角色 | 专业GM直接主持游戏 | **GM和司命对话讨论决策，不直接主持游戏** | 人类GM在实时主持上无法与司命抗衡 |


### 九、玩家身份与服务器

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 玩家身份 | 单一玩家身份 | **双层身份**：穿越旅人（无身份，单局体验）+ 原住居民（有身份，长期经营） | 需同时承载“随时来玩”和“长期生活”两种需求 |
| 本地经营 vs 大玩家服务器 | 未区分 | **核心区别：访问权限和规则由谁控制**。本地=完全私密，完全自主；大玩家服务器=大玩家设定规则 | 两种模式服务不同场景，不能混淆 |
| 大玩家服务器定位 | 仅影院模式 | **影院模式 + 主题世界模式 并存** | 大玩家有不同的资源、能力和愿景，需要不同深度的经营模式 |
| 真人玩家能否是初始案件凶手 | 默认不能 | **能。凶手候选包括所有角色（真人玩家和AI智能体），平等抽取** | 真人玩家也可以是初始凶手，更刺激，续集承接更多变数 |
| 智能体玩家的定位 | 匹配失败时的保底替补 | **游戏体验质量的基线保障者**，比不合适的真人玩家更优的选择 | 推理水平匹配、不会OOC、不会中途退出、不会恶意破坏 |


### 十、游戏类型覆盖

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 可承载的游戏类型 | 仅剧本杀 | **悬疑推理、情感恋爱、种田经营、策略经营、生存博弈、派对游戏、棋牌社交、MMORPG、开放世界RPG、集体叙事创作**等 | 核心能力（智能体+司命+动态叙事）可支撑远超剧本杀的类型边界 |
| 边界定义 | 模糊 | **核心乐趣必须来自角色之间的互动、博弈和叙事，而非物理操作或数值对抗** | 不是所有游戏类型都适合，需要清晰的能力边界 |
| 剧本杀与其他类型的关系 | 剧本杀是唯一产品 | **剧本杀是MVP切入点，种田/经营/恋爱/策略等是扩展** | 从已验证的核心体验逐步扩展，而非一步到位 |


### 十一、实现路线

| 问题 | 早期版本 | 最终版本 | 演进原因 |
| :--- | :--- | :--- | :--- |
| 开发顺序 | 一次性实现所有功能 | **三阶段渐进**：Phase 1 静态单局 → Phase 2 连续单局 → Phase 3 持续运行世界 | 技术累积和商业验证需逐阶段推进，不能一步到位 |
| 剧本在持续运行世界中的形态 | 只有单局制 | **单局剧本制 + 持续叙事流 并存** | 种田经营不需要是单局制，可以在永续时空中持续注入事件 |
