## 用户

那续集剧本的创作 创作者该怎么维护？

## DeepSeek

在《开本》动态叙事框架下，续集剧本的创作与维护不再是“写死一个故事”，而是**维护一套可供司命个性化调用的“可能性模块”与“变量衔接规则”**。创作者的终极目标是打造一个能够自然承接无数前作存档的“故事反应器”。

以下是详细的维护与创作指南：

### 一、核心维护对象：续集种子库

创作者无需维护一个庞大的剧情分支树，只需维护一个由“通用模块”和“特殊规则”构成的**续集种子库**。

| 维护对象 | 说明 | 例子 (以《白蛇传·续》为例) |
| :--- | :--- | :--- |
| **通用续集分支** | 预先定义数条续集故事的主干框架，它们是故事的基本走向。 | 分支A：法海复仇；分支B：许仙觉醒；分支C：小青独立。 |
| **变量衔接规则** | 定义前作的角色状态如何影响续集。 | 若“白素贞”在前作存活，她可能成为隐藏盟友；若前作中“对许仙忠诚度”极高，续集中他可能为你牺牲。 |
| **动态关系继承** | 定义前作结局中，重要角色与玩家扮演角色之间的关系如何继承到续集。 | 若前作结局是“玩家掩护了小青”，续集开局时她对你的初始信任值直接为8。 |
| **冲突与动机模块** | 定义续集中可用的冲突和动机池。 | 通用的“水漫金山”危机，特殊冲突“金山寺发现了你的‘穿梭者’身份”。 |

### 二、司命的个性化开局：自动组装

当玩家开启续集时，司命会自动完成复杂的组装工作：

1.  **读取前作世界快照**：获取玩家的故事线ID、角色生死状态、动态关系数据等。
2.  **匹配续集分支**：从种子库中，提取与快照中“故事线ID”相匹配的通用续集分支。
3.  **注入变量规则**：根据快照中的角色状态，激活特定的“变量衔接规则”，个性化修改续集的故事背景。
4.  **注入动态关系**：根据快照中的关系数据，个性化设定续集中NPC对玩家的初始态度。
5.  **注入专属冲突**：根据前作羁绊，从动机池中为玩家定制续集中的核心冲突。

### 三、维护工具与建议

-   **可视化维护**：剧本编辑器的“续集维护模式”允许创作者将模块与规则拖拽关联，并预览不同前作存档的生成效果。
-   **AI辅助检测**：AI会辅助检测规则冲突，并自动生成默认规则（如“未定义继承规则的角色默认为死亡”），确保完整性。
-   **分层发布策略**：创作者可采用模块化更新，发布新分支或规则而不影响已有模块。也能使用**A/B测试**，同时发布多个续集版本，通过玩家体验数据迭代出最优方案。
-   **社区维护模式**：当原创作者停更时，官方可指定新的维护者，或开启**Fork模式**，由社区接力维护。

### 四、生态价值

这套设计为IP宇宙提供了坚实的技术基础：好的续集是玩家自己“活出来”的。它解决了传统续作与玩家前作选择脱钩的体验断裂问题，让每个玩家都能收获独一无二的**个人正史**。同时，通过“一套种子库适配所有存档”的架构，创作者能以最低维护成本支撑起庞大的叙事宇宙。
